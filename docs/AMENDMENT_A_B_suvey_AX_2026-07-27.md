## 0. 이 문서가 필요한 이유

suvey AX는 검사 화면을 "섹션 단위 11페이지"에서 "1문항 1화면"으로 바꾼다.
이 전환은 기존 규칙 두 곳과 정면으로 만난다.

1. **축 이름 노출 금지** — 1문항 1화면에서는 "지금 어디를 지나는지"를 알려주지 않으면
   사용자가 76문항의 길이 앞에서 방향을 잃는다. 그런데 기존 규칙은 축 노출을 금지한다.
2. **이어보기 상태 스키마** — 문항 단위로 정확히 되돌아오려면 위치를 문항 인덱스로 알아야 한다.
   그런데 기존 `meta.step`은 섹션 스텝이고, 이 필드를 읽는 코드가 3개 파일에 흩어져 있다.

두 경우 모두 "규칙을 어기고 진행"하거나 "규칙 때문에 포기"하는 선택이 아니라,
**규칙을 정확히 갈라서 개정**하는 쪽을 택했다.
근거는 대표 지시(2026-07-27, Turn 8): *"현재 헌법 위반이 만약 우리 서비스의 가치(특히 고유성과
자산화)를 격상하기 위한 신규 규칙이라면 허용합니다. 허용하고 그걸 신규 헌법으로 하든,
개정하든 하고자 합니다."*

## 개정안 A — 축 노출 금지의 세분화

### A-1. 개정 전

> **AX 개선원칙 rev2** — Survey 전면 유지 (감성 리라이트·호흡 문구 허용, **축 이름 사용자 노출 금지**)

기존 조항은 "축 이름"이라는 하나의 표현으로 두 가지 서로 다른 것을 함께 금지했다.

- 채점에 쓰이는 4개 축: 자기이해 · 자기표현 · 자기설계 · 자기실행
- 문항이 묶여 있는 11개 영역: 자기인식, 가치와 신념, 전환과 회복 … 관심 영역 진단

### A-2. 개정 후

> **채점 축**(자기이해 · 자기표현 · 자기설계 · 자기실행)의 검사 진행 중 노출은 **절대 금지**한다.
> **진행 영역명**(questions.json `sections[].title` 11종)은 감성 리라이트를 거쳐 **노출을 허용**한다.

### A-3. 근거

**채점 축을 계속 금지하는 이유 — 응답 편향**

"이 문항은 자기표현 축입니다"를 보여주면, 사용자는 문항에 답하지 않고 **축에 맞춰 답한다.**
자기표현이 높아 보이고 싶은 사람은 표현 쪽 문항을 과대 응답한다.
이것은 리포트의 고유성을 직접 훼손한다. 응답이 사용자의 실제 결이 아니라
"보여주고 싶은 상"의 함수가 되기 때문이다. 엔진이 결정론적이어도 입력이 오염되면 출력도 오염된다.

**진행 영역명을 허용하는 이유 — 방향 감각은 편향을 만들지 않는다**

"가치와 신념"은 채점 결과와 1:1로 대응하지 않는다. 11개 영역은 4개 축으로 다대다 매핑되며,
사용자는 영역명만으로 자신의 점수가 어디로 갈지 역산할 수 없다.
반면 1문항 1화면에서 영역명이 없으면 화면은 "출처 없는 질문 76개"가 된다.
이것은 rev2가 요구한 *"분석의 시각 언어가 아니라 책의 시각 언어"* 와 정면으로 어긋난다.
책에는 장(章) 제목이 있다. 지금 몇 장을 읽는지 아는 것이 독서의 호흡이다.

**즉, 금지의 실질은 "축을 숨기는 것"이 아니라 "응답 편향을 만들지 않는 것"이었다.**
개정안 A는 규칙의 문면을 그 실질에 맞춘다.

### A-4. 적용 범위 — 오해를 막기 위한 명시

개정안 A의 금지는 **검사 진행 중(`/suvey`)에 한정**한다.

| 지면 | 채점 축 노출 | 근거 |
|---|---|---|
| `/suvey` 검사 진행 중 | **금지** | 응답 편향 차단 (본 개정안) |
| `report.html` 리포트 | **허용 (기존 설계)** | VII장 = "자기이해·자기표현·자기설계·자기실행 네 영역 심층 진단" |
| `index.html` 서비스 소개 | **허용 (기존 설계)** | `axis.a1_name`~`a4_name` 4축 소개 섹션 |
| `mypage-curation.js` 큐레이션 | **허용 (기존 설계)** | `curation.axis_*` — 이미 응답을 마친 사용자 대상 |

응답이 끝난 뒤에는 편향 위험이 사라진다. 따라서 리포트·소개·큐레이션의 축 제시는
개정안 A의 대상이 아니며, 아무것도 변경하지 않는다.

> **검증 중 발견 사항 (기록)**: 회귀 하네스 초기 규칙이 축 이름 노출을 서비스 전체 0건으로
> 잡았다가 실패했다. 확인 결과 `index.html` 14곳 · `report.html` 22곳이 정식 설계였고,
> `suvey.html`은 1곳(주석)뿐이었다. 규칙의 적용 범위를 잘못 넓힌 쪽이 하네스였으므로
> 하네스를 survey 범위로 정정했다. 코드는 처음부터 위반 0건이었다.

### A-5. 구현 결과

## 개정안 B — 이어보기 상태 스키마

### B-1. 개정 전

`meta.step` = 섹션 스텝 (0=메타, 1~11=영역, 12=검토). 정밀 위치 개념 없음.

### B-2. 개정 후

> `meta.step`의 **의미는 영구 불변**이다 (섹션 스텝 0..12).
> 정밀 위치는 `meta.qCursor` + `meta.stepModel`로 **확장**하며,
> 신버전은 **항상 양쪽을 동시 기록**한다.

| 필드 | 의미 | 범위 | 상태 |
|---|---|---|---|
| `meta.step` | 섹션 스텝 | 0..12 | **불변** |
| `meta.stepModel` | 위치 모델 | `"v1"`(암묵) \| `"v2"` | 신규 |
| `meta.qCursor` | QFLAT 문항 인덱스 | 0..55 | 신규 |

### B-3. 근거 — `meta.step`을 재정의하면 무슨 일이 벌어지는가

`meta.step`은 `suvey.html` 단독 소유가 아니다. 소비자를 전수 추적한 결과:

| 위치 | 용도 |
|---|---|
| `suvey.html` 복원부 | `Math.min(Math.max(0, data.meta.step), totalSteps - 1)` — **12로 clamp** |
| `mypage.html:2031-2037` | 진행률 fallback 체인 (`meta.answered` → `answers` size → **`meta.step`**) |
| `mypage.html:1910-1914` | 디버그 표시 |
| `functions/index.js:4195` | `answered` 산출 |

만약 `meta.step`에 문항 인덱스(0..55)를 넣으면:

1. 신버전이 `step: 40`을 기록한다.
2. 사용자가 캐시된 구버전 코드로 재접속한다.
3. 구버전이 `Math.min(40, 12)` = **12로 clamp** → 검토 단계로 튄다. **응답 위치 유실.**
4. RTDB 규칙은 `meta.step`에 `isNumber()`만 검사하고 범위를 막지 않으므로 **규칙이 방어해주지 못한다.**

이 유실은 하네스 #3에서 대조 증명으로 고정해두었다
(`[대조] step 에 문항 인덱스(40)를 넣었다면 구버전에서 12로 clamp = 유실`).
즉 개정안 B는 이론적 우려가 아니라 **재현 가능한 사고를 회피한 설계**다.

### B-4. 양방향 호환 매트릭스

| 저장 데이터 | 읽는 코드 | 결과 |
|---|---|---|
| v1 (stepModel 없음) | 신버전 | `step` 유지 + 섹션 내 첫 미응답 문항으로 **승격 복원** |
| v2 | 신버전 | `qCursor` **정밀 복원** |
| v2 | **구버전 캐시** | `step`만 읽음 → 섹션 단위로 정상 복원. 확장 필드는 **무시될 뿐 파괴하지 않음** |
| v2, step/qCursor 불일치 | 신버전 | `qCursor`를 신뢰원으로 `step` **보정** + 경고 기록 |
| 손상 (음수/초과/문자열/null) | 신버전 | 예외 없이 **0 폴백** |

### B-5. 배포 리스크 — RTDB 규칙 변경 0건

`database.rules.json`을 확인한 결과 변경이 **불필요**하다.

```json
"meta": {
  "step":     { ".validate": "newData.isNumber()" },
  "answered": { ".validate": "newData.isNumber()" },
  "$other":   { ".validate": "newData.isString() || newData.isNumber() || newData.isBoolean()" }
}
```

`meta/$other`가 문자열·숫자를 이미 허용한다 → `stepModel`(string) · `qCursor`(number) 모두 통과.
**규칙 배포 없이 데이터 스키마를 확장할 수 있다** = 배포 리스크 0.

추가로 `answers/$qid`가 `hasChildren()`을 허용하므로,
Phase 3의 `answers._log[qid] = { d, r }`도 규칙 변경이 필요 없다.

### B-6. 구현 결과

- `saveProgress()` · 제출 payload: `meta/step`(currentStep) + `meta/stepModel` + `meta/qCursor` **동시 기록**
- `_restoreQCursor()`: B-4 매트릭스 5경로 전부 구현
- `_safeQCursor()`: 섹션 모드에서도 안전한 값(섹션 첫 문항)을 기록 → 롤백 후 의미 오염 없음
- 회귀 고정: #2 · #3 · #4 · #5 · #6 · #9, 소스 계약 #12
  - "meta/step 에는 currentStep(섹션 스텝)만 기록"
  - "meta/step 에 qCursor 를 쓰는 코드 0건"

## 승격 형태 — 신규 헌법인가 개정인가

두 건 모두 **개정**으로 처리한다. 신규 헌법 제정이 아니다.

- **개정안 A**: AX 개선원칙 rev2의 "축 이름 사용자 노출 금지" 조항을 **세분화 개정**.
  금지의 실질(응답 편향 차단)을 유지하면서 문면을 정확하게 만든 것이므로, 규칙의 정신은 변하지 않았다.
- **개정안 B**: 기존 `meta.step`을 **건드리지 않고 확장**한 것이므로 기존 조항의 폐지가 없다.
  새 필드에 대한 조항을 추가하는 형태의 개정.

**최상위 원칙은 그대로 유지된다: "확실하지 않으면 배포하지 않는다."**
