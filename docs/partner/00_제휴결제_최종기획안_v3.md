## 5. 복사된 진짜 링크와 새어 나간 코드 (대표 질문 3, 다시 계산)

### 5.1 대표님 이해가 맞습니다 [사실]
- 흉내 낸 링크는 막힙니다(5.6).
- 진짜 링크와 공통 코드가 함께 퍼지면, 제휴사 회원이 아닌 사람도 남은 자리 안에서 제휴가로 결제할 수 있습니다. 제가 말한 "손해"가 이것입니다.
- 이 손해는 "들어올 돈이 덜 들어오는 것"입니다. 한 건당 19,900 − 13,000 = **6,900원**. 회사 돈이 밖으로 나가는 일은 생기지 않습니다.

### 5.2 왜 공통 코드만으로는 끝까지 못 막나 (원리) [사실]
- 공통 코드는 "아는 사람 누구나 쓸 수 있는 열쇠"입니다. 열쇠 한 개를 여러 사람이 똑같이 쓰면, 서버는 누가 진짜 회원인지 구별할 정보가 없습니다.
- 그래서 수학·보안으로 끝까지 막으려면 **"한 사람에게 한 개씩, 한 번만 쓰이는 증표"**가 필요합니다. 이 증표는 회원 명단을 가진 제휴사만 나눠 줄 수 있습니다.
- 증표가 사람마다 다르고 한 번만 쓰이면, 손해의 최대치가 "퍼진 링크 수"와 상관없어지고 **"제휴사가 나눠 준 증표 수"**로 묶입니다. 이것이 해결의 핵심입니다.

### 5.3 경우의 수 (스포츠잡알리오 기준: 500자리, 90일, 할인 6,900원)
| # | 무엇이 퍼졌나 | ② 공통 코드만 | ② + 자동 멈춤(5.4) | ③ 1인 1코드 | ④ 제휴사 연동 링크 |
|---|---|---|---|---|---|
| 1 | 아무것도 안 퍼짐 | 손해 0 | 손해 0 | 손해 0 | 손해 0 |
| 2 | 링크만 퍼짐 | 코드가 없어 결제 불가 | 결제 불가 | 결제 불가 | 링크 자체가 1회용이라 무관 |
| 3 | 코드만 퍼짐 | 링크 키가 없어 페이지가 안 열림 | 같음 | 같음 | 해당 없음 |
| 4 | 링크 + 공통 코드가 크게 퍼짐 | 최대 500 × 6,900 = **3,450,000원** | 한 번 퍼질 때 최대 30건 = **207,000원**, 그 뒤 자동 멈춤 | 공통 코드가 없어 해당 없음 | 해당 없음 |
| 5 | 회원 한 명이 자기 코드를 친구에게 줌 | (4와 같음) | (4와 같음) | 그 코드 1건만 = **6,900원**, 그 회원은 혜택을 못 씀 | 그 회원 1건만, 같음 |
| 6 | 누가 코드를 아무렇게나 맞혀 봄 | 코드가 짧으면 가능 | 같음 | 사실상 0 (5.5 계산) | 사실상 0 (위조 서명 불가) |
| 7 | 제휴사 담당자가 코드 목록 전체를 실수로 공개 | (4와 같음) | (4와 같음) | 최대 500건. 대시보드에서 "남은 코드 모두 정지 → 새로 발급" 즉시 가능 | 서명 열쇠 교체로 즉시 차단 |

정리: ③과 ④는 4번 경우(가장 큰 위험)를 **구조적으로 없앱니다.** 남는 것은 5번처럼 회원이 자기 몫을 남에게 주는 경우뿐이고, 이때도 자리는 제휴사 몫 500자리 안에서 하나 줄어들 뿐입니다. 즉 계약한 "500자리를 13,000원에" 범위를 넘는 손해는 생기지 않습니다.

### 5.4 공통 코드를 계속 쓴다면: 자동 멈춤 (수학으로 문턱 정하기)
- 규칙: **1시간에 제휴 결제가 30건 넘게 시작되면 자동으로 "멈춤"** + 대표님께 알림. 하루 상한(기본 60건)도 둡니다. 대표님이 대시보드에서 확인 후 "진행"을 누르거나 코드를 바꿉니다.
- 문턱이 평소 손님을 막을 확률 [사실, 포아송 분포 계산]:
  | 평소 시간당 평균 | 30건 넘을 확률 |
  |---|---|
  | 2건 | 사실상 0 |
  | 5건 | 약 0.000000000003% |
  | 10건 (회원 메일 발송 직후 같은 몰림) | 약 0.00003% |
  하루 상한 60건은 평소 하루 평균 30건일 때 넘을 확률이 사실상 0입니다.
- [가설] 스포츠잡알리오 회원 메일 직후 한꺼번에 몰리면 문턱에 닿을 수 있습니다. 제휴사가 메일 보내는 날을 미리 알려 주면, 그날만 대시보드에서 문턱을 올립니다.
- 코드 바꾸기: 대시보드 `코드 바꾸기` 한 번으로 옛 코드는 즉시 무효. 계약 기간 중 한 달에 한 번 바꾸는 것도 가능합니다.
- 효과: 크게 퍼지는 사고 한 번의 손해 상한이 3,450,000원에서 **207,000원**으로 줄어듭니다. 그래도 0이 되지는 않습니다(5.2 원리).

### 5.5 맞혀 보기(무작위 대입)가 안 되는 이유 [사실, 계산]
- 링크 키: 22자(132비트). 경우의 수가 너무 커서 맞힐 수 없습니다.
- 1인 1코드: 10자(헷갈리는 글자 0/O, 1/I/L 뺀 32종 글자) = 약 **1,126조** 가지. 500개만 진짜입니다.
- 틀린 코드 입력은 계정당 1시간에 5번, 접속 주소당 하루 30번으로 제한.
- 계정 하나가 90일 내내 쉬지 않고 시도(10,800번)해도 맞힐 확률 약 **0.0000005%**. 계정 1만 개를 만들어 동시에 해도 약 **0.005%**.
- 코드는 서버에 원문 대신 **지문(해시)**만 저장합니다. 저장소를 누가 보더라도 코드를 알 수 없습니다.

### 5.6 흉내 낸 링크 차단 (v2와 같음, 확정)
1. 운영 대시보드에서 등록한 제휴만 작동. 등록 안 된 `/partner/아무이름`은 "찾을 수 없는 페이지"만 보임(가격·결제 버튼 없음).
2. 추측할 수 없는 링크 키 `?k=`. 키가 없거나 틀리면 1번과 같은 화면.
3. `링크 다시 만들기`로 옛 링크 즉시 중지.
4. 가격은 서버에서만 정함. 주소·화면 값을 바꿔도 금액은 그대로.
5. 결제는 우리 사이트에서만 승인(페이플 Referer 검사, 페이팔 주문은 우리 서버만 생성).

### 5.7 확인 방식 4가지 (대시보드에서 제휴마다 선택)
| 방식 | 제휴사가 할 일 | 막을 수 있는 범위 | 추천 대상 |
|---|---|---|---|
| ① 링크만 | 링크 전달 | 링크가 퍼지면 자리 안에서 누구나 | 비공개 사내 교육 등 |
| ② 공통 코드 + 자동 멈춤 | 링크·코드를 회원 공지 | 사고 한 번 최대 207,000원 | 제휴사가 개별 발송이 어려울 때 |
| ③ **1인 1코드** | 대시보드가 만든 코드 500개(파일)를 회원에게 한 명씩 전달 | 코드 1개 = 1건, 처음 쓴 계정에 묶임 | **스포츠잡알리오 권고** |
| ④ 제휴사 연동 링크 | 제휴사 사이트가 로그인한 회원에게만 1회용 서명 링크를 만듦(개발 필요) | 위조 불가, 1회용, 회원 정보는 우리에게 오지 않음 | 회원 수가 많은 큰 제휴 (다음 단계) |

- ③ 작동: 코드는 처음 입력한 계정에 묶이고 결제가 끝나면 "사용"이 됩니다. 결제 전 30분 확인표 동안은 다른 계정이 같은 코드를 쓸 수 없습니다. 쓰이지 않은 코드는 대시보드에서 개별 정지·재발급 가능.
- ④ 작동: 제휴사 서버가 `제휴사·회원번호의 지문·만료시각`을 비밀 열쇠로 서명(HMAC-SHA256)해 링크에 붙입니다. 우리 서버는 서명을 확인하고 같은 회원번호 지문은 한 번만 받습니다. 회원의 이름·메일은 우리에게 넘어오지 않습니다.
- [확인 필요] 스포츠잡알리오가 회원에게 코드를 한 명씩 보낼 수 있는지(회원 메일 개별 치환 기능 등). 확인할 곳: 스포츠잡알리오 담당자. 가능하면 ③, 어려우면 ② + 자동 멈춤으로 시작하고 다음 계약 때 ③으로 옮깁니다.
- 계약서 권고 문구(대표 판단): "제휴사는 코드를 제휴사 회원에게만 전달한다. 코드가 공개된 사실을 알면 즉시 알린다."

## 6. 결제 흐름 (기술)
1. 페이지가 서버에서 제휴 설정을 읽음(링크 키 검사). 없음·멈춤·종료·기간 밖이면 안내만.
2. 로그인·확인(①~④) 후 서버가 **30분짜리 확인표**를 만들고 자리 하나를 먼저 잡음(동시에 눌러도 500명을 넘지 않게 한 번에 처리).
3. 페이플: 확인표 금액으로 결제창을 열고, 서버가 최종 승인 **전에** 확인표(본인·기간·상태·금액·코드)를 다시 검사. 틀리면 승인하지 않아 돈이 빠지지 않음.
4. 페이팔: 서버가 확인표 해외가로 주문을 만들고, 캡처 때 금액을 다시 검사.
5. 결제 완료 기록에 제휴사·제휴가·확인표 번호를 남기고 자리(③이면 코드도)를 "사용"으로 바꿈.
6. 이후는 지금 결제 완료 처리와 같음.
- 30분이 지나면 잡아 둔 자리와 코드는 풀립니다.
- 기존 일반 결제(19,900원·$14.99)는 코드 경로를 나눠 바뀌지 않게 합니다.
- [사실] `payments/{uid}`는 허용된 항목만 쓸 수 있는 규칙이 있습니다(`database.rules.json`). 제휴 정보는 서버 전용 Firestore 기록에 두고, `payments/{uid}`에는 기존 항목만 씁니다. 그래서 잠금 해제 규칙은 바꾸지 않습니다.

## 7. 예외 처리
### 7.1 국내 결제(페이플)가 안 될 때 → 페이팔로 부드럽게 안내 (확정)
