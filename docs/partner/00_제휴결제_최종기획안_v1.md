## 3. 회원가입과 제휴 회원 확인
### 3.1 회원가입 (해결됨)
- 로그인하지 않은 방문자에게 `회원가입하고 혜택 받기` / `이미 회원이에요 · 로그인` 버튼을 보여 줍니다.
- 가입·로그인 후 같은 제휴 페이지로 돌아옵니다. (현재 로그인 화면은 정해진 페이지로만 돌아가게 막혀 있어, `partner/…` 를 허용 목록에 추가합니다.)
- 결제는 항상 로그인한 우리 계정으로만 됩니다. 결제 완료 기록도 그 계정에 남습니다. 그래서 검사·마이페이지·리포트가 지금과 똑같이 열립니다.
- 이미 결제한 계정은 결제를 막고 마이페이지로 안내합니다.

### 3.2 그 회사 회원임을 입증하는 방법
사실: 제휴사 회원 명단을 받지 않는 한 "그 회사 회원"을 100% 확인할 방법은 없습니다. 명단을 받으면 개인정보를 주고받게 됩니다.
그래서 확인 수준을 **제휴마다 고를 수 있게** 만듭니다.

| 방식 | 어떻게 | 확인 수준 | 맞는 경우 |
|---|---|---|---|
| ① 링크만 | 링크로 들어오면 제휴가 | 낮음 (링크가 퍼지면 누구나) | 공개 이벤트, 짧은 기간 |
| ② **공통 제휴 코드 (추천 기본값)** | 제휴사가 **자기 회원에게만** 코드 하나를 공지 (예: 회원 전용 게시판, 회원 메일). 결제 전에 코드 입력 | 중간 | 스포츠잡알리오처럼 회원 커뮤니티가 있는 곳 |
| ③ 1인 1코드 | 우리가 코드 N개를 만들어 제휴사에 전달, 한 번 쓰면 끝 | 높음 | 인원이 정해진 회사 |

모든 방식에 공통으로 **최대 인원과 기간**이 걸립니다. 링크나 코드가 밖으로 퍼져도 손해의 크기는 "최대 인원 × 할인액"을 넘지 않습니다. (예: 500명 × 6,900원 = 최대 3,450,000원)
대표님이 말씀하신 "해결이 안 되면 링크 + 인원·기한"은 ①번으로 들어 있고, ②·③은 확인을 더 강하게 하는 선택지입니다.

스포츠잡알리오 확인 내용(사실): 자체 회원가입(아이디·이메일·휴대폰)이 있는 채용 정보 사이트이고, 네이버 카페·인스타그램(약 6.7만 팔로워)을 운영합니다. 그래서 ② 공통 제휴 코드를 회원 공지로 전달하는 방식을 추천합니다. 배너가 누구나 보는 곳에 걸리면 ②가 꼭 필요합니다.

## 4. 결제 흐름 (기술)
1. 페이지가 기업 설정을 불러옵니다. 없는 주소, 종료·멈춤 상태면 안내만 보여 줍니다.
2. 로그인·제휴 확인이 끝나면 서버가 **30분짜리 확인표**를 만듭니다: 회원, 제휴사, 국내가, 해외가, 만료 시각. 이때 인원 한 자리를 먼저 잡아 둡니다(동시 결제 초과 방지).
3. 페이플: 결제창에 확인표 금액과 확인표 번호를 넣어 엽니다. 서버가 페이플 최종 승인 **전에** 확인표(본인·기간·상태·금액)를 다시 검사합니다. 틀리면 승인하지 않으므로 돈이 빠지지 않습니다.
4. 페이팔: 서버가 확인표의 해외가로 주문을 만들고, 캡처 때 금액을 다시 검사합니다.
5. 결제 완료 기록에 `제휴사`, `제휴가`, `확인표 번호`를 함께 남기고, 잡아 둔 자리를 "사용"으로 바꿉니다.
6. 이후는 지금 홈페이지 결제 완료 후 처리와 같습니다(검사 이동).
- 30분 안에 결제하지 않으면 잡아 둔 자리는 다시 풀립니다.
- 기존 일반 결제(19,900원 / $14.99)는 코드 경로를 나눠서 **바뀌지 않게** 합니다.

## 6. 환불
### 6.1 페이플
대표님이 페이플 파트너 관리자에서 직접 취소합니다. 대시보드에서는 `환불 완료 기록`으로 상태와 금액을 남기고, 그 계정의 결제 완료를 해제할지(검사 시작 전 환불) 함께 처리합니다.

### 6.2 페이팔
사실(PayPal 공식 문서): 결제 후 **180일 이내** 전액·부분 환불이 가능하고, 판매자 관리 화면에서 직접 환불할 수 있습니다. 그래서 페이플과 같은 방식(대표님 직접 환불 + 대시보드 기록)으로 운영할 수 있습니다.
- 대시보드에 결제별 페이팔 거래번호(captureID)를 보여 줘서 페이팔 화면에서 바로 찾게 합니다.
- 180일이 지난 건은 대시보드에 "페이팔 환불 기간 지남 → 계좌 송금" 안내가 뜹니다.

### 6.3 예비 대책: 계좌 직접 송금
- 결제 취소가 안 되는 경우(기간 경과, 카드 해지, 결제사 오류) 이용자에게 **환불 계좌 입력 링크**를 보냅니다(본인 로그인 필요).
- 입력값: 은행, 계좌번호, 예금주. 대시보드 `계좌 환불 대기` 목록에 뜨고, 대표님이 송금 후 `송금 완료`를 누르면 끝.
- 송금 완료 후 **계좌 정보는 지우고** "송금 완료·금액·날짜"만 남깁니다.
- 이 기능은 일반 결제 환불에도 함께 씁니다.

## 7. 보안
- 금액은 서버의 확인표로만 정합니다. 화면 값, 주소 값은 금액에 영향 없음.
- 확인표는 본인 계정·30분·1회용. 결제 승인 전에 다시 검사.
- 제휴 코드는 서버에서만 확인. 틀린 코드를 여러 번 넣으면 잠시 막음(기존 요청 제한 기능 사용).
- 제휴 설정 쓰기는 운영자만. 공개 화면은 이름·로고·가격·문구·남은 자리·종료일만 읽음.
- 제휴 페이지는 검색 노출 안 함(noindex). 연락처 보호 규칙(DLP), 보안 헤더 규칙 그대로 적용.
- 페이플 결제 도메인은 `lifeportfolio.co.kr` 그대로라 페이플 도메인 등록 변경 없음.

## 8. 법률 검토
### 8.1 페이플 (고지 내용으로 확인 완료, 사실)
- 페이플 개발자 문서: 결제창 호출 시 **가맹점이 결제금액(PCD_PAY_TOTAL)을 정해 보냅니다.** 지금 우리 서비스도 이 방식(19,900원)입니다.
- 페이플 링크결제 안내: 상품명·금액을 입력해 링크를 만들고, 결제수량·마감시간 설정, "이벤트 배너에 링크 삽입"을 공식 사용 예로 안내합니다. "상품(서비스)별 다른 결제 금액" 안내도 있습니다.
- 페이플 FAQ: 과세 상품은 총 결제금액의 10%를 부가세로 처리합니다. 13,000원 = 공급가 11,818원 + 부가세 1,182원.
- 결론: 금액을 다르게 결제받는 것은 페이플이 공식적으로 지원하는 방식입니다. 별도 신고 의무는 고지 내용에서 찾지 못했습니다.
- 참고: 결제창 방식(지금 쓰는 방식)을 씁니다. 링크결제는 결제 완료가 우리 회원 계정과 자동 연결되지 않아 "결제 후 검사 열림"이 안 되기 때문입니다.

### 8.2 바꿔야 할 문서
- 이용약관: "제휴 계약에 따라 특정 단체 회원에게 별도 가격을 적용할 수 있고, 가격·기간·대상은 제휴 페이지에 표시한다" 1개 조항 추가. 이용자에게 불리하지 않아 7일 전 공지 대상으로 봅니다.
- 상품 페이지 FAQ "세금 포함 단일 가격" → "정가 19,900원(제휴가는 제휴 페이지 표시)".
- 개인정보처리방침: 새로 모으는 것은 ① 제휴 결제 기록(제휴사 이름, 제휴가) ② 환불 계좌(송금 후 삭제)뿐입니다. ②를 수집 항목·보관 기간에 추가합니다. 제휴사와 개인정보를 주고받지 않으므로 제3자 제공 항목 변경은 없습니다.
- 제휴 페이지 화면: 판매자 정보, 정가·제휴가, 청약철회 안내, 약관 동의 체크(현재 결제 화면과 같은 고지).

### 8.3 할인 표시
"정가 19,900원"은 실제로 같은 상품을 그 가격에 팔고 있어서 표시할 수 있습니다.

### 8.4 제휴 계약서에 넣을 것
제휴가·기간·최대 인원, 대상 회원 범위, 코드 공지 방법(회원에게만), 로고 사용 허락, 개인정보 미교환, 제휴사에 숫자만 공유, 종료 후 처리(결제자는 그대로 이용), 홍보 문구 범위.

## 9. 검증 계획 (작업 후)
1. 서버 테스트: 가격 위조, 남의 확인표, 만료, 인원 초과(동시 결제), 종료·멈춤, 코드 틀림, 이미 결제한 계정, 일반 결제 영향 없음.
2. 페이플 테스트 환경 결제(카드·계좌), 페이팔 sandbox 결제.
3. 화면: PC·모바일·인앱 브라우저, 로그인 전후, 가입 후 복귀.
4. 운영 대시보드: 등록 → 링크 → 수정 → 멈춤 → 환불 기록 → 계좌 환불.
5. 라이브: 스포츠잡알리오 페이지를 "멈춤" 상태로 먼저 배포 → 대표님 확인 → "진행"으로 전환 → 링크 전달.
