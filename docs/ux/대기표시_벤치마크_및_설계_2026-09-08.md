> 목적: 고객이 "확인 중 / 불러오는 중 / 생성 중" 상태를 **멈춤으로 오해하지 않고** "기다리면 되겠구나"를 0.3초 안에 인지하게 한다. PC·모바일·감속 선호·고대비 모두 포함.

## 2. 설계 원칙 (배포헌법 정합)

1. **표면 최소화(제1조)**: 마크업 추가 0. 기존 대기 요소에 `data-lp-wait` 속성 1개만 붙임. 링은 CSS `::before` 로 그리므로 **다른 스크립트가 `textContent` 를 바꿔도 링이 지워지지 않는다**(기존 페이지 로직 무수정).
2. **교체 아닌 추가(제14조)**: 기존 스피너가 있는 지면(login/signup/suvey/success/report-loading/program-loading/mypage 리포트 목록)은 손대지 않음. 문구만 있던 **10개 지점**에만 링 부착.
3. **자동 해제**: `lp-wait.js` 가 MutationObserver 로 문구를 감시 → 문구가 대기형("확인 중/불러오/Verifying/Loading…")이 아니게 되면 속성·`aria-busy` 자동 제거. 대기형→대기형(i18n 치환)은 유지(실측 확인).
4. **접근성**: 대기 중 `aria-busy="true"` 자동 부여(스크린리더가 "사용 중"으로 읽음), 완료 시 제거. 9초 보조 문구는 `::after attr()` 로 표시.
5. **안전**: 모든 코드 try/catch. 실패 시 원래 문구만 보임(퇴행 없음).

## 4. 검증 (로컬 서빙 수정본, Puppeteer, PC 1280 + 모바일 390)

- 13지면 × PC/모바일 = 26회 로드: pageerror 0, 콘솔 error 0(네트워크 404 제외), CSS/JS 로드 26/26.
- 비로그인에서 대기 요소가 남는 지면(payment-success): 링 애니메이션 확인(`lpWaitSpin`, aria-busy=true).
- 합성 테스트: 0.5s 링 표시 → 9.7s 보조 문구 자동 노출 → 문구 교체 시 링·aria-busy·보조문구 자동 제거 → 대기형→대기형 치환 시 링 유지 → 상단바 `nav()` 3px is-on → 감속 선호 시 `lpWaitFade`(회전 없음).
- 미측정: 로그인 상태(Auth 복원 후 링이 실제 사라지는 순간)는 계정 없이 자동화 불가 → 문구 교체 합성 테스트로 대체. 실기기 확인은 대표 1회 요청.
