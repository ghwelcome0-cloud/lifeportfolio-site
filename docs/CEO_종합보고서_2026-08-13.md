## 1. 축① 고유성 — 같은 답을 넣어도 다른 사람에게는 다른 지면이 나오는가

**측정한 것**

```
@@FP {"n":160,"diff":0}          고유코드(LP-xxxx) 160종 · 개선 전후 불변
D-4 G5a~d 응답 민감도            전항 통과
D-4 G6a~e 진로엔진               전항 통과
난수 호출                        0회 (엔진은 규칙 기반 결정론 · LLM 아님)
```

**의미** — 같은 응답에는 항상 같은 지면이 나오고(재현성), 응답이 달라지면 지면이 달라진다(변별력). 이번 세션의 모든 수정에서 **고유코드 160종이 1건도 바뀌지 않았다** — 즉 기존 고객의 결과물이 사후에 달라지는 일이 없었다.

**측정하지 않은 것** — 실제 고객 응답 분포에서의 변별력. 시드 기반 합성 응답으로만 측정했다.

**재현**

## 6. 저장소 위생 — 이번에 한 일과 남은 1건

**했다**

```
전 히스토리 blob 스캔        4,541건
실제 고객 식별자 발견        1건 (결제 복구 고객 이메일)
  → HEAD 제거 + 전 히스토리 치환
테스트 데이터 파일 2종       전 히스토리 삭제
커밋 보존                    1,553 / 1,553
main 트리 blob 해시          1,812 / 1,812 동일  ← 코드는 1바이트도 안 바뀜
브랜치                       20개 전량 재작성 push
ruleset                      일시 해제 → 즉시 원상 복원 (active · bypass 0)
```

**남았다 — 1건**

```
raw.githubusercontent.com/.../6c16c4b/scripts/kys_rtdb_import.json  → 200
```

- **원인** 닫힌 PR #3 의 `refs/pull/3/head`. GitHub 이 읽기전용으로 보관하며 **force-push·삭제가 원천 불가**하다.
- **내용** 대표님 **본인** E2E 테스트 데이터. 고객 데이터가 아니다.
- **발견 가능성** GitHub 코드검색 색인 **0건**. 40자 커밋 SHA 를 미리 알아야만 도달한다.
- **해소 수단** GitHub Support 에 GC 요청 — **대표님 계정으로만** 티켓 개설이 가능하다.

**부수 발견** — Dependabot 알림이 이 저장소에서 **비활성** 상태다(`403 Dependabot alerts are disabled` 실측). 그래서 취약점 4건이 그동안 자동 보고되지 않았다. 활성화 여부는 대표님 판단 사항이다.

## 7. 이번 개선이 남긴 방법론 — "게이트에 없는 검사 = 사각지대"

결함 사전은 이번 개정8 에서 **R ~ CY** 로 늘었다. 이번에 새로 배운 셋은 성격이 다르다 — 지면이 아니라 **일하는 방식**에 관한 것이다.

**CW · 게이트를 완화하라는 지시는, 게이트를 지우라는 뜻이 아니다**
「저장소 시크릿을 라이브에 재사용하라」는 지시를 받았을 때 금지 검사 한 행을 지우면 배포는 되지만, 그 순간부터 어느 워크플로로든 배포 자격증명을 만질 수 있게 된다. 지우지 않고 **조건부 허용 + 새 제약 6종**으로 다시 썼고, 제약이 실제로 작동하는지 **역전 검증 4건으로 전수 차단**을 확인했다.
⇒ 게이트를 완화할 때는 **'완화 자신을 검사하는 게이트'를 같은 커밋에 넣는다.**

**CX · force-push 는 브랜치 포인터만 갱신하고 객체를 지우지 않는다**
`main` 만 밀었을 때 지우려 한 파일이 여전히 200 이었다. 나머지 브랜치 19개가 옛 커밋을 붙잡고 있었다.
⇒ **지우려 한 경로를 raw URL 로 질의해 404 를 보기 전에는 지워진 것이 아니다.**

**CY · 히스토리 재작성은 본문은 그대로 둔 채, 문서가 인용한 커밋 해시만 무효화한다**
개정 이력표의 해시 11개가 전부 도달 불가가 되었는데, `git cat-file` 은 여전히 `commit` 을 리턴해서 **존재만 물으면 적발되지 않았다.** `commit-map` 으로 전량 재매핑하고 조상 도달성을 확인했다(14/14).

**세 개를 관통하는 것** — 조건부 지시를 받으면 **조건부터 측정한다.** 대표님이 「서비스에 직접 영향이면 진행하라」고 하셨을 때 먼저 측정했고, 그 측정이 지목된 것보다 심각한 별건(실제 고객 이메일)을 찾아냈다.
