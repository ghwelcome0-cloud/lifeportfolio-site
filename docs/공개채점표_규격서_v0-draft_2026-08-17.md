## 0. 이 문서가 해결하는 문제

지금 우리에겐 **채점표 관련 지시가 두 갈래로 흩어져 있다.**

| | 출처 | 내용 | 성격 |
|---|---|---|---|
| **갈래 A** | 총괄 발주 【과제 2】-1 (2026-08-17 01:27) | "공개 비교표에 쓸 **평가 축 6~8개**" + 예시 8개 | 실무적 · 오늘 당장 잴 수 있음 |
| **갈래 B** | 문서[2] §6-2 (2026-07-31) | AERA/ITC/EFPA 기반 **공인 채점표 요건 4개** | 학술적 · 인증 가능성의 근거 |

**둘을 따로 두면 둘 다 실패한다.**
- A만 하면 → "너희가 정한 축 아니냐"는 반박에 무너진다. 인증 근거가 없다.
- B만 하면 → 심리측정 학술 기준이라 **우리도 경쟁사도 대부분 N/A**가 되어 비교표가 텅 빈다.

**대표님 지시는 이 둘을 하나로 합치라는 것이다.** 이 문서가 그 통합 규격이다.

**통합 방식:** 갈래 A의 축을 **표의 뼈대**로 쓰고, 갈래 B의 요건 4개를 **모든 축에 적용되는 채점 규칙**으로 건다.

## 1. 설계 원칙 — 왜 이 형태여야 하는가

### 1-1. 머스크식 비교가 성립하는 조건은 단 하나

대표님이 예로 드신 그록/클로드/GPT 비교표가 설득력을 갖는 이유는
"그록이 좋다"고 말해서가 아니라 **누구나 같은 벤치마크를 돌려 반박할 수 있기 때문**이다.

> **따라서 이 채점표의 유일한 합격 조건:**
> **제3자가 우리 도움 없이 같은 절차를 밟아 같은 점수에 도달할 수 있는가.**

이 조건을 만족하지 못하는 축은 **아무리 우리에게 유리해도 표에서 뺀다.**

### 1-2. 우리에게 유리한 축을 넣으면 안 되는 이유

축을 우리 강점에 맞춰 고르는 것을 **cherry-picking** 이라 하고,
비교표에서 이것이 발각되면 **표 전체가 무효가 될 뿐 아니라 기업 신뢰가 손상된다.**

방지 장치 3개를 규격에 박는다.
1. **축은 우리 제품을 보기 전에 정의한다** — 각 축의 근거를 외부 공개 기준에서 가져온다(§3).
2. **지는 축을 반드시 포함한다** — 최소 2개 이상(§5-3).
3. **축 선정 이유를 공개한다** — 왜 이 8개인지, 왜 다른 것은 뺐는지 기록(§3-3).

### 1-3. "인증 가능"의 정확한 의미 (대표님 표현의 번역)

대표님이 쓰신 **"인증이 가능한"** 을 우리는 두 단계로 나눠 쓴다. 섞으면 허위가 된다.

| 단계 | 의미 | 지금 가능한가 |
|---|---|---|
| **L1 자기검증 가능** | 절차·원자료·환산식을 공개해 **제3자가 재현**할 수 있다 | ✅ **지금 가능. 이 문서의 목표.** |
| **L2 외부 인증** | 외부 기관이 심사하고 인증서를 발급한다 (EFPA 리뷰 등) | ❌ **현재 없음.** 있다고 쓰면 허위 |

> **문안 규칙:** "제3자 재현 가능한 공개 채점표" ⭕ / "인증받은 평가" ❌
> ([8] 용어분리지침과 동일한 논리 — 재현성과 신뢰도를 구분하듯, 재현성과 인증을 구분한다.)

## 2. 채점 규칙 (문서[2] §6-2 계승 — 전 축 공통)

**모든 축은 예외 없이 아래 규칙을 따른다.**

### 규칙 1 — 항목마다 4가지를 명시한다
① **기준 출처** (왜 이것이 평가 항목인가 — 외부 근거)
② **요구 증거 유형** (무엇을 제출해야 점수가 인정되는가)
③ **1~5점 레벨 정의** (각 점수의 조건을 문장으로)
④ **가중치**

### 규칙 2 — 데이터 없는 항목은 0점이 아니라 `N/A(평가 유보)`
0점은 "했는데 나쁘다"는 뜻이고 N/A는 "확인 못 했다"는 뜻이다. **둘을 섞으면 그 표는 거짓말이 된다.**
경쟁사 정보를 못 찾았다고 0점을 주면 우리에게 유리하게 왜곡된다. **이것이 가장 흔한 조작 경로다.**

### 규칙 3 — ★ 동일 채점표를 벤치마크에도 똑같이 적용한다
객관성의 근거는 이것 **하나뿐**이다. 우리에게만 관대한 기준을 적용하는 순간 표는 광고가 된다.
**같은 사람이, 같은 날, 같은 절차로, 같은 순서로 채점한다.**

### 규칙 4 — 최종 점수 = `평가 가능 항목 점수` + `유보 항목 목록`, 환산식 공개
유보 항목을 숨기고 총점만 내놓으면 안 된다. **"8축 중 6축 평가 완료, 2축 유보"** 를 표에 함께 싣는다.

### 규칙 5 (신규 · 총괄 추가) — 채점 원자료를 보존한다
각 셀의 점수 옆에 **증거 링크(URL·스크린샷 파일명·측정 로그)** 를 남긴다.
증거 없는 셀은 `N/A` 로 강등한다.

> **근거 — 대표 교훈 13:** "로그의 OK 를 믿지 말고 산출물을 되읽어라."
> 점수만 남고 증거가 없으면, 6개월 뒤 우리 자신도 그 점수를 재현하지 못한다.

## 3. 평가 축 8개 (v0 후보 — ★GTM 리드가 확정한다★)

**아래는 총괄이 낸 후보다. 확정이 아니다.** GTM 리드는 각 축에 대해
**채택 / 수정 / 폐기** 를 판단하고 그 이유를 적어야 한다.

### 3-1. 축 후보 일람

| # | 축 이름 | 무엇을 재는가 | 기준 출처 (규칙 1-①) | 재현 방법 |
|---|---|---|---|---|
| **A1** | **방법론 투명성** | 결과가 어떻게 산출되는지 설명하는 공개 문서가 있는가 | AERA/APA/NCME Standards Ch.1 (근거 문서화) · ITC 가이드라인 | 공개 URL 존재 여부 + 문서 내용 확인 |
| **A2** | **한계 고지의 명확성** | 이 도구로 할 수 없는 것을 스스로 밝히는가 | ITC 가이드라인 (검사 사용 고지) · EFPA Test Review | 랜딩/결과 페이지 원문 인용 |
| **A3** | **결과 재현성** | 같은 입력에 같은 출력이 나오는가 | ISO 10667 (평가 서비스 일관성) | **동일 응답 2회 제출 후 산출물 비교** |
| **A4** | **행동 전환성** | 결과물이 '오늘 할 일'을 주는가 | 우리 차별화 축 ([1] A체계 ③ 계승) | 결과물 내 실행 지시문 개수 세기 |
| **A5** | **결과물 소장 가능성** | 결과를 내려받아 보관·재열람할 수 있는가 | 우리 차별화 축 ([1] A체계 ④ 계승) | PDF/파일 제공 여부 + 재접근 가능 여부 |
| **A6** | **데이터 취급 투명성** | 개인정보 처리·보관·삭제 방침이 공개돼 있는가 | GDPR Art.13 / 국내 개인정보보호법 고지 의무 | 처리방침 URL + 삭제 요청 경로 존재 |
| **A7** | **접근성** | 저사양·모바일·보조기기 사용자가 쓸 수 있는가 | **WCAG 2.2 AA** (국제 표준) | **axe 자동검사 위반 건수 · Lighthouse A11y 점수** |
| **A8** | **가격 대비 산출물** | 지불액 대비 무엇을 받는가 | — (사실 기술 축) | 가격 · 문항수 · 산출물 형태 병기 |

### 3-2. ★ GTM 리드가 판단할 것 — 축의 성격이 두 종류로 섞여 있다

| 종류 | 해당 축 | 특징 | 위험 |
|---|---|---|---|
| **외부 기준 유래** | A1 A2 A3 A6 A7 | 우리가 만들지 않은 기준. 반박 어려움 | 없음 — **표의 신뢰 기반** |
| **우리 차별화 유래** | A4 A5 | 우리가 잘하는 영역 | ⚠ **cherry-picking 의심을 받을 수 있음** |
| **사실 기술** | A8 | 점수화가 아니라 사실 나열 | 점수를 매기면 자의적이 됨 |

**총괄 판단 (GTM 리드는 이를 검토하고 반박해도 된다):**
- A4·A5 는 **넣되, 우리가 만든 축임을 표에 명시**한다. 숨기면 발각될 때 더 큰 손해다.
- A8 은 **점수를 매기지 않고 사실만 병기**한다. "가격 대비"는 주관이 개입할 수밖에 없다.
  ⇒ **채점 축은 7개(A1~A7), A8은 참고 정보 열.**

### 3-3. 축 선정 이유를 반드시 기록한다 (§1-2 방지 장치)

GTM 리드는 아래 표를 채워야 한다.

| 축 | 채택/수정/폐기 | 이유 | 우리에게 유리한 축인가 |
|---|---|---|---|
| A1 | | | |
| A2 | | | |
| ... | | | |
| **탈락시킨 축** | | **왜 뺐는지 반드시 기록** | |

> **왜 탈락 사유까지 적는가:** "우리에게 불리한 축을 빼지 않았다"는 것을 보여주는 유일한 방법이다.
> 이 칸이 비어 있으면 표 전체의 객관성 주장이 성립하지 않는다.

## 4. 레벨 정의 서식 (규칙 1-③) — 축마다 이 형식으로 작성

**예시: A2 한계 고지의 명확성** (총괄 시안 — GTM 리드가 다듬는다)

| 점수 | 조건 | 요구 증거 |
|---|---|---|
| **5** | 한계를 **결과물 안에** 명시 + 별도 고지 문서 존재 + 비진단성을 명확히 서술 | 두 위치의 원문 인용 |
| **4** | 별도 고지 문서에 한계·비진단성 명시 | 문서 URL + 원문 |
| **3** | 이용약관·FAQ 등에 한 줄 이상 언급 | 위치 + 원문 |
| **2** | 추상적 문구만 존재 ("참고용입니다" 수준) | 원문 |
| **1** | 고지 없음 | 확인한 페이지 목록 |
| **N/A** | 확인 불가 (페이지 접근 불가·로그인 필요 등) | 시도한 경로 기록 |

**★ 레벨 정의 작성 규칙:**
- 각 레벨은 **관찰 가능한 사실**로 써야 한다. "충실하다" "잘 되어 있다" 금지.
- **점수를 올리는 조건이 무엇인지** 읽는 사람이 알 수 있어야 한다.
  (그래야 이 표가 우리의 **개선 로드맵**으로도 기능한다 — 대표님의 After 서사 재료)

## 5. 비교 대상과 채점 절차

### 5-1. 비교 대상 (문서[2] §2 목록에서 선정 — ★새로 정하지 말 것★)

| 구분 | 대상 | 출처 |
|---|---|---|
| **필수 3** | 문서[2] §2 '필수' 항목 | 문서[2] §2 |
| **랜딩 4선** | Gallup CliftonStrengths · Crystal Knows · 16Personalities · Wealthfront | 문서[5] |
| **국내** | 문서[2] §2 국내 7종 중 **현존 확인된 것만** | 문서[2] §2 + 리서처 R-4 |

⚠ 2026-08 기준 **서비스 존속·가격 변동을 재확인**해야 한다(리서처 R-3).
2026-07-31 자료를 그대로 쓰면 안 된다. 다만 **목록 자체는 이어받는다.**

### 5-2. 채점 절차 (재현 가능성의 실체)

```
1. 측정 환경 고정 및 기록
   · 날짜 · 브라우저/버전 · 뷰포트(PC 1440 / MO 375) · 도구 버전(Lighthouse, axe)
2. 대상별로 동일 순서 수행
   · 로그인 불필요한 공개 페이지만 사용 (접근 조건이 다르면 비교 불성립)
3. 축 A1~A7 을 ★같은 순서로★ 채점
   · 축 하나를 전 대상에 대해 끝내고 다음 축으로 (대상별로 몰아 채점하면 편향된다)
4. 각 셀에 증거를 첨부 (규칙 5)
5. 증거 없는 셀은 N/A 로 강등
6. 총점 = 평가 가능 항목 합 / 만점 × 100, 유보 목록 병기
7. ★자기 반박★ — "이 표를 공격한다면 어디를 칠 것인가" 를 적는다
```

**절차 3의 근거:** 대상별로 채점하면 앞 대상의 인상이 뒤 대상에 전이된다(halo effect).
축별로 가로로 채점하면 같은 잣대가 유지된다. **이것이 규칙 3의 실행 형태다.**

### 5-3. ★ 지는 축은 반드시 남긴다

> 총괄 발주 원문: **"지는 축을 숨기면 이 프로젝트는 실패합니다. 지는 축이 개선 로드맵이 됩니다."**

**총괄의 사전 예측 (틀려도 좋다 — 예측을 먼저 적어두는 것이 목적):**

| 축 | 예상 | 근거 |
|---|---|---|
| A1 방법론 투명성 | ⚠ **지금은 진다** | 우리 방법론 공개 문서가 아직 없다 |
| A2 한계 고지 | ⚠ **지금은 진다** | P0-4 미반영 상태 |
| A3 재현성 | 🔵 이길 가능성 | 결정론 엔진 — 다만 **검증 절차를 공개해야** 인정된다 |
| A4 행동 전환성 | 🔵 이길 가능성 | 첫 행동 3가지 + 21일 루틴 |
| A5 소장 가능성 | 🔵 이길 가능성 | PDF 자동 생성 |
| A6 데이터 투명성 | ❓ 미확인 | 실측 필요 |
| A7 접근성 | ❓ 미확인 | E2E QA 실측 대기 |

**예측을 먼저 기록하는 이유:** 나중에 결과가 나왔을 때
"결과에 맞춰 예측을 바꾸지 않았다"는 것을 증명할 수 있다.
이것이 **Before→After 서사의 정직성 담보**다.

## 6. 이 채점표와 기존 5축의 관계 (★혼동 방지 — 최중요★)
