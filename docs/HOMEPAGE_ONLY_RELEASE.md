- 준비 시 공개 홈페이지 GET 200, 응답 바이트가 기준 index.html과 같음을 확인했다.

### 배포 직전

1. Firebase Hosting 콘솔에서 public 사이트 `lifeporfolio`의 현재 활성 release/version ID와 배포 시간을 기록한다.
2. 그 버전을 삭제하지 않는다. 되돌릴 대상과 배포 담당자의 접근 가능 여부를 확인한다.
3. 승인된 홈페이지 후보의 정확한 commit/manifest와 필수 게시 게이트 결과를 기록한다.
4. 기존 절차에서 `hosting:public`만 배포한다. admin Hosting, Functions, Database/Firestore Rules 배포는 이번 범위 밖이다.

### 공개 후 심각한 문제가 있으면

1. 새 배포를 더 진행하지 않고 증상·시간·URL을 기록한다. 사용자 토큰/응답 내용을 로그에 복사하지 않는다.
2. [Firebase Hosting 콘솔](https://console.firebase.google.com/project/lifeporfolio/hosting)에서 배포 직전에 기록한 public 사이트 이전 버전으로 되돌린다.
3. 루트 홈과 기존 로그인/상품/마이페이지 진입이 복귀했는지 확인한다. 캐시나 이미 열린 탭 때문에 즉시 모든 사용자 화면이 바뀐다고 보장하지 않는다.
4. 결제 취소/환불, 신규 계정·응답 삭제, DB 과거 시점 복원은 자동으로 하지 않는다. 해당 문제는 별도 확인·지원 절차로 처리한다.

실제 활성 release/version ID 조회, 운영 배포, 실제 rollback 실행은 아직 하지 않았다. Firebase의 이전 Hosting release로 복귀하는 절차를 준비한 것이며 rollback 성공을 실험했다고 말하지 않는다.
