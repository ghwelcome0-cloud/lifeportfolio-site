## 0. 모든 서비스에 적용할 실행 계약 — 최신 명확화

80억 개 문구를 미리 만들거나, 새로운 사람의 근거를 몇천 개 사람 유형으로 압축하는 것이 목표가 아니다. 원문·선택·관계·조건·예외를 보존하고, 필요한 관계를 해석하며, 읽기 쉬운 통찰과 실행으로 표현하는 구조를 계속 확장한다. 공유 가능한 핵심 문장이 있다는 사실을 고정 유형 수용의 근거로 삼지 않는다.

사용자가 거절한 ‘창의성·신중함의 모습에서…’ 나열형 및 ‘직접 적은…’ 인용형 헤드라인은 품질 기준을 충족하지 않는다. 검사 건수나 문자열 변화는 의미 활용의 증명이 아니다. PR333의 이전792a905 후보는 배포하지 않고 관계 판단층을 교체한다.

## 1. 북극성: 같은 직업이어도 서로 다른 자산화 경로

사용자 핵심 피드백: 추천 직업이 똑같이 ‘스포츠 코치’여도 고유성이 다르므로 자산화 과정은 달라질 수 있다. 같은 축구선수여도 포지션·장점·탁월함이 다르듯, 공통 직업명이나 높은 수준의 능력이 사람의 차이를 지우지 않는다. 규칙 기반 생성은 관리 편의의 분류기가 아니라 고유성을 발견하는 도구여야 한다.

**목표: 응답에서 중요한 개인차를 발견 → 이해 가능한 말로 보존 → 그 사람에게 맞는 실행 → 경험·결과를 축적 → 타인에게 기여할 수 있는 자산으로 활용.**

- ‘직업명이 달랐다’는 개인화 검증이 아니다. 같은 직업 안에서 역할·대상·작동 조건·기여 방식·남길 결과의 차이를 확인한다.
- ‘문장이 달랐다’도 충분하지 않다. 이름·날짜·고유코드·해시·어순·동의어만 달라진 것은 의미 개인화로 세지 않는다.
- 같은 응답에는 일관된 해석이 필요하다. 서로 다른 사람이라는 이유로 근거 없는 차이를 만들어 내지 않는다.
- 짧은 핵심 문장 하나에 사람 전체를 넣으려 하지 않는다. 핵심 문장·설명·키워드·실행 제안이 각자 다른 역할로 의미를 보존한다.
- ‘최고로 날카로운 서비스’는 개발 목표다. 비교 실험 없이 다른 기업보다 우수하다거나 8억·80억 명의 고유성이 검증됐다고 광고하지 않는다.

> 서로의 양식이 되도록

## 2. 성경이라는 근본 기준과 적용의 정직성

성경은 여러 참고 틀 중 하나나 내부 철학에 한정되지 않는다. 파이스 / 인생포트폴리오의 모든 원리·원칙·규칙·전략의 최상위 근본 기준이다. 수학·과학·철학·벤치마크는 그 아래에서 사용되는 발견·설계·검증 도구다.

사용자의 명시적 신앙 전제는 하나님이 세상을 창조하셨으며, 예수님만이 구원자이고, 거듭난 사람에게 성령이 함께하신다는 것이다. AI의 해석이나 경영 판단을 하나님의 뜻과 동일시하지 않는다. 설문 결과·생산성·수익으로 구원, 영적 은사, 소명이나 신앙의 성숙도를 판정하지 않는다.

고유성은 하나님의 형상으로 지음 받은 사람의 존엄(창 1:27)과 서로 다른 지체의 필요를 존중하는 방향으로 적용한다. 직관성은 알아들을 수 있는 말(고전 14:9)과 사랑 안에서 진실을 말함(엡 4:15)을 함께 지킨다. 자산화는 받은 것으로 서로 섬김(벧전 4:10)과 맡겨진 것에 대한 신실함(마 25:14–30)을 실행·기록·재사용으로 연결한다. 이는 본문에서 도출한 사업 적용이며, 성경이 특정 진단 점수나 알고리즘을 직접 제시한다는 주장이 아니다.

모든 규칙의 근거를 네 층으로 분리한다: **성경 본문과 문맥 → 신학적 해석과 사업 적용 → 설계 가설 → 실제 검증 결과.** 성경적 동기는 특정 알고리즘의 정확성을 자동 입증하지 않으며, 실적이 좋다는 이유로 왜곡·기만을 정당화하지 않는다.

DNA 비유를 ‘이 설문이 유전적 개성이나 은사를 측정한다’는 과학적 주장으로 바꾸지 않는다. 개인의 존엄은 유전자 차이·성과·수익·점수에 달려 있지 않다. 경험·관계·환경과 개인의 선택도 중요하다.

실무 적용: 직접 쓴 응답을 저장만 하고 해석·제안에 활용하지 않았다면 반영 완료라고 말하지 않는다. 복수 선택을 대표 유형 하나로 줄이기 전에 중요한 의미 손실을 검사한다. 묻지 않은 우선순위·동기·소명은 만들어 내지 않는다. 같은 직업 안의 다른 실행 경로는 확인된 근거로 구분하며, 부족한 정보는 추가 질문이나 작은 실행으로 확인한다.

사용자는 마취·절대평가의 역사적 사례가 당사자 증언과 여러 문헌에 기록되어 있다고 명확히 했다. 이를 부정하는 결론을 두지 않는다. 다만 이 개정에서 해당 사료를 직접 조사한 것은 아니므로 구체적 역사 서술을 인용할 때는 출처·발언·연대를 확인해 붙인다.

- 시편 139편: 하나님의 깊은 앎과 인간 도구의 한계를 구분한다.
- 고린도전서 12:4–7,12–27: 다양한 은사와 한 몸의 여러 지체라는 문맥. 사업에는 서로 다른 기여를 존중한다는 원리로 적용한다. 설문 성향을 신적 은사 판정과 동일시하지 않는다.
- 로마서 12:3–8: 과대평가 없는 자기이해와 서로 섬김.
- 고린도전서 14:6–19, 느헤미야 8장: 이해 가능한 말과 뜻을 풀어 줌.
- 마태복음 24:45 및 28:18–20의 본문 문맥·제품 적용 구분은 기존 학습 기준 §1.2–1.3을 따른다.

참고 본문: https://www.biblegateway.com/passage/?search=1%20Corinthians%2012%3A4-7%2C12-27%3BRomans%2012%3A3-8&version=ESV

이 문서는 정식 신학 검증 완료를 주장하지 않는다. 고객 리포트에 종교 표현을 자동으로 삽입하지 않는다.

## 3. 수학적 설계 원리와 그 한계

### 3.1 손실은 앞단에서 막는다 — 데이터 처리 부등식

응답 X → 내부 표현 Z → 고객 표현 T라는 처리 경로에서, 데이터 처리 부등식은 `I(X;T) ≤ I(X;Z)`라는 한계를 준다. 앞단에서 구별 불가능하게 합쳐 버린 차이는 뒤에서 문장을 꾸민다고 복원되지 않는다.

따라서 대표 유형 하나로 먼저 축소하지 않는다. **출처와 복수 응답·관계·조건을 보존한 뒤, 독자에게 필요한 만큼 표현한다.** 다만 모든 응답을 모든 문장에 반복할 필요는 없다. 중요한 것은 해당 해석과 선택에 필요한 차이다.

### 3.2 단어 나열을 넘어 관계를 본다 — 조건과 상호작용

성향·가치·활동·조건·성취 기준을 독립 라벨로만 다루지 않는다. 예를 들어 같은 분석 성향이라도 어떤 대상과 환경에서 무엇을 해결하려는지는 다를 수 있다.

관계마다 다음을 기록한다: `출처 문항/필드 | 직접 응답/해석/제안 | 관계의 근거 | 불확실성 | 영향을 주는 표현/행동`.

**중요:** 함께 선택했다는 사실이 우선순위·인과·상충 관계를 증명하지 않는다. 순위를 묻지 않은 복수 선택 배열의 `[0]`을 ‘가장 중요한 것’으로 단정하지 않는다. 긴장·맹점·숨은 욕구·동기를 지어내지 않는다. 관계가 미측정이면 질문으로 확인한다.

### 3.3 중요한 차이를 남기는 압축 — 율–왜곡 관점

고객의 읽기 부담을 제한하면서 선택·실행에 중요한 의미 손실을 최소화한다. 개념적 목표는 `읽기 길이 예산 안에서 D(근거 있는 해석, 고객 표현)를 최소화`하는 것이다.

D는 아직 검증된 수치가 아니다. 임의 점수와 가중치를 붙여 과학적으로 완성됐다고 말하지 않는다. 실제 검수에서는 다음을 확인한다.

1. 서로 다른 근거를 같은 사람으로 오해하게 하는가?
2. 중요한 조건·대상·선택의 이유를 지웠는가?
3. 짧아지면서 행동 제안까지 범용 조언으로 바뀌었는가?
4. 펼쳐 읽으면 근거와 한계를 확인할 수 있는가?

현재 승인된 네 축 질문·3지면·짧은 카드·시각 위계·키워드는 보존한다. 상세 해설을 리포트에 모두 쏟아 넣지 않는다.

### 3.4 질문의 가치는 의사결정에 대한 정보이득

문항을 추가하기 전에 ‘이 답을 알면 어떤 해석·실행 선택이 달라지는가’를 명시한다. 사람을 더 잘게 나누기만 하는 문항은 충분하지 않다. 정보이득 수치는 응답 분포와 모델 검증 없이 계산한 척하지 않는다.

새 문항 후보에는 `아직 모르는 차이 | 기존 문항으로는 부족한 이유 | 바뀔 제안 | 응답 부담 | 민감정보 여부 | 파일럿 검증`을 붙인다. 본문항·조건부 입력·확인 질문·실행 후 회고 중 가장 부담이 적은 위치를 선택한다.

### 3.5 실행을 통해 보완하는 개인 내 확인

진단은 완전한 사람 판정이 아니다. 단서 → 해석 가설 → 작은 실행 → 맞았던/달랐던 경험 → 조건 보완 → 재사용의 순환을 설계한다. 한 번의 성패를 본질·인과로 확정하지 않는다. 기록만 했다고 자산화 완료를 주장하지 않는다.

| 직접 알려 준 대상·과제 | 운동을 처음 배우는 사람이 동작을 이해하도록 돕고 싶다 | 경험 있는 선수가 경기 상황별 판단을 복기하도록 돕고 싶다 |
| 직접 알려 준 강점·방식 | 차분한 설명, 반복 연습 과정 관찰 | 장면 비교, 원인 분석과 피드백 |

| 확인 질문 | 누구에게 어떤 설명이 실제로 도움이 됐는가? | 어떤 비교 기준이 다음 판단에 도움이 됐는가? |

핵심은 서로 다른 직업을 추천하는 것이 아니라 **같은 직업 안에서도 기여와 축적 경로가 근거에 따라 달라지는 것**이다. 직업명만 같고 근거가 다를 때 실행까지 동일한지 검사한다. 반대로 근거가 같은데 차별화를 위해 다른 길을 강요해서는 안 된다.

## 5. 데이터 처리 단계별 감사 계약

1. **물었는가:** 문항의 내용·유형·선택 수·순위 요청 여부·기타 입력·상황 범위.
2. **보존했는가:** 원응답에서 표준화로 갈 때 보기 내부 쉼표, 복수 선택, 결측, 기타 입력, 버전을 보존했는가.
3. **사용했는가:** 명세 매핑의 축/섹션과 실제 엔진의 소비 필드를 분리해 추적한다.
4. **해석했는가:** 응답 관계가 근거 있는 의미 차이로 이어졌는가. 출처만 저장했다고 해석 활용으로 세지 않는다.
5. **보였는가:** 엔진 결과가 고객 강조 문장·설명·키워드·제안에서 사라지지 않았는가.
6. **도움이 됐는가:** 이해·행동 선택·실제 기여의 검증은 코드 민감도와 별도다.

감사 분류: `보존됨 / 일부 압축·손실 / 해당 출력에서는 반응 미관측 / 애초에 미측정 / 확인 필요`.

단일 합성 예에서 문장이 바뀌지 않았다는 이유만으로 문항 전체가 무용하다고 결론 내리지 않는다. 반대로 고유코드만 바뀐 것을 의미 반영으로 세지 않는다. 시간·식별자·해시만 달라진 출력은 내용 비교에서 제외한다.

## 6. 필수 반례·품질 검사

- **같은 직업, 다른 근거:** 제목은 같아도 적절한 기여·조건·실행·축적이 구별되는가.
- **같은 응답, 다른 이름:** 의미 해석은 일관적인가. 이름 차이를 고유성으로 세지 않는다.
- **첫 선택 고정, 두 번째 선택 변경:** 근거상 중요한 변화가 필요한 층에 드러나는가.
- **순서만 변경:** 순위를 묻지 않았다면 입력 순서에만 의존한 우월·선호 해석을 하지 않는가. 기존 코드가 순서 민감하면 버전 변경으로 다룬다.
- **유사·경계·상충 응답:** 반대 결론을 과도하게 만들거나 모순을 지워 버리지 않는가.
- **정보가 없음:** 임의 대상·경력·능력·전문성·은사·자산화 성과를 채워 넣지 않는가.
- **사용자 재설명:** 사용자가 뜻·자신에게 해당하는 이유·다음 행동을 자신의 말로 설명할 수 있는가. 미실시 독자 검증을 자동 검사로 대체하지 않는다.
- **확대된 표본:** 문장 충돌률, 의미 중복, 근거 충실도, 입력 변화 민감도, 길이/가독성, 실행 적합성을 따로 보고한다. 임의 종합점수나 8억 명 검증 주장 금지.
