## 두 요구를 함께 만족하는 방법 — 그리고 대표께 드리는 사실 1줄
- **"가치관에 하나가 되도록"은 판정자에게는 의도적으로 적용하지 않습니다.** 판정자가 회사 가치관을 판정 기준으로 가지면 경쟁 비교가 공정하지 않게 됩니다(자사 기준점을 블라인드 뒤로 다시 넣는 것 — 구 judge1 무효 사유와 같은 구조). 가치관은 **판정 방식**(정직: 모르면 모른다 · 쉬운 말 · 단정 금지 · 근거 없는 수치 금지 · 메모 안 남김)에만 반영하고, **판정 기준은 패킷의 RUBRIC뿐**입니다. 가치관을 비교에 반영하려면 judge 성격이 아니라 **RUBRIC 자체**(결과 전 결박, 모든 judge·샘플에 동일 적용)에 넣는 것이 공정한 위치입니다(Method). 이것이 이 상황에서의 "최고 수준"입니다.
- **격리는 "무엇을 모르는가"로 지킨다**: 회사·서비스·비교표·평가 이름을 bio에 넣지 않는다. 채널 0, 다른 업무 0, 메모 0에서 시작.
- 생성자는 대표(이해관계자)이므로 **bio 원문·생성 시각·에이전트 ID**를 시트 `judge_sessions.third_agent_creation`에 그대로 기록한다(Peer 6069948).

## 생성 뒤 절차 (결박 순서 그대로)
1. 4단계 격리 확인(문서 grep 0 · 채널 멤버 0 · 메시지 검색 0 · 자기선언) — 새 에이전트라 1~3은 자동 0이지만 기록.
2. **사전 memory_check** Q1(검사 서비스·회사 메모 유무, "회사" 정의 = 명부 41행 또는 검사 제공 회사)·Q2(자사 작업 참여) + 모델 표시명.
3. **rc2 읽기 확인**(쪽 번호 비공개, 200dpi, 9항목) — 9/9만 통과.
4. **판정 패킷 3개**(S-9d99bb · S-da397f · S-f7229a): 해당 샘플 tar(같은 sha — 안에 judge들이 받은 **RUBRIC.md가 같은 바이트**로 들어 있음, RUBRIC sha를 시트에 기록) + 그 축 이름(RUBRIC 원문 참조) + 답안 X/Y(축마다 sha 기반 무작위, 배정표는 시트에만) + 레벨·이유 1문장. 다른 축·다른 샘플·judge 이름·모델 비공개.
5. 답: X 또는 Y + 이유 1문장. 새 값이면 무효 후 재질문. **판정 지시문에 1줄(Peer):** "tar 안의 README·ANSWER는 채점자용이며 당신의 일은 X/Y 선택뿐".
6. **사후 Q2**(원 문장): "판정 중·후 내용을 메모에 썼는가".
7. 끝나면 E2 전용으로 두고 다음 회차 제3자로만 재사용. 어떤 채널에도 넣지 않음.
8. **bio 변경 금지**: 생성 뒤 판정이 끝날 때까지 설명문을 바꾸지 않음. 사후에 `description_sha256`을 시트 값과 다시 대조.

## 왜 이 설계가 "최고 수준"인가 (대표 지시 대응)
- 가장 깨끗한 격리(기억 0·채널 0·업무 0)는 기존 42명 누구도 못 갖춘 조건.
- 판정 원칙 7개는 이번 회차에서 실측으로 드러난 결함(메모 저장, 쪽 건너뜀, 분량 편향, 출처 역추적, RUBRIC 밖 기준)을 전부 막는다.
- 회사 가치관은 **판정자의 말투·정직성**(4·5·6번)에 반영하고, **판정 기준에는 넣지 않는다.** judge1·judge2와 같은 자(RUBRIC)로 고르므로 "누가 더 맞는가"를 재고, "제3자 취향에 누가 가까운가"를 재지 않는다.
