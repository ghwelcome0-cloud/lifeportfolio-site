- 작성일: 2026-08-28
- 범위: 문안·검사 명세만 제안. 구현 및 제품 파일 수정 없음.
- 보존 원칙: 완료 판정 기준은 삭제하거나 완화하지 않고, 지면에 따라 표현만 고정 변주한다.

### 배치 규칙

1. 위 15개 문안은 `완료기준 ID × 지면 ID`의 고정 매핑으로 관리한다.
2. 같은 지면·같은 완료기준이면 응답 내용과 생성 순서가 같을 때뿐 아니라 다를 때도 동일한 문안을 쓴다. 개인화는 이 판정 문장이 아닌 주변 설명에서 처리한다.
3. 문안을 임의로 섞거나 후보군에서 추첨하지 않는다.
4. 판정 기준 ID를 문안과 분리해 보관한다. 문안을 고칠 때는 해당 ID의 필수 의미 요소를 대조한다.
5. ③의 프로그램 V장 문안은 실제로 수신 완료를 관찰할 수 있을 때만 채택한다. 관찰 가능한 값이 발송 완료뿐이면 **“끝까지 해낸 기록을 포함한 결과를 받을 사람에게 보내면 이 작업은 끝입니다.”**로 고정한다. 판정 가능 범위를 문안이 앞서가면 안 된다.

## R-3b. 반복 검출 게이트 명세

### 1. 목적과 검사 단위

- 목적: 한 개의 최종 리포트 또는 프로그램 산출물 안에서 동일 문장이 과도하게 재등장하는 회귀를 배포 전에 막는다.
- 검사 단위: 사용자에게 전달되는 최종 산출물 1건. 리포트와 프로그램이 별도 파일이면 각각 검사하고, 묶음 상품이면 개별 결과와 결합 결과를 모두 검사한다.
- 입력: 최종 렌더 직전의 사용자 가시 텍스트. HTML 소스 문자열이 아니라 DOM에서 추출한 본문을 우선한다. 숨김 노드, `script`, `style`, 접근성 보조용 중복 텍스트는 제외하되 PDF에 실제 표시되는 텍스트는 포함한다.
- 문장 분리: 마침표·물음표·느낌표·줄바꿈과 한국어 목록 항목 경계를 사용한다. 표 셀과 카드 제목도 독립 문장 단위로 센다. 문장 분리 결과 원문과 위치를 함께 보존한다.

### 2. ‘같은 문장’의 정의

배포 실패 판정은 **정규화 후 완전 일치**를 기본으로 한다.

정규화 순서:

1. Unicode NFC 정규화
2. HTML entity 해제 및 NBSP를 일반 공백으로 변환
3. 앞뒤 공백 제거
4. 연속 공백·탭·줄바꿈을 공백 하나로 축약
5. 문장 맨 앞의 목록 표지(`•`, `-`, `①`, `1.` 등)만 제거
6. 문장 끝의 마침표·물음표·느낌표 중복만 하나로 통일한 뒤 종결부호를 비교키에서 제거

보존 항목:

- 조사, 어미, 단어, 숫자, 고유명사, 문장 내부 문장부호는 제거하거나 치환하지 않는다.
- 대소문자는 영문에 한해 소문자로 통일할 수 있다.
- 숫자·주차·단계 번호를 와일드카드로 바꾸지 않는다. `1주차`와 `2주차`를 같은 문장으로 보면 정상적인 구조 문구까지 대량 오탐할 수 있기 때문이다.

유사도 검사는 배포 실패 조건에서 분리한다.

- 문자 3-gram cosine 또는 문장 임베딩 유사도는 **경고용 보조 지표**로만 둔다.
- 권고 경고값: 길이 20자 이상인 두 문장의 문자 3-gram cosine ≥ 0.92.
- 이유: 이번 수정처럼 의미를 의도적으로 보존한 변주는 유사도가 높을 수 있다. 유사도만으로 실패시키면 정상 변주를 결함으로 오판한다.

### 3. 실패 임계값 N

- 기본값: 동일 정규화 문장이 한 산출물에 **3회 이상** 나오면 실패(`count >= 3`). 즉 N=3.
- 근거:
  - 현재 문제로 보고된 노출은 문장별 약 5회이므로 확실히 검출한다.
  - 2회는 목차–본문, 지시–요약처럼 의도된 재호명이 흔해 바로 실패시키면 오탐 부담이 크다.
  - 3회째부터는 사용자가 “또 이 문장”으로 체감할 가능성이 커지고, 단일 산출물의 일반 본문에서 같은 완결 문장을 세 번 그대로 써야 할 편집상 필요가 드물다.
- 별도 경고: 2회는 실패시키지 않고 위치를 출력한다. 편집자가 의도 여부를 검토할 수 있게 한다.
- 짧은 문장: 정규화 후 12자 미만은 기본 실패 집계에서 제외하고 별도 빈도표로 낸다. `확인하세요`, `다음 단계` 같은 UI 문구가 본문 품질 실패를 과도하게 만들 수 있기 때문이다.

### 4. 의도된 반복의 예외 처리

전역 문자열 무시는 금지한다. 예외는 버전 관리되는 명시적 레지스트리에서 다음 네 값을 함께 가져야 한다.

- `normalized_text_hash`: 정규화된 정확한 문장의 해시
- `scope`: 허용되는 문서 유형과 섹션 또는 컴포넌트 ID
- `max_occurrences`: 허용 상한. 무제한 금지
- `reason` 및 `owner`: 반복이 필요한 이유와 재검토 책임자

운영 규칙:

1. 머리말·법적 고지·페이지 푸터처럼 반복이 기능적으로 필요한 문구만 예외로 둔다.
2. 예외 문장이 허용 범위 밖에 나오거나 허용 상한을 넘으면 실패한다.
3. 와일드카드·정규식 예외 및 문서 전체 제외는 금지한다.
4. 예외 추가·상한 증가는 문안 리뷰 대상으로 남긴다.
5. 완료 판정 기준 문장은 핵심 상품 문구이므로 예외 등록 대상이 아니다.

### 5. 출력과 실패 리포트

각 중복군마다 다음을 출력한다.

- 원문과 정규화 문장
- 출현 횟수
- 문서명, 페이지/섹션, DOM 경로 또는 안정된 블록 ID
- 앞뒤 문맥 각 40자
- 예외 적용 여부와 예외 ID
- 판정: `PASS`, `WARN(count=2)`, `FAIL(count>=3)`

프로세스 종료코드는 실패군이 하나라도 있으면 1, 없으면 0으로 한다. 경고만 있으면 0이다.

### 6. 게이트 자체의 음성·양성 검증

- 음성 검증 A: 동일 문장을 공백·NBSP·줄바꿈·종결부호만 달리해 3회 넣은 fixture는 반드시 FAIL.
- 음성 검증 B: 동일 문장을 서로 다른 세 섹션에 그대로 넣은 fixture는 반드시 FAIL.
- 음성 검증 C: 예외 문장을 허용 범위 밖에 한 번 더 넣거나 상한을 넘긴 fixture는 반드시 FAIL.
- 양성 검증 A: 동일 문장 2회는 WARN이되 종료코드 0.
- 양성 검증 B: 이번 R-3의 15개 문안은 정규화 완전 일치 중복이 없으므로 PASS.
- 양성 검증 C: 숫자만 다른 정상 주차 제목과 12자 미만 UI 문구는 본문 중복 실패를 내지 않아야 한다.
- 안전장치: 음성 fixture 중 하나라도 PASS하면 게이트 자체를 실패 처리한다.

### 7. 오탐 위험

1. **표 머리글·페이지 푸터:** 인쇄 레이아웃상 매 페이지 반복되는 문구가 3회를 넘을 수 있다. 안정된 컴포넌트 범위와 상한을 둔 예외로만 처리한다.
2. **법적·안전 고지:** 문구 변경이 허용되지 않는 고정 고지가 반복될 수 있다. 정확 문장 해시와 필요한 섹션만 예외 처리한다.
3. **목차와 본문의 동일 제목:** 제목이 본문에도 그대로 나타나 세 번이 될 수 있다. 제목 노드를 별도 유형으로 집계하되, 본문 완결 문장과 섞어 세지 않는다.
4. **PDF 텍스트 레이어 중복:** 시각적으로 한 번 보이는 글자가 렌더러 때문에 두 번 추출될 수 있다. DOM 검사와 PDF 추출 결과가 어긋나면 즉시 문안 결함으로 단정하지 말고 렌더 중복 여부를 확인한다.
5. **의도적 학습 반복:** 워크북에서 같은 지시를 반복하는 것이 교육적으로 필요할 수 있다. 그래도 전역 면제하지 않고 해당 활동 블록과 최대 횟수를 명시한다.
6. **정상적인 의미 보존 변주:** R-3 문안들은 의미가 같아 유사도 임계값을 넘을 수 있다. 따라서 유사도는 경고만 내고 정규화 완전 일치만 자동 실패시킨다.

## 자기 반박

1. **변주가 오히려 기준을 흐릿하게 만들 수 있다.** 맞다. 특히 `모였다/볼 수 있다`, `보냈다/받았다`는 관찰 가능한 상태가 다를 수 있다. 그래서 문안보다 먼저 완료기준 ID와 필수 의미 요소를 고정하고, 문안마다 동일성 검토를 붙였다. ③ 프로그램 V장의 수신형은 수신을 실제 확인할 수 없으면 발신형으로 되돌려야 한다.
2. **15개 변주가 편집 부담과 유지보수 비용을 키운다.** 한 기준을 바꿀 때 5개 문안을 함께 고쳐야 한다. 이를 줄이려면 자유 문안 15개가 아니라 `기준 ID × 지면 ID` 매핑과 의미 요소 체크리스트로 관리하고, 한 기준의 문안들을 묶어 리뷰해야 한다.
3. **N=3은 근거가 충분히 실측된 수치가 아니다.** 현재 사용자의 반복 피로가 몇 회부터 시작되는지 사용자 시험은 미실시다. N=3은 현재 약 5회 문제를 잡으면서 2회 재호명은 허용하려는 보수적 운영값이다. 실제 산출물 표본의 중복 분포와 사용자 검토 결과를 모은 뒤 조정해야 한다.
4. **정규화 완전 일치만 실패시키면 표현을 조금만 바꾼 반복을 놓친다.** 맞다. 그러나 의미 동일 문장을 자동 실패시키면 이번의 의도적 변주까지 잡는다. 첫 단계는 완전 반복 회귀를 확실히 차단하고, 유사도 결과는 편집 리뷰 대상으로 축적한 뒤 별도 근거가 생길 때 실패 규칙으로 승격하는 편이 안전하다.
5. **문장 단위 검사는 카드·표 구조의 반복 체감을 놓칠 수 있다.** 같은 문장이 아니어도 같은 카드 구조와 인접 문맥이 계속 반복되면 독자는 반복으로 느낀다. 이 게이트는 동일 문장 검출의 하한선이지 산출물 고유성 전체의 합격증이 아니다. 구조 다양성과 응답 반영도는 별도 검사로 다뤄야 한다.
