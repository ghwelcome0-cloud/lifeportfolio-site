# P1-B 대체 검증 도구 3종 상세 설계 v1.0

작성일: 2026-08-28  
성격: 설계·공표 규칙 초안 / 인증·외부 감사·EFPA 평가·ISO 적합성 증명 아님

## 0. 결론과 선행 교정

세 도구는 **인증의 대체물**이 아니라, 현재 가능한 증거를 더 재현 가능하고 정직하게 공개하는 도구다. 따라서 목표는 “인증 없이 4점 자동 획득”이 아니라 **수정된 4점 앵커를 사전 공개한 뒤 그 앵커를 실제로 충족했는지 독립 채점하는 것**이어야 한다.

현재 자료만으로 R2·R5·R6을 4점으로 올리거나 ⑤축 93.33점을 공표할 수 없다. 이유는 다음과 같다.

1. 원 rubric v1.0은 1·3·5점만 정의하고 **2·4점 앵커가 없다**. 사후에 “인증분만 빠졌으므로 4점”이라고 보간하면 결과를 본 뒤 기준을 만든 것이 된다.
2. R2의 38/38은 전 문항이 아니며, 200/200은 “대규모 표본”이라는 원문의 요건을 충족한다고 사전 정의된 적이 없다. 38/38·200/200은 제한된 내부 소프트웨어 회귀 표본이다.
3. R5의 EFPA 2025는 “등급을 받기 위한 한 항목”이 아니라 문서화·규준·신뢰도·타당도·공정성·디지털 보고서를 포괄하는 90쪽 리뷰 모델이다. 공개 문서만으로 전체가 충족되지는 않는다.
4. R6은 현재 `npm test`의 산출물 품질 검사가 0개라는 최신 실측이 제시됐다. 과거 “86 게이트·203 회귀” 주장은 현재 저장소에서 재현되지 않으므로 현행 증거로 쓸 수 없다.
5. EFPA 2025 자체 척도는 `n/a, 0, 1, 2, 3, 4`이며 4가 Excellent다. 우리 rubric의 1~5와 동일 척도가 아니다. 두 점수를 직접 치환하면 안 된다.

### 권고하는 v1.1 4점 공통 앵커

> **4점 = 3점 요건을 충족하고, 사전 공개된 절차·원문·판정규칙을 사용해 제작팀과 분리된 2인 이상이 독립 수행했으며, 핵심 결과와 증거 digest가 일치하고, 불일치·미충족·한계를 함께 공개한 상태. 단, 외부 감사·기관 평가·인증은 없음.**

이 앵커는 기존 원문의 발견이 아니라 **향후 적용할 rubric 개정안**이다. rubric v1.1로 먼저 버전 고정하고, 실행 전에 공개해야 한다.

# T-2. 항목 2 — 제3자 독립 재현 프로토콜

## 1. 목적과 비목적

목적은 제3자가 제공된 절차와 공개 자산만으로 응답 변화·출력 변화 및 fingerprint 충돌 검사를 재실행할 수 있는지 확인하는 것이다.

다음은 측정하지 않는다.
- 사람의 재검사 신뢰도
- 구성·준거·예측타당도
- 실제 인구에서의 개인 고유성
- 외부 감사 또는 인증 적합성

## 2. 재현 절차서 목차와 필수 기재 항목

1. **문서 상태**: 프로토콜 버전, 공개일, 변경 이력, 사전등록 시각
2. **대상 release**: Git commit, `instrument_release_id`, manifest SHA-256
3. **목적·가설**: 어떤 입력 변화가 어떤 산출 경로에 영향을 줘야/주지 않아야 하는가
4. **모집단이 아닌 시험공간 정의**: core 56, conditional Other 최대 20, 응답 유형·허용값·조건부 노출
5. **표본 생성 규칙**: seed, 표본 수 결정 근거, 층화/경계값, 중복 제거, 금지 조합
6. **개입 단위**: 한 번에 바꿀 QID, 원값/대체값, 다른 입력 고정 방법
7. **환경**: OS, 런타임·브라우저 버전, locale/timezone, dependency lock digest
8. **실행 명령**: clean checkout부터 build·run·export까지 복사 가능한 명령
9. **관찰 대상**: score, tier, 고객 노출 문장, program, fingerprint32/64를 분리
10. **동등성 규칙**: 제외 가능한 timestamp/nonce와 byte-equal 또는 canonical JSON 비교법
11. **기대 출력**: 사전 공개한 machine-readable schema; 결론값은 blind packet에서 제외
12. **판정 규칙**: PASS/FAIL/INCONCLUSIVE와 각 실패 유형
13. **음성·양성 통제**: 일부러 변화가 없어야 하는 입력, 변화가 반드시 감지돼야 하는 결함 fixture
14. **증거**: raw log, manifest, fixture hash, output hash, 환경 캡처
15. **편차 처리**: 재실행 횟수, 환경 불일치, 누락, 프로토콜 위반
16. **공개 패키지**: 원자료가 합성인지, 개인정보 0인지, 재실행 라이선스

## 3. 시험 설계

### A. 단일 문항 반응성
- Q3~Q78의 **각 평가 대상 입력**을 기준값에서 하나씩 변경한다.
- conditional Other는 활성/비활성 조건과 텍스트/숫자 문자열을 별도 시험한다.
- “무엇이든 달라지면 성공”이 아니다. contribution registry에 따라 `axis_score`, `narrative`, `fingerprint`, `excluded` 중 **예정된 경로만** 달라져야 한다.
- 예정된 불변 경로가 바뀌어도 FAIL이다.

### B. 충돌 시험
- 공개된 seed와 생성기로 서로 다른 합성 응답 N개를 만든다.
- fingerprint 충돌뿐 아니라 동일 fingerprint에서 고객 노출 산출이 다른 경우, 서로 다른 입력에서 산출 전문이 같은 경우를 따로 센다.
- N은 먼저 파일럿 분포를 측정한 뒤 고정한다. `N=200=대규모`라고 사후 명명하지 않는다.

### C. 결정론 시험
- 동일 release·동일 입력을 최소 3회 실행한다.
- 허용된 비결정 필드를 제외한 canonical output digest가 모두 같아야 한다.
- 이는 software determinism 결과로만 기록한다.

## 4. 제3자 채점자 요건·선정

최소 **2명**을 권고한다. 1명은 실행 오류와 해석 오류를 구분하기 어렵다.

필수:
- 프로토콜 작성·엔진 구현·fixture 생성에 참여하지 않음
- 테스트 자동화 또는 재현 연구 경험 1명 이상
- 측정/연구설계 또는 심리측정 배경 1명 이상
- 결과를 보기 전에 이해상충·소속·보상·사전 접촉 공개
- 저장소 read-only, 수정 제안은 별도 기록
- 우리 예상 결론·기존 38/38·200/200·목표 점수를 제공받지 않음

내부 에이전트는 **절차상 분리된 내부 제3자**일 수는 있으나 조직적 독립 외부 감사자가 아니다. 결과에는 `내부 독립 재현`으로 표기한다.

## 5. Blind 지시문

> 제공된 프로토콜과 공개 패키지만 사용해 시험을 실행하십시오. 제품팀의 기존 결론과 목표 점수는 제공되지 않습니다. 각 케이스를 PASS/FAIL/INCONCLUSIVE로 판정하고 raw log·환경·commit·manifest·fixture/output digest를 보존하십시오. 어떤 결과도 고치지 말고 발견 그대로 기록하십시오. 절차가 모호하거나 필요한 자산이 없으면 추정하지 말고 INCONCLUSIVE로 판정하십시오. 소프트웨어 결정론을 재검사 신뢰도·타당도·개인 고유성으로 해석하지 마십시오. 채점 완료 전 다른 채점자와 결과를 공유하지 마십시오.

## 6. 최소 4점 조건

아래를 **모두** 만족해야 rubric v1.1의 R2=4 후보가 된다.

1. v1.1 4점 앵커와 프로토콜을 결과 확인 전에 공개
2. Q3~Q78 contribution registry 기준의 전 범위 시험; 단순 38개만으로 “전 문항” 주장 금지
3. 표본 수와 생성분포를 사전 고정하고 합성 원자료·seed 공개
4. 독립 채점자 2명이 완주하고 핵심 case 판정, aggregate count, output digest가 100% 일치
5. 불일치 0이 아니면 조정 전 원결과와 원인을 공개하고 재시험은 새 버전으로 수행
6. 음성 통제는 모두 FAIL 감지, 양성 통제는 모두 PASS
7. 외부 감사 없음과 표본 범위를 결과 상단에 고정

이는 설계 기준이며 현재 충족 여부는 **미측정**이다.

## 7. 공표 양식

> **검증 유형:** 내부 독립 재현(외부 감사 아님)  
> **대상:** release ___ / commit ___ / manifest ___  
> **절차:** 사전 공개 URL ___  
> **채점자:** 2명, 제작·프로토콜 작성 미참여(소속·이해상충 공개)  
> **결과:** 총 ___건 중 PASS ___ / FAIL ___ / INCONCLUSIVE ___  
> **일치:** 조정 전 판정 일치 ___%, 핵심 digest 일치 ___%  
> **한계:** 합성 입력과 해당 release의 소프트웨어 동작만 확인. 외부 감사, 개인 고유성, 재검사 신뢰도, 타당도 증거가 아님.

자체 수행이면 `검증 유형: 자체 채점`으로 바꾸고 제3자라는 말을 쓰지 않는다.

# T-5. 항목 5 — EFPA Test Review Model 2025 자기평가 공표

## 1. 출처와 적용 경계

- EFPA 공식 소개: https://www.efpa.eu/resource/efpa-test-review-model-version-2025/
- EFPA 공식 PDF: https://www.efpa.eu/wp-content/uploads/2025/08/efpa_test_review_model_v2025_5-1.pdf
- 문서명: *Model for the Review, Description and Evaluation of Psychological and Educational Tests*, Version 5.0, August 2025.

공식 원문은 개발자·출판자가 자체 품질평가에 모델을 사용하는 것을 권장하지만(p.2), 그 rating이 EFPA의 endorsement·approval·recommendation을 뜻하지 않으며 그렇게 광고해서는 안 된다고 명시한다(p.2). 따라서 `EFPA 등급 자기획득`은 금지하고 `EFPA 2025 항목을 참조한 자체 점검`만 허용한다.

EFPA 원척도는 `n/a / 0(정보 부족으로 평가 불가) / 1(Inadequate) / 2(Adequate) / 3(Good) / 4(Excellent)`다(p.18). 우리 1~5 rubric으로 변환하지 않고 **원척도 그대로 별도 표**에 쓴다.

## 2. EFPA 평가 항목 목록

### Part A — 설명(점수화가 아닌 사실 기술)
1. Factual description
2. Classification
3. Measurement and scoring
4. Digitally-generated reports
5. Supply arrangements and materials
6. General description of the instrument

### Part B — 평가
- 6. 설명·근거·정보의 품질
  - 6.1 Rationale and development
  - 6.2 Adequacy of documentation available to the user
  - 6.3 Quality of procedural instructions
  - 6.4 Overall adequacy of rationale and documentation
- 7. Test materials
  - 7.1 Technology-enabled materials
  - 7.2 Paper/non-technology materials
- 8. Norms
  - 8.1 Norm-referenced interpretation
  - 8.2 Criterion-referenced interpretation
  - 8.3 General considerations and overall adequacy
- 9. Reliability/Precision
  - 9.1 Data provided
  - 9.2 Internal consistency
  - 9.3 Test–retest/temporal stability
  - 9.4 Parallel/alternate forms
  - 9.5 IRT methods
  - 9.6 Inter-rater reliability
  - 9.7 Other methods
  - 9.8 Overall adequacy
- 10. Validity
  - 10.1 Content
  - 10.2 Internal structure
  - 10.3 Relations to other variables
  - 10.4 Other sources
  - 10.5 Overall validity evidence
- 11. Supporting Fair Use
  - rationale/documentation, design, piloting/analysis, reliability, validity, interpretation, reports, overall evaluation
- 12. Digitally Generated Reports
  - 12.1 Scope/coverage
  - 12.2 Reliability
  - 12.3 Relevance/validity
  - 12.4 Fairness/freedom from bias
  - 12.5 Acceptability
  - 12.6 Level of detail
  - 12.7 Overall adequacy

세부 문항은 공식 PDF 전체를 정본으로 삼는다. 요약 목록을 원문 대체물로 쓰지 않는다.

## 3. 자기평가 3열 공표표

현재 상태 칸은 반드시 `충족 / 부분 충족 / 미충족 / 확인 불가 / 비적용 후보` 중 하나와 증거 URL을 가진다. 아래는 현재 알려진 사실로 만든 **초기 상태**이며, 점수 부여 전 독립 확인이 필요하다.

| EFPA 요구영역 | 우리 현재 상태 | 미충족·증거 상태 |
|---|---|---|
| Part A 1~5 사실 기술 | 부분 충족 | 문항·매핑·엔진·룰 문서는 있으나 하나의 공개 release manifest와 버전 provenance 미구현 |
| 6.1 근거·개발·문항 품질 | 미충족 | 4축 이론모형, SME 내용타당도, item analysis 미완료 |
| 6.2 사용자 문서 | 부분 충족 | 제작규칙·설명 문서는 존재. 규준·신뢰도·타당도 문서화는 근거 자체가 없음 |
| 6.3 절차 지침 | 부분 충족 | 운영/채점 안내 일부 존재. 자동채점 오류 점검·공정성·제한·지원의 완전성 미확인 |
| 7.1 디지털 재료 | 확인 불가 | UI·접근성·오류 복원 전 항목의 최신 동일조건 실측 필요 |
| 7.2 비디지털 재료 | 비적용 후보 | PDF가 평가 재료인지 결과물인지 정의 후 독립 판정 필요. 임의 N/A 금지 |
| 8 규준 | 미충족 | 규준 표본·대표성·백분위 없음 |
| 9 신뢰도/정밀도 | 미충족 | 내적 일관성·재검사·등가형·IRT·평가자 신뢰도 연구 없음 |
| 10 타당도 | 미충족 | 내용·내부구조·수렴/판별·준거/예측 연구 없음 |
| 11 공정 사용 | 확인 불가/대부분 미충족 | 라벨 회피·고지는 일부 있으나 집단별 bias/DIF·동등성 연구 없음 |
| 12.1 보고서 범위 | 확인 불가 | 적어도 서로 다른 score profile 3개를 근거와 함께 독립 평가해야 함 |
| 12.2 보고서 reliability | 미충족 | 결정론 증거는 있으나 측정오차를 반영한 해석·경고 근거 없음 |
| 12.3 보고서 relevance/validity | 미충족 | 점수→문장 규칙 문서는 일부 있으나 관계의 경험적 근거 없음 |
| 12.4 fairness | 확인 불가 | 언어 규칙은 있으나 집단별 편향 평가 미완료 |
| 12.5 acceptability | 확인 불가 | 목표 사용자 이해도·수용성 연구 미완료 |
| 12.6 detail | 확인 불가 | 보고서 길이·구체성 대비 측정 정밀도 정당화 미완료 |
| 12.7 overall | 평가 유보 | 12.1~12.6 독립 평가 전 종합점수 금지 |

# 자기 반박 — 이 설계가 실패할 수 있는 이유

1. **제3자 재현은 외부 감사와 동등하지 않다.** 인정 범위는 “공개된 절차를 다른 실행자가 같은 release에서 재실행했다”까지다. 감사인의 독립성, 전문직 책임, 통제환경 검토, 표본선정 보증, 인증기관 감독을 제공하지 않는다.
2. **같은 조직의 에이전트는 조직적으로 독립하지 않다.** blind와 역할 분리는 확인편향을 줄이지만 외부 이해관계 독립성을 만들지 못한다. 따라서 `내부 독립 재현`으로만 표기해야 한다.
3. **원 rubric의 4점이 비어 있다.** 지금 만든 4점 앵커는 사후 보간이 아니라 다음 버전용 개정이어야 한다. 기존 결과에 소급 적용하면 점수 조작이 된다.
4. **EFPA 자기평가는 문서가 좋아 보이는 효과를 낼 수 있다.** 규준·신뢰도·타당도 결손을 미충족으로 유지하지 않으면 문서화가 측정 품질을 대체하는 오류가 생긴다.
5. **ISO 적용범위가 제한적이다.** ISO 10667은 work/organizational settings 중심이다. 일반 소비자 자기성찰 전체에 적용된다고 단정하면 scope 과장이다.
6. **공개 ISO preview는 요구사항 전문이 아니다.** 제목만 보고 compliance를 채우면 거짓 초록불이다. 정식 원문 검토 전에는 상세 요구를 `출처 미확인`으로 둬야 한다.
7. **재현 표본이 실제 사용자를 대표하지 않는다.** 합성 collision 0은 표본 내 software result일 뿐 모집단 고유성이나 개인화 품질을 보장하지 않는다.
8. **현재 게이트 공백 때문에 R6은 즉시 상승할 수 없다.** npm test 22개 중 산출물 품질 0개라는 최신 실측을 해소하지 않고 4점을 주면 반대 방향의 오판이다.
