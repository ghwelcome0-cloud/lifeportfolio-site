# 2. [M-3] 행동 시나리오 분기 설계

## 2.1 설계 원칙

- 상태 라벨보다 **상황 → 먼저 택한 행동 → 도움이 되는 조건**을 보여준다.
- “앞으로 반드시 이렇게 한다”가 아니라 **응답 당시 선택을 재서술**한다.
- 출력 기본형:

> 당신이 적어준 응답으로 볼 때, **{상황}**에는 **{첫 행동}**을 택한 쪽에 가깝습니다. 이때 **{보조 조건}**이 있으면 움직임을 이어가기 쉽습니다.

- 신호가 충돌하거나 coverage가 부족하면 단정하지 않는다.

> 이 상황에 관한 응답 신호가 한쪽으로 모이지 않았습니다. 상황에 따라 달라질 수 있으니 아래 두 방식 중 실제에 가까운 쪽을 확인해 보세요.

## 2.4 선택·동률·결손 규칙 — 설계(미검증)

1. 상황별 세 모드 점수를 계산한다.
2. 1위가 2위보다 **1.5점 이상** 높고 직접근거가 1개 이상이면 단일 시나리오를 출력한다.
3. 격차가 1.5점 미만이면 상위 두 모드를 “상황에 따라 두 방식을 함께 택했다”로 병기한다.
4. 직접근거 응답률이 60% 미만이면 `insufficient_data`로 두고 행동 단정을 출력하지 않는다.
5. 완전 동률은 고정 우선순위가 아니라 `SHA-256(instrument_release_id + sid + scenario_id)`로 문장을 고르는 방식도 금지한다. 동률은 실제 혼합 신호이므로 두 모드를 그대로 보여 준다.
6. 동일 release와 동일 응답에는 항상 동일 결과가 나온다.

**주의:** 1.5점과 60%는 운영을 위한 초기 설계값이며, SME 검토와 사용자 인지 인터뷰 전에는 최종 임계값이 아니다.

## 2.5 분기·조합 수

- 시나리오 4개 × 행동 모드 3개 = 단일 모드 **12개 출력 슬롯**.
- 혼합형(상위 2개 병기)을 허용하면 상황별 조합은 `3 단일 + C(3,2)=3 혼합 + 1 결손 = 7`, 전체 시나리오 상태 벡터의 이론 상한은 `7^4=2,401`이다.
- 그러나 문항 간 논리적 제약과 실제 응답 분포 때문에 2,401개가 모두 도달 가능하다는 뜻은 아니다.
- **대외 조합 수로 사용 금지.** 구현 후 옵션 제약을 만족하는 property-based 입력과 실제 익명 응답으로 도달 상태 수를 측정해야 한다.

# 3. [M-4] 자기 내 상대 위치 표기

## 3.1 산출식 — 설계(미검증)

입력은 동일 scoring release에서 산출된 네 축 값 `x_i`다.

1. 각 축 coverage가 최소 기준을 통과했는지 먼저 확인한다. 미달 축이 하나라도 있으면 전체 순위를 숨기고 `자료 부족`을 표시한다.
2. 내림차순으로 정렬하되, 차이가 **2.0 퍼센트포인트 미만**이면 공동 위치로 처리한다. 2.0pp는 초기 표시 안정화 값이며 검증 전이다.
3. 평균 `m=(x1+x2+x3+x4)/4`는 **개인 내부 기준선**으로만 계산한다.
4. 각 축의 자기 내 편차 `d_i=x_i-m`을 퍼센트포인트로 표시한다.
5. 전체 폭 `R=max(x)-min(x)`를 표시하되 가치판단을 붙이지 않는다.
6. 설명 구간은 초기 설계로 `R<5: 고른 편`, `5≤R<15: 일부 차이`, `R≥15: 차이가 뚜렷한 편`을 사용한다. 이 구간은 규준이 아니라 UI 서술 임계값이며 사용자 검증 전이다.

**권장:** 표준편차나 개인 내 z점수는 축이 4개뿐이고 축 간 단위 동등성이 검증되지 않아 사용하지 않는다. 정확한 퍼센트포인트 차이가 더 정직하다.

## 3.2 지면 표기

**1순위: 네 개의 동일 길이 기준 막대 + 개인 평균선**

- 고정 순서: 자기이해 → 자기표현 → 자기설계 → 자기실행. 순서 자체를 순위로 재배열하지 않는다.
- 각 막대 끝에 현재 값, 개인 평균선과의 `+/- n.npp`를 표시한다.
- 아래 한 문장만 요약:

> 당신의 네 영역 안에서 이번 응답에 가장 두드러진 것은 **자기실행**이며, 개인 내부 기준선보다 **14.0퍼센트포인트 높습니다**. 자기이해와의 차이는 **17.1퍼센트포인트**입니다.

- “강점/약점” 대신 `더 두드러짐 / 상대적으로 덜 두드러짐`을 쓴다.
- 막대 길이만으로 의미를 전달하지 않고 숫자·텍스트를 함께 제공한다.

## 3.3 금지·허용 문구

| 금지 | 허용 |
|---|---|
| 상위 10%, 백분위 90 | 당신의 네 영역 중 가장 두드러진 것은 |
| 평균보다 높다 | 당신 자신의 네 영역 평균보다 n.npp 높다 |
| 일반 사람보다 강하다 | 이번 응답 안에서 상대적으로 더 두드러진다 |
| 하위권, 취약, 부족 | 네 영역 중 상대적으로 덜 두드러진다 |
| 성장했다/퇴보했다 | 이전 회차와 값이 다르다 — 단, 동일 scoring release에서만 |
| 균형이 좋다/나쁘다 | 네 영역 간 차이가 작다/크다 |

## 3.4 필수 고지 문안

> 이 표는 다른 사람과 비교한 백분위나 규준점수가 아닙니다. 같은 회차에서 나온 당신의 네 영역 참고 지수를 서로 놓아 본 **개인 내부 비교**입니다. 네 지수는 서로 다른 응답 구성과 가중치를 사용하므로, 높고 낮음이 능력·가치·적합성의 우열을 뜻하지 않습니다. 질문·채점 버전이 다르면 회차 간 직접 비교하지 않습니다.

## 3.5 구현 전 차단 조건

- 네 축의 eligible weight, observed weight, coverage, `insufficient_data`가 먼저 구현되어야 한다.
- 선택형 “응답 있음=1.0” 규칙을 그대로 유지할지 별도 scoring 결정이 필요하다.
- 축마다 문항 구성과 가중치가 다르므로, **현재 값의 자기 내 순위가 실제 심리특성의 강약이라는 주장은 금지**한다.

# 4. [M-5] 매칭 규칙 변별력 강화

## 4.1 현재 분기 조건과 문제 구간

| 계층 | 현재 조건 | 실측/구조 문제 |
|---|---|---|
| 4축 점수 | Likert 강도 + 선택형 응답 존재 1.0 + 가중치 | 선택형의 구체적 선택이 축 점수를 바꾸지 않아 서로 다른 응답이 같은 축 프로필을 만들 수 있음 |
| 톤 | Q13 가치 빈도 + 상위 축 + Q63/Q6 보조 + 주도 카테고리 보너스 | 36 fixture에서 4톤×9건, visionary 0. 단 fixture의 축 프로필이 모두 같고 Q13/Q63만 변함 |
| 축 카드 | 축별 제한된 Likert/choice 목록 + fingerprint 템플릿 선택 | 원응답 차이가 있어도 동일 요약 강도·같은 template index면 같은 문장 가능 |
| v4 문장 | tone/category/axis/tier 라이브러리 + fingerprint pick | 전역 hash를 여러 지면에서 salt만 바꿔 쓰므로 의미가 다른 응답이 같은 modulo 슬롯에 충돌 가능 |
| 증거 지면 | 일부 직접 응답 6개 중심 | 읽은 문항 전체와 실제 문장 기여 문항을 혼동할 위험 |

## 4.2 개선 원리 — 설계(미검증)

**톤을 더 많이 만드는 것이 아니라, 독립적인 의미 축을 계층적으로 분기한다.**

```text
Tone family
  └─ Situation profile (M-3 네 상황)
      └─ Action mode (상황별 3모드)
          └─ Evidence anchor (실제 응답 1~2개)
              └─ Surface template variant
```

동일 문장이 되려면 tone뿐 아니라 `scenarioId + mode + evidenceAnchor + templateVariant`가 모두 같아야 한다.

## 4.3 현재 조건 → 개선 조건식

| 현재 | 개선 조건식 — 설계(미검증) | 목적 |
|---|---|---|
| Q13·상위축이 tone 대부분 결정 | tone은 문체만 결정. 행동 내용은 M-3 scenario mode가 결정 | 톤 집중이 내용 반복으로 직결되는 문제 차단 |
| 선택형은 존재만 축 점수에 반영 | 행동 시나리오에서는 **선택한 옵션의 의미 키**를 직접 사용 | 서로 다른 선택이 실제 다른 분기로 연결 |
| 전역 fingerprint `% pool.length` | 의미 키로 1차 pool을 고르고, 그 안에서 hash는 표현 변형에만 사용 | hash 충돌이 의미 충돌이 되지 않게 함 |
| 고정 tie priority | 의미 점수가 동률이면 혼합형으로 보존; 임의 강제승자 금지 | 우선순위 쏠림 억제 |
| 문장 출처 불명 | 각 출력에 `evidenceQids`, `ruleId`, `mappingVersion` 저장 | 반복·오매핑 원인 추적 가능 |

## 4.4 톤 도달성 보정 제안 — 설계(미검증)

톤을 고객 유형으로 노출하지 않는 전제에서, 문체 라우팅용 내부 조건을 서로 겹치지 않게 만든다.

- `principled_designer`: 원칙/안정/책임 신호 + Q60·Q61 높은 응답 + 계획/마감 방식
- `warm_connector`: 관계 신호 + 대화/협력/공감 행동 선택
- `visionary_creator`: 성장·자유 신호 + Q6 창의/도전 + Q39 창작/탐색 + Q63 자유/재미 + Q70 구상 체류 신호
- `pragmatic_achiever`: 결과 신호 + Q51/Q67/Q68 실행 신호 + Q71 계획/마감/단기완료
- `reflective_explorer`: 자기관찰/복기 신호 + 혼자/글/성찰 회복 행동

각 톤은 **필수 핵심 신호 1개 + 보조 행동 신호 1개**를 요구한다. 조건 불충족 시 tone을 강제하지 않고 neutral copy pool을 쓴다. 이 방식은 빈도 균등화를 목표로 하지 않는다. 실제 응답에서 특정 톤이 적은 것은 결함이 아닐 수 있다.

## 4.5 도달 가능 분기 수 추정

### 구조적 하한 — 설계값

- 4 시나리오 × 3 행동 모드 = 12개 의미 분기.
- 각 의미 분기에 근거 앵커 2종을 보장하면 24개.
- 각 근거 앵커에 표현 변형 2종을 두면 **48개 문장 경로**.
- 이는 이론적 설계 슬롯 수이며 실제 도달 가능 수가 아니다.

### 실제 도달 가능 수 측정법

1. 질문의 max·필수·조건부 규칙을 지키는 property-based synthetic 응답을 생성한다.
2. 각 문항 옵션을 최소 한 번 포함하는 pairwise covering array와 경계 Likert 패턴을 만든다.
3. 각 입력에서 `tone/scenario/mode/evidence/template` 경로 ID를 기록한다.
4. `reachable / declared`, 경로별 빈도, 0-hit 분기, 문장 충돌률을 산출한다.
5. synthetic 결과와 별도로 동의된 실제 익명 응답에서 빈도를 측정한다. 실제 데이터에서는 희귀 분기를 결함으로 자동 판정하지 않는다.
6. 음성 검증: 일부러 dead branch, 동일 문장, 잘못된 evidence QID를 심은 fixture가 반드시 FAIL해야 한다.

### 권장 acceptance — 설계(미검증)

- 선언된 48개 문장 경로의 synthetic 도달률 100%.
- 각 행동 모드에 최소 2개의 서로 다른 유효 입력 fixture.
- 의미가 다른 `scenario+mode` 간 정규화 문장 완전일치 0건.
- 같은 응답·같은 release 반복 실행의 경로 ID와 문장 일치 100%.
- 한 문항 변경 시 무조건 문장이 달라져야 한다는 기준은 사용하지 않는다. 그 문항이 해당 지면에 의미상 기여하지 않는 경우 동일 결과가 정당할 수 있다.

**개선 후 실제 도달 가능 분기 수:** 현재는 미측정이며, 구현 전이므로 추정 확정 불가. 구조상 목표는 최소 48개 경로지만, 도달성은 위 covering-array gate로 검증해야 한다.

# 5. 검증 계획

## 5.1 정적 계약 검사

- 시나리오에 참조된 QID가 모두 core 질문에 존재하는가.
- option key가 질문의 실제 option과 정확히 일치하는가.
- 각 mode에 직접근거가 최소 1개 있는가.
- 자유입력 otherId가 숫자형 Likert로 silent fallback되지 않는가.
- 모든 출력에 `ruleId/evidenceQids/release`가 있는가.

## 5.2 결정론·음성 검증

- 동일 release·동일 입력 100회 → 동일 path ID·동일 문장.
- 한 상황의 근거 문항만 바꾸면 그 상황 외 path는 불필요하게 변하지 않아야 한다.
- 결손·동률 fixture는 단정문을 출력하지 않아야 한다.
- dead branch를 심으면 reachability gate가 FAIL.
- evidenceQid를 틀리게 심으면 provenance gate가 FAIL.
- 서로 다른 의미 분기에 같은 문장을 심으면 collision gate가 FAIL.

## 5.3 사용자 검증

정량 연구 전에 목표 사용자 인지 인터뷰 15~30명으로 다음을 확인한다.

- “내가 답한 내용과 연결된다”를 구체적으로 설명할 수 있는가.
- 상황 문장이 미래 단정이나 평가로 읽히지 않는가.
- 자기 내 상대 위치를 타인 백분위로 오해하지 않는가.
- 틀린 문장에 “아니다/상황에 따라 다르다”를 선택할 수 있는가.

그 다음 blinded A/B 평가에서 기존 상태 서술 대 신규 상황 서술을 비교한다. 1차 지표는 `나와 맞는다고 느낀 정도`, 2차는 근거 회상·오해율·반박률이다. 점수 상승을 미리 보장하지 않는다.

# 6. 이 설계가 ②축을 올리지 못할 수 있는 이유

1. **원문항의 한계:** 현재 문항은 특정 상황에서 실제 행동을 반복 관찰한 기록이 아니라 자기보고다. 조건형 문장으로 재구성해도 독자가 실제 모습과 다르다고 느낄 수 있다.
2. **선택형 채점의 현 구조:** 선택 내용이 4축 점수에 반영되지 않는 현 산식과 신규 의미 분기가 함께 노출되면, 지수와 시나리오가 서로 모순돼 공감이 오히려 낮아질 수 있다.
3. **상황 직접 측정 부족:** “선택 과부하”처럼 직접 묻지 않은 상황을 넓게 해석하면 과장으로 읽힌다. 그래서 본 설계는 “기준이 엇갈리는 선택”으로 제한했지만, 이조차 충분하지 않을 수 있다.
4. **자기 내 순위의 오해:** 고지를 붙여도 사용자가 높은 축을 능력, 낮은 축을 결함으로 읽을 수 있다. 네 축의 단위 동등성도 아직 검증되지 않았다.
5. **문장 수와 공감의 비선형성:** 분기를 늘리면 반복은 줄지만, 문장이 길거나 설명이 많아져 핵심 자기인식이 흐려질 수 있다.
6. **fixture와 실사용의 차이:** synthetic 도달성이 좋아져도 실제 사용자의 응답 분포가 특정 패턴에 몰리면 체감 다양성은 개선되지 않을 수 있다.
7. **평가축 자체의 주관성:** 외부 ②축 평가는 문장 품질·디자인·기대 수준의 영향을 함께 받는다. 매핑 규칙만 바꿔도 3차 재평가 점수가 오르지 않을 수 있다.

# 7. 최종 권고

1. M-3은 네 상황·세 행동 모드로 작은 범위에서 시작한다. 직접 묻지 않은 상황은 만들지 않는다.
2. M-4는 coverage와 scoring release가 준비된 뒤에만 노출한다. 정확한 pp 차이와 고지를 함께 쓴다.
3. M-5는 tone 수를 늘리는 작업이 아니라 `상황 → 행동 → 근거 → 표현`의 독립 분기 구조로 바꾼다.
4. 구현 전 SME 5~8명 내용 검토, 구현 후 negative-control이 포함된 도달성 gate, 그 다음 사용자 인지 인터뷰 순으로 진행한다.
5. ②축 목표 도달 여부는 외부 재평가로만 판정한다.
