# P1-A ⑤축 전문성·신뢰감 — 0원 경로 산출

## 1. IX장 결정론 고지 문안 3안

### 권고안 A — 가장 직접적

> 이 리포트는 결정론적 규칙으로 계산합니다. 난수를 사용하지 않으므로 같은 응답을 다시 입력하면 같은 결과가 나옵니다. 이는 **계산 재현성이 증명되었다**는 뜻입니다. 같은 사람이 시간이 지난 뒤 다시 응답해도 같은 결과가 나오는 **재검사 신뢰도는 아직 미증명**이며, 이 결과가 측정하려는 개념을 얼마나 타당하게 반영하는지에 대한 **타당도도 아직 미증명**입니다.

### 안 B — 사용자 친화형

> 같은 응답에는 같은 리포트를 제공합니다. 결과를 임의로 바꾸는 난수는 쓰지 않습니다. 확인된 범위는 **계산 재현성**이며, 이 범위는 증명되었습니다. 반면 **재검사 신뢰도**와 **타당도**는 아직 증명되지 않았습니다.

### 안 C — 기술 투명성형

> 생성 방식: 난수 호출 없이 응답과 규칙만으로 결과를 계산합니다. 동일한 응답 데이터는 동일한 출력을 만듭니다(**계산 재현성: 증명됨**). 이는 시간 간격을 둔 반복검사의 일치도를 뜻하지 않습니다(**재검사 신뢰도: 미증명**). 또한 결과 해석의 타당성을 입증한 것은 아닙니다(**타당도: 미증명**).

### 금지어 판정

| 표현 | A | B | C | 판정 근거 |
|---|---:|---:|---:|---|
| `재현성 100%` 단독 | 없음 | 없음 | 없음 | 비율 주장 안 함 |
| `검증된 재현성` | 없음 | 없음 | 없음 | 허용된 구분 표현 `계산 재현성: 증명됨`만 사용 |
| `정확도 N%` | 없음 | 없음 | 없음 | 정확도 주장 안 함 |
| `과학적 근거에 기반` | 없음 | 없음 | 없음 | 과학성 주장 안 함 |
| `공인 인증` | 없음 | 없음 | 없음 | 인증 주장 안 함 |
| `공인 평가` | 없음 | 없음 | 없음 | 평가기관 주장 안 함 |

권고는 A다. 같은 입력→같은 출력과 난수 미사용을 한 문단에서 가장 명시적으로 말하고, 세 개념의 경계를 완전한 문장으로 남긴다.

## 2. 전체 56문항 매핑 공개표 스펙

### 데이터 원천과 행 정의

- 행 집합: `data/questions.json`의 `sections[].questions[]` 56개 본문항.
- 제외: 20개 `otherId` 입력과 이름·수신방법 메타 2개. 제외 이유를 표 머리말에 명시한다.
- 매핑 SSOT: `data/mapping.json.questionMapping[문항ID]`.
- 표시 순서: 질문 스키마의 화면 순서. 문항 ID 사전순으로 재정렬하지 않는다.
- 매핑 누락, 알 수 없는 축/섹션, 행 수≠56이면 표 생성 실패 처리한다.

### 4개 열

| 열 | 원천 | 표시 규칙 |
|---|---|---|
| 문항ID | `question.id` | `Q3` 등 원문 ID |
| 문항요지 | `question.text` | 전체 질문 문장. 임의 요약으로 의미를 바꾸지 않음 |
| 매핑축 | `questionMapping[id].axes[]` → `mapping.axes[].title` | 복수 축은 ` · `로 병기 |
| 리포트 반영 위치 | `questionMapping[id].sections[]` → `reportSections[].title` | 복수 섹션 모두 병기 |

가중치와 내부 코멘트는 요청한 4열에는 넣지 않는다. 공개 필요가 생기면 별도 부록 열로 추가하되 SSOT 값을 그대로 사용한다.

### 부분 공개를 선택할 때 반드시 붙일 선정 기준 문장

> 이 표는 전체 56문항 중 고객 지면에 문항 근거가 직접 표시되는 항목만 추린 부분 공개본입니다. 선정 기준은 현재 지면의 provenance에 문항 ID가 직접 노출되는지 여부이며, 점수가 높거나 결과에 유리한 문항을 임의로 고른 것이 아닙니다. 전체 56문항 매핑표는 별도 공개본에서 확인할 수 있습니다.

현재 코드 주석상 지면 provenance 집합은 Q13·Q39·Q41·Q47·Q49·Q73으로 고정되어 있다. 부분 공개는 이 6개와 정확히 대응해야 하고, 전체표 링크/위치를 함께 제공해야 “전체 매핑 공개” 요건을 충족한다. 전체표 없이 6개만 보이는 상태는 부분 공개다.

### 산출 자동화

`scripts/gates/build_mapping_disclosure.js`가 질문·매핑 SSOT를 읽고 56행 Markdown 표를 생성한다. 원본 JSON은 수정하지 않는다.

## 3. 게이트 실측

### `determinism_random_gate.js`

- 대상: 엔진 3개.
- 방법: Esprima tokenizer로 JS를 파싱하고 line/block comment token을 제외한 뒤 실행 토큰의 `Math.random(` 호출을 검사한다. 문자열/주석의 문자 일치로 판정하지 않는다.
- 정상 실행: exit 0, 실행 난수 호출 0건.
- 음성 통제: `/tmp` 엔진 사본에 `Math.random();` 삽입 후 동일 게이트 subprocess 실행. 관찰 exit 1.
- 주석 오탐: 원본의 `Math.random` 금지 주석은 검사 결과에 포함되지 않았다.

### `determinism_hash_gate.js`

- 요청된 호출 시그니처 그대로 실제 합성 파이프라인을 2회 실행했다.
- 제외 키: 객체 트리 전체의 `generatedAt`, `publishedAt`, `submittedAt`.
- 객체 키를 정렬한 canonical JSON의 SHA-256을 비교한다.
- 정상 실행: exit 0.
- 리포트 SHA-256: `c18ca862733cf194871e6b29af8bd0f6eaf4a6af0e9f764aa924b835ec836d0c` ×2 일치.
- 프로그램 SHA-256: `be949efe53310ac4e7d4dadb56b79eed9148e50777c479040f65395917a2883c` ×2 일치.
- 음성 통제: 두 번째 리포트 출력의 첫 가용 문자열 1글자 변경 후 동일 게이트 subprocess 실행. 관찰 exit 1.

요청문에 인용된 기존 두 hash prefix와 이번 hash가 다른 이유는 이번 게이트가 정렬된 canonical JSON, 지정 세 키의 재귀 제외, 현재 합성 fixture를 하나의 명시된 계약으로 사용하기 때문이다. 두 측정은 비교 계약이 다르므로 수치 동일을 기대하면 안 된다.

## 4. `test-all.mjs` 편입 줄

```js
run("Determinism random API gate", process.execPath, ["scripts/gates/determinism_random_gate.js"]);
run("Determinism output hash gate", process.execPath, ["scripts/gates/determinism_hash_gate.js"]);
```

두 스크립트 모두 exit 0=PASS, exit 1=FAIL이다. 원본 엔진과 `data/*.json`은 수정하지 않았다.
