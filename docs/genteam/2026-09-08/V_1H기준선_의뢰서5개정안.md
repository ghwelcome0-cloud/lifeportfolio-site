# V — `①-H` 기준선 신설 및 3차 재평가 의뢰서 §5 개정안

## 0. 선결 판정 — “텍스트로만 평가”와 “홈페이지 실물 평가”는 한 채점 절차에 섞지 않는다

### 판정

`①~⑤ 텍스트 재평가`와 `①-H 홈페이지 평가`는 **한 파일에 함께 안내할 수는 있어도, 서로 다른 평가 도구·제출 단계·증거 묶음으로 분리**해야 한다. 권고 구조는 다음과 같다.

1. **본 의뢰서 Part A:** 종전과 동일한 입력·정의로 ①~⑤만 평가한다. 평가자는 개선 후 고객 대면 **텍스트 전문만** 보고 먼저 제출한다.
2. Part A 제출 후 결과를 잠근다. 되돌아가 수정할 수 없게 한다.
3. **별첨 H:** 홈페이지 URL·고정 뷰포트·관찰 과업을 처음 공개하고 `①-H`를 측정한다.
4. 결과표도 `①~⑤ 재평가`와 `①-H 0차 기준선`을 분리한다. `①-H`를 ①~⑤ 균등 가중 평균이나 현재 7축 가중식에 넣지 않는다.

가능하면 Part A와 별첨 H를 **서로 다른 외부 평가 세션**으로 운영한다. 같은 사람이 연속 수행하면 홈페이지에서 본 표현이 텍스트 채점에 스며드는 순서효과가 생긴다. 동일 평가자가 불가피하면 반드시 Part A 선제출·잠금 후 별첨 H를 공개한다.

### 채택하지 않는 방식

- **기존 §5의 “이 텍스트로만 평가”를 삭제하고 홈페이지까지 함께 보게 하는 안:** 기각. 3차 ①~⑤의 입력 범위가 1·2차와 달라져 과거 점수와의 비교가 깨진다.
- **① 정의에 홈페이지 첫인상을 덧붙이는 안:** 기각. 기존 ①축 62→73 시계열의 구성개념이 바뀐다.
- **①-H 문항을 기존 ① 점수의 하위항목으로 합산하는 안:** 기각. 과거 ①에는 해당 하위항목이 없으므로 같은 숫자 이름 아래 다른 점수를 만들게 된다.
- **본문 텍스트와 홈페이지를 동시에 보여 준 뒤 각각 채점하는 안:** 기각. 채점표를 나눠도 관찰 입력이 분리되지 않아 오염을 막지 못한다.
- **완전히 독립된 두 의뢰서로만 배포하는 안:** 측정 독립성은 가장 강하지만, 버전 불일치·누락 위험이 있다. 따라서 본 의뢰서에 Part A/별첨 H의 결합 규칙과 버전을 명시하되 실제 입력 공개와 제출은 분리하는 방식을 권고한다.

## 1. `①-H` 지표 정의서

### 1.1 한 문장 정의와 ①축과의 차이

> **`①-H 홈페이지 첫 화면 이해·진입성`은 표준화된 최초 방문 조건에서 사용자가 홈페이지 첫 화면만으로 서비스의 대상·얻는 결과·다음 행동을 제한 시간 안에 정확히 파악하고, 핵심 진입 동작을 방해 없이 시작할 수 있는지를 재는 지표다.**

기존 ①축은 **제공된 고객 대면 텍스트의 첫인상 직관성**을 평가한다. `①-H`는 렌더링된 홈페이지의 실제 정보 우선순위, 화면 내 노출, 반응형 상태 및 진입 행동을 관찰한다. 같은 “첫인상”이라는 말이 들어가더라도 **입력물과 관찰 단위가 다르다.**

### 1.2 측정 대상 고정

| 항목 | 0차 및 후속 측정의 고정 조건 |
|---|---|
| 지면 | 공개 운영 홈페이지의 단일 랜딩 URL. 다른 캠페인·가격·로그인 페이지는 제외 |
| 언어 | 한국어 기본 지면. 영어판은 별도 표본으로만 기록하고 본 점수에 혼합하지 않음 |
| PC | CSS viewport `1440×900`, 100% 확대 |
| 모바일 | CSS viewport `390×844`, 100% 확대 |
| 사용자 상태 | 비로그인, 해당 도메인 쿠키·localStorage·service worker·cache를 지운 새 브라우저 프로필 |
| 방문 상태 | 최초 방문. 재방문·개인화·A/B 잔존 배정 제외 |
| 시작 상태 | URL 직접 입력 후 최초 로드 완료 시점. 팝업·쿠키 배너도 실제 상태 그대로 포함 |
| 네트워크 | 동일한 사전 정의 프로파일을 사용하고 설정값·브라우저 버전·측정 시각을 증거에 기록 |
| 범위 | 첫 화면 관찰과 주 CTA 1회 진입까지. 인증 뒤 제품 기능은 제외 |

PC와 모바일은 각각 완전한 별도 실행으로 측정한다. 총점은 두 환경 점수의 평균이 아니라 **낮은 환경 점수**로 확정한다. 평균으로 모바일 실패를 숨기는 것을 막기 위함이다.

### 1.3 점수 구조 — 무앵커 총평 금지

평가자는 0~100을 직관적으로 부여하지 않는다. 아래 **10개 관찰항목을 각각 0·5점으로만 판정**하며, PC와 모바일 각각 50점 만점이다. 환경별 점수는 `(통과 항목 수 ÷ 10) × 100`, 최종 `①-H`는 `min(PC 점수, 모바일 점수)`다.

따라서 허용 점수는 10점 단위이며, `통과/실패` 증거 없이 숫자만 제출한 결과는 무효다. 정밀해 보이는 임의의 73점보다 반복 가능한 70/80점 판정이 낫다.

#### A. 최초 viewport의 관측 상태 — 5개

스크롤·클릭·탭·캐러셀 이동 전에 판정한다.

| ID | 5점 통과 앵커 | 0점 실패 앵커 |
|---|---|---|
| V1 서비스 결과 | “사용 후 무엇을 얻는지”를 나타내는 문구가 viewport 안에 완전한 문장으로 보임 | 없거나, 잘렸거나, 스크롤해야 보임 |
| V2 대상/상황 | 누구 또는 어떤 상황을 위한 서비스인지 식별 가능한 문구가 보임 | 대상·상황 문구가 없거나 화면 밖임 |
| V3 산출물/방식 | 실제 제공물 또는 작동 방식 중 최소 하나가 구체 명사로 보임 | 추상 효익만 있고 무엇이 제공되는지 식별 불가 |
| V4 주 행동 | 의미가 명시된 주 CTA 하나가 완전히 보이고 활성 상태임 | CTA가 없거나 잘렸거나 비활성, 또는 동급 주 CTA가 2개 이상이라 단일 주 행동을 특정할 수 없음 |
| V5 화면 무결성 | 핵심 문구와 주 CTA에 겹침·가림·수평 스크롤·0픽셀/화면 밖 배치가 없음 | 네 현상 중 하나라도 핵심 문구 또는 주 CTA에 발생 |

V1~V3의 “식별 가능”을 평가자 감으로 판정하지 않도록, 측정 전에 다음 **정답 코드북**을 동결한다: 허용되는 `대상/상황`, `얻는 결과`, `산출물/방식`, `오답·과장 표현`의 문구 목록. 홈페이지 배포 뒤에 정답 목록을 고치면 해당 측정은 무효다.

#### B. 제한시간 이해·진입 행동 — 5개

각 환경에서 화면을 처음 보는 대상 사용자 표본에게 첫 viewport를 **5초간** 보여 준 뒤 화면을 가리고 U1~U3을 묻는다. 이후 새 실행에서 U4~U5를 관찰한다. [추정] 0차의 현실적 최소 표본은 환경별 12명이며, 이는 통계적 대표성을 증명하는 수가 아니라 프로토콜을 실행하기 위한 운영 기준이다. 후속 측정도 동일 모집 조건·인원을 유지한다.

| ID | 5점 통과 앵커 | 0점 실패 앵커 |
|---|---|---|
| U1 결과 회상 | 표본의 75% 이상이 “무엇을 얻는지”를 동결 코드북의 허용 코드로 답함 | 75% 미만 또는 과장·오답 코드 응답 |
| U2 대상/상황 회상 | 표본의 75% 이상이 대상 또는 사용 상황을 허용 코드로 답함 | 75% 미만 |
| U3 산출물/방식 회상 | 표본의 75% 이상이 실제 제공물/방식 하나 이상을 허용 코드로 답함 | 75% 미만 |
| U4 다음 행동 예측 | 화면을 다시 보여 주기 전에 표본의 75% 이상이 “다음에 무엇을 눌러야 하는지”를 주 CTA와 일치하게 답함 | 75% 미만 |
| U5 첫 진입 성공 | “서비스를 시작해 보라”는 지시 후 표본의 90% 이상이 도움 없이 10초 내 주 CTA를 작동시키고 의도된 다음 지면에 도달함 | 90% 미만, 오클릭, 오류, 잘못된 도착 중 하나 발생 |

75%·90%, 5초·10초는 자연법칙이 아니라 **[추정] 운영 임계값**이다. 중요한 것은 0차 전에 고정하고 후속 측정에서 바꾸지 않는 것이다. 표본별 성공/실패 원자료를 보존하며 평균 응답시간을 임의의 추가점수로 환산하지 않는다.

### 1.4 채점자 간 동일 판정 보장 장치

1. 배포 커밋 또는 아카이브 식별자, URL, 측정 시각, 브라우저·OS·viewport·네트워크 설정을 동결한다.
2. 각 V 항목은 전체 viewport 스크린샷과 화면 녹화, 각 U 항목은 익명화한 원응답·시간 로그를 필수 증거로 붙인다.
3. 두 코더가 서로의 판정을 보지 않고 동일 증거를 이진 코딩한다. 일치하지 않는 항목은 점수를 평균내지 않고, 코드북에 따라 제3의 사전 지정 판정 절차로 하나의 0/5 결론을 낸다.
4. 정답 코드북, 모집 조건, 실패 처리, 타이머 시작·종료 규칙을 0차 전에 버전 고정한다.
5. 로드 실패·외부 장애·실험 배정 혼입은 0점이 아니라 `측정 무효`로 기록하고 같은 조건에서 재실행한다. 실제 UI 결함으로 진입이 실패한 경우에만 0점이다.
6. 평가자가 자유서술 총평을 점수에 섞는 것을 금지한다. 자유서술은 원인 진단용 별첨일 뿐이다.

### 1.5 0차 기준선 최초 확정

`①-H`에는 과거 소급점수를 만들지 않는다. 다음 순서로 **외부 0차 측정**을 실시하고 그 값만 최초 기준선으로 등록한다.

1. 지표 정의서 v1.0, 코드북, 모집 조건, 기기 조건, 무효 기준을 먼저 잠근다.
2. 측정 대상 배포본을 동결하고 식별자·전체 화면 캡처를 남긴다.
3. 내부 사전 QA는 실행 오류 확인에만 쓰며 `①-H` 점수로 발표하거나 기준선에 합치지 않는다.
4. 외부 실행자가 PC·모바일을 표준 절차로 측정하고 원증거를 제출한다.
5. 이중 코딩·불일치 판정 후 `PC`, `모바일`, `min`, 실패 항목, 무효 실행 수를 함께 공표한다.
6. 이 결과를 `①-H 0차 기준선(측정일·프로토콜 버전·배포 식별자)`으로 고정한다. 다음 측정부터 동일 프로토콜에서만 증감을 말한다.

현재 유효한 ①~⑤ 외부 기준선은 아래 두 회차뿐이며, `①-H` 0차와 서로 대체하거나 소급 결합하지 않는다.

| 축 | 1차 2026-07-25 | 2차 2026-07-31 |
|---|---:|---:|
| ① 첫인상 직관성 | 62 | 73 |
| ② 자기인식·공감 | 75 | 79 |
| ③ 바로 실행가능성 | 78 | 83 |
| ④ 자산화·축적 | 85 | 88 |
| ⑤ 전문성·신뢰감 | 58 | 67 |
| 가중 평균(①~⑤ 균등 20%) | 71.6 | 78.0 |

- 1차 리서치 id: `c7f9bc84-d7e6-40c6-a1f5-f10904730509`
- 2차 리서치 id: `42e259dc-db0a-4b4d-9b5d-e024827e2f5d`
- ⑥축 58.82, ⑦축 81.00은 내부 지표이며 위 외부 기준선 표와 성격이 다르다.

### 1.6 ①축과의 관계

`①-H` 상승이 ①축 상승을 보장한다고 주장할 수 없다. 두 지표는 문구의 의미 일부를 공유할 수 있지만 입력과 측정 방식이 다르다. Hero를 고쳐 `①-H`가 상승해도, ①축에 제공되는 텍스트 전문이 같으면 ①은 그대로일 수 있다. 반대로 텍스트 전문을 개선하면 ①이 오르더라도 실제 홈페이지에서 핵심 문구가 접힘 아래로 밀리면 `①-H`는 오르지 않을 수 있다.

두 점수의 동반 변동은 상관 관찰일 뿐 인과 증거가 아니다. 인과를 말하려면 다른 변경을 통제한 사전 등록 실험이 별도로 필요하다. 현재 문서에서는 **인과를 주장하지 않는다.**

## 3. 위험 평가 — 8번째 관리축으로 만들지 말 것

### 3.1 가장 강한 반박

`①-H`는 기존 ⑥축의 이용편의성·시각품질과 관찰 대상이 겹친다. 새 지표를 상시 8번째 축으로 올리면 다음 실패가 예상된다.

- 어느 실패가 `①-H`이고 어느 실패가 ⑥인지 책임 경계가 흐려진다.
- 이미 외부 5축, 내부 ⑥·⑦축, 7축 가중식이 있는 상태에서 대시보드·목표·회의·개선 백로그가 하나 더 생긴다.
- 팀이 낮은 점수의 원인을 고치기보다 지표 간 이동과 가중치 재설계에 시간을 쓸 수 있다.
- 새 점수를 기존 75.42→90.56 목표식에 넣는 순간 목표의 의미와 과거 추적성이 다시 깨진다.
- Hero만 과최적화하고 실제 리포트·행동 경로·신뢰 문제를 뒤로 미룰 수 있다.

이 반박은 타당하지만, M의 구조 결함보다 강해서 `①-H` 자체를 폐기할 정도는 아니다. M이 지적한 문제는 실제다. 홈페이지 개선의 효과를 기존 ①로 주장할 수 없고, ⑥은 홈페이지 전체의 이용편의성·시각품질이라 “첫 화면에서 무엇을 얻는지 이해하고 진입하는가”를 분리 진단하기 어렵다.

### 3.2 최종 판단

**신설은 승인하되, 8번째 핵심 성과축이 아니라 한시적·비가중 진단지표로 운영해야 한다.**

- 기존 7축 가중식 `콘텐츠(①②③④ 평균)×0.60 + ⑤×0.15 + ⑥×0.15 + ⑦×0.10`은 그대로 둔다. 현재 75.42와 목표 90.56도 재계산하지 않는다.
- `①-H`는 Hero 개선 프로그램의 0차→후속 변화만 추적하고, ①이나 ⑥의 대체점수로 쓰지 않는다.
- `①-H` 실패항목이 ⑥의 핵심 경로 무결성과 겹치면 개선 티켓은 하나만 만들고 두 지표에 중복 계상하지 않는다. O6~O9·O12는 이때 점수 앵커가 아니라 보조 QA 체크리스트로만 쓴다.
- [추정] 0차와 두 번의 동일 프로토콜 후속 측정 뒤 계속 유지할지 심사한다. 의사결정을 바꾸지 못하거나 ⑥과 동일한 결론만 반복하면 지표는 종료하고 증거는 실험 기록으로 보존한다.

즉, 대표 승인 방향은 옳지만 “축을 하나 더 영구 관리한다”로 해석하면 틀리다. 필요한 것은 과거 ①을 오염시키지 않는 **측정 사이드카**이지, 7축 체계의 8축화가 아니다.
