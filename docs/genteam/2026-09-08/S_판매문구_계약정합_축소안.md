## 1. 문구 축소 원칙 5개조

1. **기본 계약의 확정 산출물만 무조건형으로 쓴다.** 단정 가능한 핵심은 1인 1회 진단, 개인별 리포트, 본인 열람, 조직 ID·Access Code, 계약서상 가격·환불·증빙이다.
2. **별도 계약되지 않은 서비스는 판매 상품처럼 열거하지 않는다.** 팀 종합 리포트, 워크숍, 연간·분기 운영, 코칭, 전담 채널은 현재 패키지·가격·일정·가능 여부를 단정하지 않는다. “별도 견적”도 실제 공급 가능성과 별도 계약 양식이 확인된 항목에만 쓴다. 그 전에는 “현재 제공 범위 아님”으로 표시한다.
3. **제품 기능과 고객의 자율 활동을 분리한다.** 본인이 자발적으로 리포트를 공유하거나 조직이 자체 대화를 여는 것은 가능하지만, 이를 회사가 팀 공유·조직 변화·성과를 제공하는 것처럼 쓰지 않는다.
4. **규모·기간·언어는 운영능력 약속으로 취급한다.** 계약 단가표에 200명·500명이 있더라도 대규모 동시 운영, 다국어 지원, 연간 운영, 전담 지원이 입증되는 것은 아니다. 승인된 10~29명 PoC만 전면에 둔다.
5. **모든 노출층을 같은 계약 문장에 묶는다.** 화면 본문뿐 아니라 title, meta/OG/Twitter description, JSON-LD, FAQ 구조화 데이터, PDF 원본, 견적 폼 placeholder, 블로그의 구매 안내까지 동일한 제공 범위와 문항 구성으로 맞춘다. 검색 비노출(`noindex`)은 허위·과대 문구의 면책이 아니다.

### 권장 핵심 가치제안

> **팀을 분석하지 않습니다. 사람을 먼저 존중합니다.**  
> 10~29명 PoC에서 각 참여자는 핵심 56문항과 조건에 따른 최대 20개 추가 입력을 진행하고, 자기 응답이 정리된 개인 리포트 1부를 본인만 열람합니다. 조직에는 참여용 코드만 제공하며 개인 결과와 팀 집계는 제공하지 않습니다.

이 문구의 전환 논리는 “기능의 양”이 아니라 **낮은 도입 위험, 명확한 범위, 개인정보 통제권**이다. 특히 HR 구매자에게 무엇을 받지 못하는지까지 먼저 밝히므로, 계약 직전 이탈·오해·분쟁을 줄이는 신뢰 자산이 된다. [추정] 실제 전환 영향은 현재 퍼널 데이터가 없어 방향만 판단 가능하며 수치 효과는 미측정이다.

## 4. Enterprise 보류 후 10~29명 PoC 판매 지면 구조

1. **Hero — 대상·범위·제약을 한 화면에**  
   H1: `우리 팀 10~29명, 개인별 자기이해 리포트로 작게 검증하세요`  
   Sub: 공통 대체 문구 정본  
   CTA: `PoC 견적 받기` / 보조 CTA `개인 리포트 샘플 보기`
2. **받는 것 / 받지 않는 것**  
   받는 것: 조직 ID 1개, 인원별 Access Code, 개인별 진단 1회, 개인별 리포트 1부, 본인 열람.  
   받지 않는 것: 팀 종합 리포트, 관리자 개인결과 열람, 워크숍, 코칭, 연간·분기 운영, 전담 채널.
3. **진행 절차**  
   견적·계약 → 입금 확인 → 영업일 1일 이내 코드 발급 → 참여자 직접 가입·동의 → 개인별 진단·리포트. 계약 근거가 없는 일정이나 회의는 넣지 않는다.
4. **개인정보 경계**  
   회사·운영자는 개인 결과를 보지 않으며 고객사에 개인 결과나 팀 집계를 제공하지 않는다는 현재 FAQ를 핵심 차별점으로 승격한다.
5. **가격**  
   `10~29명 · ₩18,000/인 · VAT 별도`만 판매 카드로 노출. 최소 10명, 최대 29명을 폼에서도 강제한다.
6. **PoC 판단 기준**  
   “효과 보장” 대신 운영 관찰 항목을 사전에 공개: 코드 발급 성공, 참여 시작/완료, 리포트 발급·열람, 지원 문의, 범위 오해. 개인 내용이나 점수는 고객사 평가 지표에서 제외한다.
7. **한계·FAQ·계약 링크**  
   자기이해·자기경영 보조 도구, 채용·인사평가 단독 근거 금지, 통계적 신뢰도·타당도 상태, 환불, 보유기간을 구매 전에 노출한다.

### 200명+ 전담 채널 처리

- `b2b.html` Enterprise 카드·가격·CTA·연간·분기·다국어·전담 채널 문구를 전부 제거한다.
- `b2b-quote.html`의 200명·500명 가격 노출과 10,000명 입력 허용을 제거하고 최대 29명으로 닫는다.
- 계약 단가표의 200명·500명 조항은 판매 지면과 충돌하므로, 법무 검토를 거쳐 **“신규 접수 보류”**를 계약에도 명시하거나 비활성 단가 부록으로 이동하는 것이 안전하다. 이는 계약 범위 확장이 아니라 접수 범위 축소다.
- 대기명단을 받을 운영 계획이 없다면 “문의 가능”, “별도 협의”도 쓰지 않는다. 향후 재개 가능성만 말하려면 `200명 이상 도입은 현재 접수하지 않습니다.`로 끝낸다.

**P1 — 같은 릴리스 전 검색·게이트**

- 소스와 실제 Hosting 산출물에서 다음 표현을 차단: `팀 종합 리포트|개인·팀 리포트|사내 워크숍|연간 라이선스|분기별 리포트|전담 운영자 채널|다국어/디아스포라|조직의 시너지와 성과`.
- `76문항`은 전면 금지하지 말고, 고객 노출 B2B 문맥에서 같은 블록 안에 `핵심 56`과 `최대 20`과 `조건`이 모두 있는지 검사한다.
- JSON-LD는 HTML 텍스트 검색에 그치지 말고 JSON 파싱 후 `Service.serviceType`, `Service.description`, `Offer.name/description`, `FAQPage.acceptedAnswer.text`를 검사한다.
- 음성 통제군: fixture에 `팀 종합 리포트` 한 건을 의도적으로 넣어 게이트가 실패하는지 확인하고, 허용 문구 `개인 리포트 본인 열람`은 통과하는지 함께 확인한다.

## 6. 최종 권고안

- 판매 단위는 당분간 **10~29명 PoC 한 종류**로 통일한다.
- “팀 상품”의 매력은 팀 분석이나 조직 성과가 아니라 **개별 참여, 본인 소유가 아닌 본인 열람, 비강제 공유, 명확한 개인정보 경계**에서 만든다.
- 화면·PDF·견적 폼·계약·개인정보·JSON-LD를 한 PR에서 수정한다. 한 층이라도 남으면 고객과 검색 수집기에 서로 다른 계약을 제시하게 된다.
- 문구 축소 뒤 전환 변화는 [추정]하지 말고 `b2b_quote_start → submit → payment_reported → active → participant_completed` 단계별로 전후 비교한다. 단, 개인 진단 내용은 측정하지 않는다.
