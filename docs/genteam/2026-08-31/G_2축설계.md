# 발주 G — ②축 자기 인식·공감 개선 데이터 설계

- 작성일: 2026-08-31
- 기준선: 외부 제3자 심층평가 2차 ②축 79점(발주 제공값)
- 목표: 설명·표기·지면 구성만 개선해 90점 재평가를 지향
- 변경 제외: 76문항 내용, 채점식, 8개 판별 상수 및 지정된 엔진·규칙 파일

## 0. 먼저 고정할 판정

79점의 **인과 원인은 현재 자료만으로 확정할 수 없다.** 평가자의 항목별 감점 로그, 실제 이용자의 문장별 적합도 응답, 비교군 리포트가 이 분석에 제공되지 않았기 때문이다. 아래의 `[증거 있음]`은 “원인으로 작동할 수 있는 제품 구조가 코드·문서에서 확인됨”을 뜻하며, 그것이 11점 격차를 실제로 얼마나 설명하는지는 미확인이다.

또한 “내 얘기 같다”는 반응만 높이는 것은 목표가 아니다. Forer(1949)는 여러 사람에게 같은 일반적 성격 서술을 주어도 개인에게 맞는 설명으로 받아들일 수 있음을 보였다. 따라서 ②축은 **공감 반응 + 사람 간 변별 + 응답 근거 추적**을 함께 통과해야 한다.

## 2. 개선 방법의 분리와 우선순위

### 2.1 추가 응답 데이터 없이 가능한 개선

| 우선 | 제안 | 데이터 근거 | 완료 기준 |
|---:|---|---|---|
| P0 | **첫 2개 지면에 `내 답 → 해석 → 확인` 3열 근거 카드 배치** | 이미 가진 direct provenance 6종과 원응답을 읽기 전용으로 재배치할 수 있다. 현재 IX장 대조표 구조를 앞쪽 핵심 주장 2~3개에 축약 재사용한다. | 핵심 정체성 주장 100%에 `source_qid`, 가공 전/후 값, 해석 규칙 ID가 연결되고, 출처 없는 주장은 “가설”로 표시됨. |

## 3. 바넘 위험 자체 점검 지표

### 3.1 원칙

단일 점수로 합치지 않는다. 가중치를 임의로 정한 “종합 바넘 점수”는 다시 조작 가능한 숫자가 된다. 다음 5개를 함께 보고하고, 세 가지 핵심 게이트 `근거·변별·민감도` 중 하나라도 실패하면 검토 대상으로 둔다.

입력은 고정 시드 `N`명의 가상 응답, 각 리포트의 표시 문장, 문장별 provenance, 그리고 1문항씩 바꾼 대응 응답쌍이다. 개인정보는 필요 없다. 한국어 토큰화는 외부 라이브러리 없이 Unicode 문자 정규화, 문장부호 제거, 공백 분할, 조사·상투어 stop-list 버전 고정으로 수행한다.

### 3.2 지표와 계산식

#### A. 문장 재사용률(Sentence Reuse Rate, SRR) — 낮을수록 좋음

\[
SRR=\frac{\sum_s f_s\,I(f_s\ge2)}{\sum_s f_s}
\]

- `f_s`: N개 리포트 전체에서 정규화 문장 `s`의 출현 횟수
- 입력: 섹션 ID, 문장 ID, 정규화 문장
- 공통 안내문은 별도 층으로 빼고, 개인 해석 문장에만 계산한다.
- 문헌 직접 지표가 아닌 **공학적 휴리스틱**이다. 현행 중복 측정의 확장판이다.

#### B. 문장 보편 도달률(Universal Reach, UR) — 낮을수록 좋음

\[
UR_s=\frac{|\{u:s\in report_u\}|}{N}
\]

`UR_s`가 높은 개인 해석 문장은 여러 사람에게 동일하게 주어진다. `UR_s`가 높고 direct provenance가 없으면 우선 검토한다. 임계값은 현재 고정 코호트의 분포를 먼저 동결한 뒤 정하며, 결과를 본 뒤 변경하지 않는다.

#### C. 응답 근거 커버리지(Response Provenance Coverage, RPC) — 높을수록 좋음

\[
RPC=\frac{\#(개인\ 해석문장\ 중\ source\_qid와\ rule\_id가\ 모두\ 있는\ 문장)}{\#(개인\ 해석문장)}
\]

- 입력: `sentence_id`, `source_qids[]`, `source_values[]`, `rule_id`, `provenance_type`
- `fingerprint`만 연결된 문장은 direct 근거로 세지 않는다.
- 현행 provenance 구조(`report-engine-v4.js:7166-7204`)를 표시층 감사 로그로 확장하면 된다.
- 이것도 내부 감사 지표이며, 내용의 옳음을 증명하지 않는다.

#### D. 1문항 반응률(Counterfactual Response Rate, CRR) — 적정 범위 필요

문항 `q`만 바꾼 동일 응답쌍 `(x,x^{(q)})`에 대해:

\[
CRR_q=\frac{\#\{k:O_k(x)\ne O_k(x^{(q)})\land q\in provenance_k\}}{\#\{k:q\in provenance_k\}}
\]

- `O_k`: 출력 슬롯 k의 정규화 문자열
- 필요한 입력: 기준 답, 한 문항만 바꾼 답, 슬롯별 출력, 슬롯 provenance
- 0이면 그 문항을 근거로 표기하면서 출력이 반응하지 않는 의심, 모든 슬롯이 바뀌면 무관한 영역까지 흔드는 의심이다.
- 기존 “한 문항 변화” 검사를 **어떤 슬롯이 왜 변해야 하는지**까지 좁힌 공학적 지표다.

#### E. 희소 토큰 정보량(Specific Token Information, STI) — 높을수록 특이성이 큼

\[
idf(t)=\log\frac{N+1}{df(t)+1},\quad STI_s=\frac{1}{|T_s|}\sum_{t\in T_s}idf(t)
\]

- `df(t)`: 토큰 t가 등장한 리포트 수
- 입력: N개 리포트의 개인 해석 문장 토큰
- 이름·날짜·고유코드는 제거한다. 이 값들이 특이성을 인위적으로 올리기 때문이다.
- 높은 STI는 희소 표현일 뿐 의미 적합성을 보장하지 않는다. **공학적 휴리스틱**으로만 사용한다.

### 3.3 자동 플래그

문장 `s`를 다음 중 하나면 검토 대상으로 둔다.

1. `provenance_type=template-fallback`인데 개인 특성으로 표시됨
2. `RPC` 분자 조건을 충족하지 못하면서 `UR_s`가 고정 코호트 중앙값보다 높음
3. source_qid가 있는데 해당 문항 반사실 변경에서 관련 슬롯이 변하지 않음
4. 이름·고유코드 제거 후 동일 문장이 다수 리포트에 반복됨
5. “상황에 따라”, “때로는”, “가능성이”, “균형”, “내면” 같은 사전 등록 모호어가 있으면서 구체 행동·환경·응답 근거가 없음

5번 사전은 언어 규칙에 불과해 단독 실패로 쓰지 않는다. Forer 효과의 핵심은 일반적·모호한 서술을 개인에게 맞는 것으로 받아들이는 현상이라는 문헌에 근거하지만, 특정 한국어 단어가 곧 바넘 문장이라는 검증 자료는 없다.

## 4. 기존 데이터로 개인 특이성을 지면에 보여주는 3안

### 안 A — “내 답이 이 문장이 된 경로” 카드

`가장 소중한 가치(Q13) → 해석 규칙 → 핵심 문장`처럼 한 행에 배치한다. Q39·Q41·Q47·Q49·Q73도 같은 형식으로 최대 3행만 첫 2개 지면에 싣고, 전체 대조는 현행 IX장에 둔다. 원답을 그대로 노출하면 민감하거나 길 수 있으므로 현행 `evdsafe()`와 4칩 제한을 유지한다. **장점:** 공감과 근거 추적을 동시에 강화. **위험:** 답을 다시 말한 것뿐인데 해석처럼 보일 수 있어 가운데 `규칙` 열이 필수다.

### 안 B — “네 축의 모양” 카드

보유 중인 4개 `axisPct`를 동일 축척의 작은 막대/점으로 전부 보여주고, “가장 높은 축”, “가장 가까운 두 축”, “현재 보완 여지”를 수치 차이와 함께 설명한다. 모집단 비교가 아니므로 백분위·등급 대신 **이 응답 안에서의 상대 모양**이라고 표시한다. **장점:** 같은 1위여도 나머지 세 축과 격차가 달라 개인 차이가 보인다. **위험:** 숫자가 측정 성숙도보다 정밀해 보일 수 있어 소수점 과표현을 피하고 한계 문구를 붙인다.

### 안 C — “내가 움직이는 조건” 4칸

이미 가진 `가치(Q13) / 몰입 활동·주제(Q39·Q41) / 자리·리듬(Q47·Q49) / 완료 단서(Q73)`를 `선택 기준 / 하는 일 / 잘 되는 환경 / 끝났다고 느끼는 장면`으로 재배열한다. 아래에 `직접 응답`, `규칙 해석` 배지를 구분한다. **장점:** 추상 성향보다 생활 장면이라 확인·반박이 쉽다. **위험:** 민감한 원문을 그대로 재노출하지 말고 현재 중립 치환과 축약을 유지한다.

우선순위는 A→C→B다. A와 C는 이미 존재하는 provenance·source 구조를 이용해 의미 근거를 먼저 보이고, B는 숫자의 과잉 권위를 통제한 뒤 보조로 쓴다.

## 5. ⑤축을 깎을 수 있는 지점

1. **문자열 고유율을 내용 적합성으로 바꾸어 말하는 경우.** 서로 다른 문장은 쉽게 만들 수 있지만, 그 문장이 해당 이용자에게 더 맞는지는 별도 문제다.
2. **fingerprint를 의미 근거로 쓰는 경우.** 고유코드는 응답 조합 식별·결정적 재계산의 도구이지, 해석의 내용 근거가 아니다. 과거 `time_horizon` 결함이 이를 보여준다.
3. **4축 값을 규준 점수처럼 보이게 하는 경우.** 현재 모집단 규준과 구성·예측 관련 근거가 없으므로 백분위·우열·정밀한 사람 간 비교처럼 제시하면 안 된다.
4. **직접 답을 되말하면서 분석으로 포장하는 경우.** `Q13=성장`을 “성장을 중시한다”로 바꾸는 것은 추적 가능하지만 정보 증분이 작다. `내 답`, `규칙 해석`, `확인 필요`를 분리해야 한다.
5. **공감만 최적화하는 경우.** 긍정적·모호한 문구는 쉽게 수용될 수 있다. Forer 계열 문헌상 높은 자기적합도 반응만으로 개인 변별을 결론 내릴 수 없다.
6. **근거를 너무 많이 노출하는 경우.** 민감 응답 재노출, 인지 과부하, 선택적 근거 제시 문제가 생긴다. 첫 지면은 2~3개, 전체 감사표는 뒤쪽으로 분리한다.
7. **사용자 피드백을 사후 문구 선택에만 쓰는 경우.** 잘 맞았다는 응답이 많은 문구만 남기면 호의적 일반문이 생존할 수 있다. 자기 리포트 식별력과 `다름` 응답을 함께 최적화해야 한다.

현 상태 표기 경계는 유지한다: **계산 재현성은 증명됨 / 재검사 관련 근거는 미증명 / 내용타당도는 진행 중 / 구성·예측 관련 근거는 미증명.** 위 설계는 출력의 근거 추적성과 변별 가능성을 점검할 뿐, 이 경계를 확장하지 않는다.

## 6. 실행 순서와 판정 게이트

1. 고정 synthetic 코호트와 현재 출력의 SRR·UR·RPC·CRR·STI 기준선을 저장한다.
2. 코드 변경 없이 화면 설계 시안 A/C/B를 기존 report JSON으로 렌더한다.
3. 공통 안내와 개인 해석을 분리하고, 핵심 개인 주장 RPC 누락을 0으로 만든다.
4. 같은 고정 코호트에서 지표가 악화되지 않았는지 확인한다.
5. 이후에만 D0 자기 리포트 식별 실험과 문장별 적합도 실험을 시행한다.
6. 같은 외부 루브릭으로 재평가한다. 90점은 이 재평가 전까지 달성으로 기록하지 않는다.
