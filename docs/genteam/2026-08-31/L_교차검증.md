## 2. 서로 모순되거나 함께 채택할 수 없는 주장

### 충돌 1 — 첫 화면의 1순위: 문안인가, 작동하는 축적 표면인가

- C 184~193행: A안 문안을 1차 후보로 권고하며 `76문항·약 15분`, `PDF 리포트+21일 실행`, `삶의 기준+다음 행동`, `기록 축적` 순서를 제안한다.
- A 345~366행: 문구 추가가 아니라 `총량+기간+일별 흔적+원기록`이 보이는 **작동하는 축적 표면**이 필요하다고 판정한다.
- **판정**: A의 근거가 더 강하다. A는 GitHub·Apple·Spotify·Goodreads·Robinhood 등 공식 제품 자료에서 시각 문법을 추출했고, C는 문안 후보를 제시했으나 사용자 실험 전임을 스스로 인정했다(C 60, 193행). 다만 둘은 완전한 양자택일이 아니다.
- **통합안**: C의 문안은 A의 축적 프리뷰 위에 얹는 보조층이다. 문안만 먼저 배포해 ①축 개선 완료로 취급하는 안은 기각한다. 먼저 ‘기록·결과물’ 집계 정의와 샘플/실데이터 표시 규칙을 확정하고, 정직한 프리뷰가 가능한 경우에만 C 문안을 결합한다.

### 충돌 2 — `PDF 2권`과 공통 기준선의 `리포트 1권`

- 발주 L의 유효 기준선은 `76문항 → 리포트 1권 → 21일 체크인`이다.
- C 70·81·88행은 `PDF 2권`을 핵심 문안으로 제안하면서 실제 구매 흐름과의 일치 여부를 출시 직전 확인해야 한다고 적었다.
- **판정**: 현 시점에는 공통 기준선이 더 강하다. C의 `PDF 2권`은 스스로 미확인 조건을 달았으므로 대외 문안으로 채택할 수 없다.
- **조치**: 계약·실제 다운로드 산출물에서 2개 PDF가 항상 제공됨을 전수 확인하기 전까지 `PDF 리포트와 21일 실행 프로그램`으로 표현한다. “출시 직전 확인”이 아니라 **문안 승인 전 확인**이 순서다.

### 충돌 3 — ⑥축을 7축 총점에 넣는가, 별도 기준선으로 두는가

- 공통 맥락은 ⑥·⑦축을 “내부 추가 2축”으로 제시한다.
- F 140~155행은 신규 ⑥축을 기존 5축 평균에 합산하지 않고 별도 기준선으로 기록하라고 한다.
- **판정**: F가 더 강하다. 2차 평가에는 ⑥축이 없었으므로 합산하면 1·2·3차 총점의 측정 대상이 달라져 시계열 비교가 깨진다. 성격이 다른 신규 척도를 과거 5축 평균에 소급 합산할 근거도 없다.
- **조치**: 3차 결과는 `기존 5축 평균`과 `신규 ⑥축`을 분리 보고한다. 내부 7축 대시보드를 별도로 유지하더라도 외부 2차 78.0과 직접 비교하지 않는다. ⑦축도 향후 외부 평가에 넣으려면 별도 기준선이 필요하다.

### 충돌 4 — F의 “독립 채점”과 평가 입력에 자체 실측을 제공하는 구조

- F 115~128행은 자체 실측을 참고 증거로 제공하되 자동 점수 환산을 금지한다.
- F 140~148행은 평가자가 독립적으로 점수를 산정해야 한다고 한다.
- **판정**: 문장상 모순은 아니지만 **앵커링 위험**이 남는다. 평가 전에 의뢰자 수치(AA 100%, AAA 64.8~67.3%, CLS 0.0625)를 보여 주면 독립 관찰이 그 수치에 끌릴 수 있다.
- **조치**: 2단계 블라인드 절차로 바꾼다. 평가자가 먼저 사이트를 독립 관찰·가채점하고 결과를 고정한 뒤, 자체 실측 원자료를 열어 교차검증·수정 사유를 기록한다. F의 현재 “같이 제공” 방식은 조건부 인수다.

### 충돌 5 — F의 0~100 채점 요구와 항목별 점수 앵커 부재

- F 63~86행은 6개 항목을 각각 0~100으로 채점해 가중합하도록 한다.
- 그러나 문서에는 0·20·40·60·80·100 또는 구간별 관찰 기준이 없다.
- **판정**: **기각**. 관찰 지시만으로 0~100 숫자를 만들면 평가자 재량이 지나치게 크고, 외부 점수의 재현 가능한 의미가 없다. `낮은 뷰포트 점수 채택`은 승인된 규칙이지만, 그 입력 점수 자체가 무앵커다.
- **조치**: 항목마다 등급 앵커와 필수 실패 조건을 먼저 확정하거나, 정량점수 대신 증거표와 중대도 판정을 요청한다. 이 보완 전에는 ⑥축 숫자를 확정하지 않는다.

### 충돌 6 — A의 데모 수치와 ⑤축·법정 표현 리스크

- A 351~353행은 `지난 21일 · 살아낸 기록 14개 · 남긴 결과물 3개`, `발견 76/76 · 살아냄 9/21일` 같은 프리뷰를 제안한다.
- A는 `예시` 표기를 요구하지만, 실제 사용자가 이를 자기 데이터·평균 성과·보장 결과로 오인할 가능성은 남는다.
- **판정**: A의 시각 제안은 방향성이 강하지만 숫자 예시는 I 법정·표현 감사 전 배포 금지다. 특히 “남긴 결과물”의 집계 규칙이 아직 미확정임을 A 359·366행이 인정한다.
- **조치**: 실데이터가 아니면 `가상 예시 화면`을 같은 시각 위계로 표시하고, 수치가 무엇을 세는지 정의·드릴다운을 제공한다. 집계 규칙 없는 수치는 제거한다.

### 충돌 7 — E의 장기 기능 확장과 현재 보안·신뢰 우선순위

- E 5·10·371~377행은 Phase 0만 채택하고 구현을 보류한다.
- 동시에 OAuth, A2A Gateway, Agent Card, 외부 파트너 연동까지 상세 로드맵을 제시한다.
- **판정**: 결론 자체는 타당하지만, 현재 ⑤축 67·⑥축 58.82·⑦축 81과 B2B 실패 위험을 고려하면 Phase 1 이후는 우선순위 밖이다. E가 스스로 보류를 명시했으므로 당장 실행 목록에 넣으면 산출물 취지를 거스른다.
- **조치**: Phase 0의 경계·정직 선언만 설계 표준으로 채택한다. 외부 A2A 구현은 K 보안과 J B2B 요구가 도착한 뒤 재심한다.

## 3. 중복 제안 통합

### 통합 묶음 U1 — 첫 화면 정체성·자산화 전달

- **중복 출처**: A + C
- A는 시각 증거(총량·기간·격자·원기록), C는 정보 문안(문항·산출물·기간·첫 행동)을 제안한다.
- **단일 작업으로 통합**: `Hero Evidence Package`
  1. 집계 규칙과 데이터 출처 확정
  2. 가상 예시/실데이터 구분
  3. 축적 프리뷰 1개
  4. C 문안 1안만 결합

### 통합 묶음 U3 — 접근성·시각 회귀 검증

- **중복 출처**: D(미도착) + F
- F는 외부 평가 절차를, D는 개선 설계를 담당한다. 둘이 각각 점수 규칙을 만들면 중복이다.
- **통합 원칙**: D는 CSS/HTML 변경과 회귀 테스트만, F는 독립 평가 지시만 담당한다. 자체 게이트 결과를 외부 점수로 자동 변환하지 않는다.

### 통합 묶음 U4 — 보안·A2A 경계

- **중복 출처**: E + K(미도착) + J(미도착)
- E의 OAuth·scope·quota·감사·취소 설계와 K의 보안 개선이 중복될 가능성이 높다.
- **통합 원칙**: K가 현재 보안 기준선을 확정하기 전 E Phase 2 설계를 구현하지 않는다. J가 실제 B2B 구매 요구를 제시한 뒤 필요한 파트너 기능만 남긴다.

## 4. 축 간 상충 관계

### 4-1. ①축 문안 개선 ↔ ⑤축 전문성·신뢰감

- 구체성을 높이려 `76문항·15분·PDF 2권·21일`을 압축 노출하면 ①축에는 유리할 수 있다.
- 그러나 미확인 수량, “사명·강점·가치를 찾는다” 같은 과도한 인과, 샘플 수치를 실제 성과처럼 보이는 방식은 ⑤축을 훼손한다.
- **게이트**: 모든 숫자·산출물·인과 문구는 계약·실데이터·현재 표기 경계와 대조한다. C의 `PDF 2권`은 검증 전 금지. A의 샘플 수치는 `가상 예시` 표기와 집계 정의 없이는 금지.

### 4-2. ②축 공감 강화 ↔ 용어 분리

- G 미도착으로 구체 제안은 판정할 수 없다.
- 일반 위험만 확정할 수 있다: 공감 문장을 강하게 만들수록 “당신을 정확히 안다”, “응답에서 읽어냈다” 같은 근거 초과 표현으로 흐를 수 있다.
- **게이트**: 현 상태 표기(계산 재현성 증명됨, 재검사 자료 없음, 내용타당도 진행 중, 구성·예측타당도 미증명)를 문장별로 적용한다. 감정 공감은 가능하지만 측정 성능 주장으로 변환하지 않는다.

### 4-3. AAA 44px ↔ 시각 일관성·정보 밀도

- D 미도착이므로 요소별 판정은 미측정이다.
- 확정 사실: AA 24px는 측정 범위에서 전량 통과했고 AAA 44px는 약 65~67%다. AAA 미달을 법정 실패처럼 표현하면 안 된다.
- **게이트**: 44px는 무조건 요소 박스를 키우는 방식이 아니라 CSS 픽셀 목표, 간격 예외, 인라인 예외, 인접 오조작 위험을 함께 검토한다. 변경 후 390/1440에서 줄바꿈·가로넘침·헤더 밀도·탭 순서를 회귀 측정한다. WCAG 2.2 SC 2.5.5는 AAA, SC 2.5.8은 AA라는 등급을 분리한다: https://www.w3.org/TR/WCAG22/#target-size-enhanced / https://www.w3.org/TR/WCAG22/#target-size-minimum

### 4-4. 보안 강화 ↔ 기능 파손

- K 미도착으로 구체 변경은 미측정이다.
- E는 외부 A2A에서 OAuth resource/audience/scope, quota, 취소, allowlist를 요구한다. 이를 현재 기능에 일괄 적용하면 로그인·결제·체크인·관리자 흐름을 막을 수 있다.
- **게이트**: 보안 변경마다 허용 흐름 양성시험과 차단 흐름 음성시험을 쌍으로 둔다. CSP·권한·rate limit은 보고→관찰→강제 순서, exact endpoint allowlist, rollback을 요구한다. 외부 A2A는 Phase 0 외 구현 보류.

### 4-5. 자산화 시각화 ↔ 개인정보·B2B 재식별

- A의 원기록 드릴다운은 ④축·①축에 유리하지만, E 248~251·260행이 지적한 개인정보·집단 재식별 위험을 키운다.
- **게이트**: 공개 첫 화면은 가상 데이터만, 로그인 후 실제 데이터는 본인 범위만, B2B 집계는 최소 집단 크기·억제·역추론 방지 전에는 구현하지 않는다.

### 4-6. ⑥축 확대 ↔ 기존 5축 비교 가능성

- 홈페이지를 3차 평가에 넣는 것은 필요하지만 기존 5축의 평가 범위를 홈페이지까지 넓히면 2차와 비교가 깨진다.
- **게이트**: F처럼 기존 5축은 기존 텍스트 범위, ⑥축은 실제 사이트 범위로 분리한다. 한 총점으로 합치지 않는다.

## 5. 근거가 약해 기각하거나 보류할 제안

1. **C의 A안 즉시 채택 — 보류**: 5초 테스트·실제 렌더·행동 데이터 전에는 후보일 뿐이다. 특히 숫자 과밀과 `PDF 2권` 불일치가 남는다.
2. **A의 링·격자·누적차트 동시 구현 — 기각**: 집계 정의가 선행되지 않았고 첫 화면 정보 과부하를 만들 수 있다. 한 컴포넌트씩 실험한다.
3. **A의 3초 O/X를 사용자 사실로 사용 — 기각**: A 11행 스스로 화면 감사 판정이라고 한정한다.
4. **F의 무앵커 0~100 채점 — 기각**: 평가자 간 점수 의미가 고정되지 않는다.
5. **F의 자체 실측 선공개 — 수정 필요**: 독립 관찰 후 공개하는 2단계 블라인드로 바꾼다.
6. **E Phase 1~3 즉시 실행 — 보류**: 현재 제품 품질 격차와 직접 연결된 효과가 미측정이고 보안·비용·법적 선행조건이 없다. Phase 0만 채택한다.

## 7. 최종 판정

- 현재 채택 가능한 것은 **A의 근거 조사, C의 후보 문안, E의 Phase 0 원칙, F의 축 분리·낮은 뷰포트 채택·Lab/field 구분**이다.
- 현재 그대로 실행하면 안 되는 것은 **C의 미확인 `PDF 2권`, A의 집계 규칙 없는 샘플 수치, F의 무앵커 0~100 채점과 자체 실측 선공개, E의 Phase 1~3 구현**이다.
- 가장 큰 중복은 A와 C의 첫 화면 개선이다. 별도 실행하지 말고 `집계 정의 → 단일 축적 프리뷰 → 문안 결합 → 사용자·렌더 검증` 한 흐름으로 합친다.
- B·D·G·H·I·J·K는 미도착이다. 이들의 구체 제안과 A·C·E·F 사이 충돌은 현재 판정하지 않았다.
