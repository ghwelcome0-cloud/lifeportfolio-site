# ⑤축 전문성·신뢰감 67 → 90 개선 설계

- 작성일: 2026-08-31
- 기준선: 2026-07-31 외부 제3자 심층평가 ⑤축 67점
- 범위: 공개·설명·문서화·독립 검토 층. 문항·매핑·채점식·성역 파일 변경 제안 없음
- 판정 지위: 연구 설계안. 점수 상승 보장 또는 자체 재채점 결과가 아님

## 0. 결론

현재 자기 진단의 핵심은 맞다. **동일 release·동일 엔진·동일 입력에서 같은 계산 결과가 나온다는 소프트웨어 근거는 있으나, 같은 사람을 다시 측정했을 때의 안정성, 네 축 구조, 외부 준거와 미래 결과에 대한 근거는 없다.** 내용 관련성 검토는 준비·진행 단계이지 완료 근거가 아니다.

그러나 67점의 원인을 “측정자료 부족” 하나로만 설명하면 불완전하다. 외부 원문의 ⑤축 채점은 평가 가능한 8항목 중 다음 상태를 기록했다.

| 항목 | 가중치 | 2차 점수 | 외부 원문의 직접 감점 사유 |
|---|---:|---:|---|
| 산출 재현성 | 15% | 4/5 | 지면 고지는 있으나 최상 앵커와의 차이 존재 |
| 응답 반응성 | 10% | 3/5 | 38/38·200/200은 자체 실측이며 외부 감사 없음 |
| 내용 관련성 | 10% | 3/5 | 전체 56문항 매핑 미공개, 사람 SME 평가 미실시 |
| 근거 공개 | 15% | 4/5 | 일부 응답–결과 매핑만 공개 |
| 문서화 품질 | 10% | 3/5 | 제작 문서와 기술 자료의 외부 공개 부족 |
| 품질 통제 | 10% | 3/5 | 자체 게이트는 있으나 외부 감사 없음 |
| 윤리적 안전장치 | 10% | 4/5 | 한계·비낙인 장치는 있으나 최상 앵커 미충족 |
| 고지의 정직성 | 10% | 4/5 | 한계 일부 공개, 최상 앵커와의 차이 존재 |
| 규준·신뢰도·구성타당도 | 10% | N/A | 규준·α/ω·재검사·요인·예측 자료 없음 |

외부 보고서는 평가 가능 8항목을 71.1점으로 계산한 뒤 N/A의 구조적 한계를 반영해 67점으로 제시했다. 이 마지막 4.1점 조정은 정형화된 산식이라기보다 평가자의 종합 판단이다. 따라서 **8개 항목을 문서로 개선해도 90점이 자동 산출되지 않는다.** 특히 2점·4점 앵커가 원문에 없어서, “3점 요건은 넘고 5점 요건 중 일부만 충족했으니 4점”이라는 사후 보간은 금지해야 한다.

### 도달 가능성 판정

- **현 보유 자료의 정리·공개만으로:** ⑤축의 신뢰 인상과 항목 1·4·7·8, 일부 5의 근거를 강화할 수 있다. 90점 보장은 불가능하다.
- **현 보유 자료를 독립 재현하고 공개하는 추가 작업까지 포함하면:** 항목 2·5·6의 4점 후보 근거를 만들 수 있다. 단, 먼저 관찰 가능한 4점 앵커를 공개하고 제작팀과 분리된 채점자가 판정해야 한다.
- **실제 사람 자료 없이 해결되지 않는 것:** 재검사 신뢰도, 내적 구조, 규준, 준거·예측 관련성. 항목 9의 N/A와 평가자의 구조적 감점은 남는다.
- **따라서 90점은 가능성 있는 목표이지 현재 근거에서 도출되는 값이 아니다.** 3차 평가자가 90 미만을 줄 합리적 근거가 남아 있다.

## 1. 67점 원인 가설 검증

분류 기준:

- **증거 있음:** 외부 원문 또는 현재 공개 지면·저장소에서 직접 확인됨
- **추정:** 개연성은 있으나 평가자 원인 진술·운영 증빙이 부족함
- **반박됨:** 현재 근거와 모순되거나 원인의 범위를 과장함

| # | 원인 가설 | 분류 | 판정 근거 |
|---:|---|---|---|
| 1 | 재검사 신뢰도 자료가 없다 | 증거 있음 | 외부 원문 항목 9가 N/A로 기록했고, 내부 프로토콜도 `미착수 데이터`로 명시한다. |
| 2 | 구성·예측타당도 자료가 없다 | 증거 있음 | 외부 원문 항목 9에 요인분석·예측 자료 전무가 기록돼 있다. 현재 저장소에도 완료 연구 결과가 없다. |
| 3 | 전체 문항–축 매핑을 평가 당시 공개하지 않았다 | 증거 있음 | 외부 원문 항목 3은 6개 사례만 공개됐다고 기록한다. 현재 라이브 one-page도 11영역 요약표 중심이며 문항별 56행은 아니다. |
| 4 | 응답 반응성 근거가 내부 소프트웨어 표본에 머물렀다 | 증거 있음 | 외부 원문 항목 2가 38/38·200/200을 자체 실측으로 한정한다. 모집단 개인화나 실제 사람 결과를 뜻하지 않는다. |
| 5 | 기술 매뉴얼·제작 규칙·품질 증빙의 공개 URL이 부족하다 | 증거 있음 | 외부 원문 항목 5가 외부 비공개를 직접 감점했다. 공개 블로그는 설명 자료지만 버전·결측·채점·오류·한계를 한 문서에서 추적하는 기술 매뉴얼은 확인되지 않았다. |
| 6 | 품질 게이트가 존재해도 독립 실행·원로그·결함 주입 증거가 부족하다 | 증거 있음 | 외부 원문 항목 6이 외부 감사 부재를 감점했다. 기존 설계 검토에서도 산출물 품질 게이트 범위가 현행 증거로 완결되지 않았다. |
| 7 | 고지 자체가 여러 지면에서 불일치한다 | 증거 있음 | 라이브 one-page는 `56+14+메타2=76`으로 표기하지만 현재 정본은 핵심 56+조건부 기타 20이며 메타 2는 76에서 제외된다. 개발자 노트는 내용타당도 “매핑 일관성 확보”라고 쓰지만 독립 내용 검토는 진행 단계다. |
| 8 | 계산 재현성 문구가 측정 안정성으로 오독될 위험이 있다 | 증거 있음 | `report.html`에는 “100%”, “같은 응답은 언제나 같은 결과”가 남아 있다. 동일 입력의 결정론을 밝히더라도 숫자·문맥이 사람에 대한 안정성처럼 읽힐 수 있다. |
| 9 | 외부 기관 검증 이력이 없어서 B2B 신뢰가 약하다 | 증거 있음 | 공개채점표 규격서 A0가 2026-08 기준 외부 기관 검증 없음으로 고정돼 있다. 다만 이것은 정보보호·측정 품질·학술 검토를 하나로 합산할 수 있는 점수가 아니다. |
| 10 | 한계 공개는 고객 불안을 키우므로 숨겨야 점수가 오른다 | 반박됨 | 외부 원문은 ‘고지의 정직성’을 독립 항목으로 4/5 평가하고, 최상 앵커도 한계의 지면 공개를 요구한다. AERA·ITC도 지원되지 않는 해석과 기술적 한계 공개를 요구한다. |
| 11 | 문서만 잘 만들면 측정자료 부재가 해소된다 | 반박됨 | EFPA 2025는 문서화, 규준, 신뢰도/정밀도, 타당도를 별도 영역으로 평가한다. 문서 공개는 증거의 부재를 투명하게 만들 뿐 없는 자료를 생성하지 않는다. |
| 12 | 67점의 주원인은 낮은 브랜드 인지도다 | 추정 | 신뢰 인상에는 영향을 줄 수 있지만 외부 ⑤축 채점표의 직접 항목은 재현성·내용·설명·문서·통제·윤리·고지·측정근거다. 인지도는 직접 감점 사유로 확인되지 않았다. |
| 13 | 가격이 낮아 전문성이 낮게 평가됐다 | 추정 | ⑤축 외부 채점표에 가격 항목이 없다. 가격–신뢰 인과 자료도 없다. |

### 자기 진단에 대한 수정

1. `내용타당도=진행 중`은 대외적으로 완료처럼 읽힐 수 있다. 더 정확한 상태는 **“문항–축 매핑 문서는 존재하고, 독립 사람 SME 평정 결과는 없음”**이다.
2. `계산 재현성=증명됨`은 release·환경·제외 필드·시험 표본과 함께 써야 한다. 제품 전체나 사람 결과에 대한 무조건적 표현으로 확장하면 안 된다.
3. `구성·예측타당도=미증명`은 맞다. 여기에 **규준과 내적 일관성 자료도 미확인/미완료**라는 항목을 분리해야 한다.
4. 외부 평가 원문은 항목 9를 N/A로 제외한 뒤 4.1점을 별도 감점했다. N/A 처리와 감점을 동시에 한 산식은 재사용 규칙이 충분히 명시되지 않았다. 3차 평가 전 평가자에게 동일 산식을 그대로 쓸지 확인해야 비교가 성립한다.

## 2. 현 보유 자료만으로 신뢰를 올리는 우선순위

### 점수 기여 표기의 원칙

아래 `예상 점수 기여`는 3차 점수 예측이 아니다. 외부 원문 가중치상 해당 항목이 1단계 움직일 때의 **산술 민감도**다.

- 15% 항목 1점 상승: 약 **+3.33점**
- 10% 항목 1점 상승: 약 **+2.22점**
- 실제 4점 앵커가 비어 있으므로 4점 인정 여부는 외부 평가자가 결정한다.
- 같은 산출물이 여러 항목에 관련돼도 중복 가산을 보장하지 않는다.

### P0. 공개 사실의 모순부터 제거

**실행**

1. 공개 문항 수를 `핵심 56 + 조건부 기타입력 최대 20 = 최대 76; 메타 2는 별도`로 통일한다.
2. “내용타당도 확보” 대신 `문항–축 매핑 문서 존재 / 독립 사람 SME 평정 결과 없음`으로 정정한다.
3. 계산 고지는 `동일 release·동일 엔진·동일 입력 → 동일 계산 결과`로 한정하고 바로 옆에 `사람의 시간 안정성이나 타당도를 뜻하지 않음`을 둔다.
4. `다음 분기`, `수십만 명 누적 후`처럼 근거 없는 일정·표본 약속은 삭제하거나 내부 계획으로 분리한다.

- **근거 문헌/사례:** AERA Standards 1.1·1.3(의도한 해석과 미평가 해석 공개), 2.19(신뢰도 방법·표본·조건 명시), ITC 2.7.2·2.7.7·2.8.3–2.8.5(척도 한계와 수신자 수준에 맞는 보고), 외부 원문 항목 8.
- **예상 점수 기여:** 항목 8의 4→5 후보, 최대 산술 +2.22. 모순이 남으면 오히려 감점 가능.
- **구현 난이도:** 낮음. 공개 문안과 문서만 수정.
- **위험:** 한계 문구가 제품 가치를 약하게 보이게 할 수 있다. 해결은 한계를 숨기는 것이 아니라 `확인된 기능 / 미측정 / 사용 금지` 3단 표로 짧고 명확하게 제시하는 것이다.

### P1. 공개 기술 매뉴얼 1개와 증거 인덱스 1개를 정본화

**필수 목차**

1. 제품 목적과 비목적, 의도 대상, 허용·금지 사용
2. 핵심 56·조건부 20·메타 2의 구분
3. 4축 정의와 포함/제외 경계
4. 응답 형식, 결측·조건부 입력 처리
5. 문항→축→점수→문장→PDF/21일 프로그램의 추적 구조
6. 점수·가중치·프로파일 해석 한계
7. release ID, commit, 문항/매핑/규칙/엔진 digest
8. 계산 재현 절차와 비교 제외 필드
9. 현재 근거표: 계산 재현성/재검사/내용/구성/예측/규준/공정성
10. 알려진 결함, 변경 이력, 문의·오류 신고

각 주장 옆에 공개 URL, 파일 버전, 확인일, 담당자, 상태(`확인됨/부분/미측정/비적용`)를 둔다.

- **근거 문헌/사례:** AERA 1.0–1.4, 4.0–4.4, 4.7, 4.18, 4.22–4.25; ITC 2.2.2–2.2.6; EFPA 2025 Part A와 Part B §6.
- **예상 점수 기여:** 항목 5의 3→4 후보(+2.22), 항목 4 보강. 5점 요건의 외부 평가 부분은 충족하지 못함.
- **구현 난이도:** 중간. 기존 문서를 합치는 것보다 정본·버전·증거 링크를 유지하는 운영 부담이 큼.
- **위험:** 문서가 현재 코드와 어긋나면 신뢰를 더 잃는다. release manifest와 자동 링크 검사 없이는 공개하지 않는다.

### P2. 전체 56문항 매핑과 선정·제외 기준 공개

문항 ID, 문항 요지, 축, 기여 성격, 결과 반영 위치, 가중치, 제외/보조 여부를 56행으로 공개한다. 원문 전체 공개가 문항 보안을 해치면 문항 요지와 근거를 공개하고, 무엇을 가렸는지 명시한다. 6개 좋은 사례만 고르는 방식은 중단한다.

- **근거 문헌/사례:** AERA 1.11(내용의 관련성과 대표성), 4.1, 4.12(정의된 영역 대표성); ITC 2.2.2(a); 외부 원문 항목 3·4.
- **예상 점수 기여:** 항목 4의 4→5 후보(+3.33). 항목 3은 매핑 공개만으로 사람 SME 요건을 충족하지 않으므로 3점 유지 또는 4점 후보에 그침.
- **구현 난이도:** 낮음~중간. 현재 매핑 자료를 공개용으로 정리하고 56/56 무결성 게이트 필요.
- **위험:** 현 매핑의 과잉·모순이 드러날 수 있다. 이것은 숨길 위험이 아니라 수정 목록으로 공개할 품질 정보다.

### P3. 기존 합성 회귀자료의 독립 재현 패키지 공개

새 고객자료 없이 가능한 일이다. 고정 합성 입력, seed, release/환경, 실행 명령, 기대 출력 schema, 원로그·digest, 양성/음성 통제, PASS/FAIL/INCONCLUSIVE 규칙을 공개하고 제작에 참여하지 않은 2인이 서로의 결과를 보지 않고 재실행한다. 결과가 불리해도 공개한다.

- **근거 문헌/사례:** AERA 4.15(시행 조건의 재현 가능 문서화), 4.18–4.21(채점 정확성·일치), ITC 2.6, ISO 10667-1/-2:2020 공개 구조의 assessment delivery/evaluation/review.
- **예상 점수 기여:** 항목 1의 4→5 후보(+3.33), 항목 2·6의 3→4 후보(각 +2.22). 외부 감사와 동등하지 않음.
- **구현 난이도:** 중간~높음. clean checkout 재실행, fixture와 결함 주입, 독립 실행자가 필요.
- **위험:** 현재 게이트 공백과 불일치가 노출될 수 있다. 실패를 삭제하면 전체 절차가 무효다. 내부 에이전트 실행은 `내부 독립 재현`으로만 부른다.

### P4. 근거 상태 대시보드와 실패 로그 공개

| 근거 종류 | 현재 공개 상태 | 허용되는 말 | 다음 해금 조건 |
|---|---|---|---|
| 계산 재현성 | 내부 게이트 근거 있음 | 같은 release·입력의 계산 결과 일치 | 독립 재실행·원로그 공개 |
| 재검사 신뢰도 | 데이터 없음 | 미측정 | 동일 사람, 사전등록 간격·지표·CI |
| 내용 관련성 | 매핑 있음, 독립 사람 평정 없음 | 매핑 공개·평정 미완료 | 독립 사람 SME 평정·원분포 공개 |
| 내적 구조 | 데이터 없음 | 미측정 | 독립 표본의 사전등록 분석 |
| 준거·예측 관련성 | 데이터 없음 | 미측정 | 외부 준거·추적 연구·교차검증 |
| 규준 | 없음 | 타인 대비 해석 불가 | 정의된 모집단과 대표 표본 |
| 공정성 | 집단별 자료 없음 | 미측정 | 집단별 bias/DIF·접근성 연구 |

- **근거 문헌/사례:** AERA 1.3, 2.19; EFPA §§8–12; ITC 2.2·2.7·2.9; 외부 원문 항목 8.
- **예상 점수 기여:** 항목 8의 4→5 후보(+2.22), 항목 5 보강. 측정 항목 자체 점수는 올리지 않음.
- **구현 난이도:** 낮음. 월별 갱신 책임자는 필요.
- **위험:** 미충족이 많아 보인다. 그러나 서로 다른 증거를 한 녹색 배지로 합치지 않는 것이 B2B 신뢰의 최소 조건이다.

### P5. EFPA 2025 항목별 자체 점검 공개

EFPA 원척도 `n/a/0/1/2/3/4`를 그대로 사용하고 내부 1–5 점수로 환산하지 않는다. Part A 사실 기술과 Part B §6 문서, §7 재료, §8 규준, §9 신뢰도/정밀도, §10 타당도, §11 공정 사용, §12 디지털 보고서를 빠짐없이 표로 만든다. 0·1·미확인은 숨기지 않는다.

- **근거 문헌/사례:** EFPA Test Review Model Version 5.0(2025), Part B rating guidance와 §§6–12. 개발자 자체평가가 EFPA의 추천·승인을 의미하지 않는다는 원문 주의.
- **예상 점수 기여:** 항목 5의 3→4 후보(+2.22). EFPA 리뷰가 없으므로 5점 요건은 불충족.
- **구현 난이도:** 중간.
- **위험:** 자체 점검을 제3자 결과처럼 보이게 할 위험. 모든 페이지 상단에 `자체 점검 / EFPA의 평가가 아님`을 표시한다.

### P6. 사람 SME가 아닌 AI 패널 결과는 보조 부록으로 제한

기존 자격시험·음성 통제·블라인드 독립 평정 절차를 실행할 수 있다. 단, 결과는 `AI 전문가 패널 N명, 자체 채점`으로 표시하고 사람 SME 3~5명 요건을 대신하지 않는다. 사람 SME 진행 전 문항·축 정의의 오류 후보를 찾는 사전 검토 용도로 쓴다.

- **근거 문헌/사례:** AERA 1.9(판정자 선정·자격·훈련·독립·합의 공개), 1.11; 외부 원문 항목 3.
- **예상 점수 기여:** 항목 3의 4점 후보 근거. 외부 원문은 4점 앵커를 정의하지 않았고 5점에는 사람 SME가 필요하므로 기여값 **미확인**.
- **구현 난이도:** 중간.
- **위험:** AI를 사람 전문가처럼 보이게 하거나 CVR 숫자만 강조하는 순간 신뢰가 하락한다. 기반 모델 간 오류 상관도 남는다.

### P7. B2B 신뢰 패킷을 구매 심사 순서로 재구성

한 폴더/URL에 다음을 묶는다: 제품 사용범위, 샘플 산출물, 기술 매뉴얼, 근거 대시보드, 처리위탁·국외이전·보존/삭제, 보안 통제 증빙, 장애/문의/SLA, 접근성 실측, 계약상 금지 사용, 제3자 검토 이력, 알려진 제한·사고 대응.

- **근거 문헌/사례:** ISO 10667-1/-2의 agreement→pre-assessment→delivery→review 구조; ITC §§1.3–1.5, 2.1–2.9; 개인정보보호법상 처리 근거·위탁·국외이전·정보주체 권리 고지 영역.
- **예상 점수 기여:** ⑤축 자체 항목 5·7·8 보강. 별도 공개채점표 A1·A2·A6·A11에도 관련되나 척도 간 환산은 금지.
- **구현 난이도:** 중간~높음.
- **위험:** 현 B2B 개인정보 문서의 계약·국외이전·리전 표현을 증빙 없이 확정하면 법적 위험이 커진다. 문안보다 계약서·콘솔·DPA 실물이 먼저다.

## 3. 국제 규범 요구와 현황 대조

### “검사 아님”이라고 부르면 적용을 피할 수 있는가

**아니다.** ITC Guidelines는 명칭과 무관하게 표준화된 조건에서 행동 표본으로 사람에 대한 추론을 만드는 절차를 넓게 다룬다. assessment procedure가 `test`라고 불리지 않아도 지침이 관련될 수 있다고 명시한다. AERA Standards도 명칭보다 점수 해석과 사용 주장을 중심으로 본다. ISO 10667은 직무·조직 장면의 사람 평가 서비스에 적용되므로 B2B 라인은 특히 관련성이 높다.

다만 “의료·임상 진단이 아닌 자기성찰·실행설계 참고자료”라는 범위 고지는 중요하다. 이것은 의무를 없애는 면책문이 아니라 **허용되는 해석과 사용을 좁히는 통제**다.

| 규범 | 요구되는 공개 수준 | 현황 | 차이·조치 |
|---|---|---|---|
| AERA 1.0–1.4 | 점수별 의도 해석·용도·대상·구성과 근거, 미검증 해석 경고 | 축 정의·한계 블로그 일부 공개 | 기술 매뉴얼에 해석/금지 사용/근거 상태를 score 단위로 고정 |
| AERA 1.8–1.11 | 타당도 표본·조건, 전문가 선정·독립·합의, 내용 매핑·누락 영역 | 타당도 표본 없음; 매핑 파일 존재; 사람 SME 결과 없음 | 56행 공개, 평가자 자격·이해상충·원평정 공개 |

| ITC 1.1–1.5 | 윤리, 역량 한계, 책임, 보안, 결과 기밀성·보존·동의 | 한계·약관·처리방침 일부 존재 | 역할별 역량, 접근권한, 보존·삭제 실증, 계약/정책 일치 필요 |
| ITC 2.1–2.3 | 사용 필요성, 기술적으로 적합한 도구 선택, 타당도·규준·편향·공정성 검토 | 사용 목적 설명은 있으나 기술 근거·집단별 공정성 미측정 | B2B 의사결정의 단독 사용 금지, 대안정보 병용, 공정성 상태 공개 |

### 공개 지면에서 확인된 중요한 모순

1. one-page의 `기타 14 + 메타 2` 표기는 현재 정본 `조건부 기타 20, 메타 2는 76 밖`과 불일치한다.
2. 개발자 노트는 심리측정 작업을 “수십만 명 누적 시”로 표현하지만 내부 재검사 파일럿은 N≥30을 계획한다. 연구 단계와 목적을 구분해야 한다.
3. B2B 개인정보 문서는 Google LLC의 국가를 미국으로 쓰면서 데이터 리전을 `asia-northeast3 / asia-southeast1`로 병기한다. 법인 소재지, 처리 위치, 저장 위치가 섞여 있어 구매 심사자가 오해할 수 있다.
4. B2B 개인정보 문서는 수탁자와 표준 DPA 또는 동등 약정을 체결했다고 단정하지만, 내부 ROPA 문서는 Payple/PayPal/Resend의 DPA·처리국가·보유를 미확인으로 둔다. Resend에 대한 공개 주장과 내부 증거 상태가 충돌한다.
5. 클라우드 사업자의 ISO 27001/SOC 2 범위를 이용한다고 해서 인생포트폴리오 조직·애플리케이션 자체가 같은 심사 범위에 포함되는 것은 아니다.

- [x] 참여 자율성과 인사상 불이익 금지 존재
- [ ] **미확인:** 가동률, 지원시간, 우선순위별 응답·복구 목표가 있는 SLA
- [ ] **미확인:** 장애·변경·종료·데이터 이전·사업 연속성 절차
- [ ] **미확인:** 도입 담당자용 운영 매뉴얼과 참여자 민원·이의제기 경로
- [ ] **미확인:** 하도급·재위탁 변경 통지와 고객 승인/해지 절차

### E. 접근성·도입 실증

- [ ] **미확인:** WCAG 2.2 AA 기준의 실제 axe/Lighthouse/키보드/스크린리더 결과
- [ ] **미확인:** PC·모바일의 완주율, 소요시간, 중단 지점, 도움 요청 경로
- [ ] **미확인:** B2B 파일럿의 사전 합의 성공기준과 낮은 결과를 포함한 보고
- [ ] **미확인:** 도입 결정자에게 제공할 데이터흐름도·위험등록부·책임분장표

### 최소 Go/No-Go

**B2B 유료 파일럿 Go**는 가능하지만 다음 조건이 필요하다.

1. 채용·승진·징계·의료 판단의 단독 근거 사용 금지
2. 자발적 참여와 개인 리포트 비공유
3. 처리위탁·국외이전·보존/삭제·사고대응을 계약과 실제 설정으로 일치
4. 기술 매뉴얼·한계표·release 증거 패킷 제공
5. 파일럿 성공기준, 지원 수준, 종료·삭제 절차를 계약 부속서로 합의

이 다섯 조건이 없으면 구매자가 `준비 안 된 제품`으로 분류할 가능성이 높다. 반대로 외부 기관 이력이나 측정 연구가 없어도 **낮은 위험의 자발적 교육·코칭 파일럿**은 조건부로 가능하다. ⑤축 90은 B2B 매출의 충분조건도, 모든 파일럿의 필요조건도 아니다.

## 5. 절대 해서는 안 되는 표현·주장

| 금지 표현/행위 | 왜 위험한가 | 근거 |
|---|---|---|
| “신뢰도 100%”, “신뢰도가 검증됐다” | 계산 결정론을 사람의 시간 안정성으로 오인시킴 | AERA 2.1–2.6, 2.19; 표시광고법 제3조·제5조 |
| “재현성 100%” 단독 | 무엇을 어떤 release·표본에서 반복했는지 숨김 | AERA 2.1·2.19; ITC 2.8 |
| “타당성이 입증된”, “과학적으로 증명된” | 내용·구조·준거·예측 근거가 없는 상태와 충돌 | AERA 1.0–1.5; 표시광고법 제3조·제5조 |
| 자사 제품을 “심리검사”라고 자칭 | 고객이 임상·심리측정 수준의 근거와 자격을 기대할 수 있음 | ITC Scope, 2.2; 현행 근거 상태 |
| “정확도 N%”, “적중률 N%” | 정답·준거·검증표본이 정의되지 않음 | AERA 1.17–1.20; 표시광고법 제5조 |
| “공인 인증”, “공인 평가” | 해당 기관이 제품을 심사했다는 허위 인상을 줌 | EFPA 2025의 자체평가 비추천/비승인 주의; 외부 원문 §8.4 |
| “전문가 N명” 단독 | AI 패널 또는 내부 인력을 사람 SME로 오인시킴 | AERA 1.9의 자격·선정·독립 공개 원칙 |
| “상위 N%”, “평균 이상” | 정의된 규준 표본이 없음 | AERA 4.22; EFPA §8; ITC 2.6.5·2.7.2 |
| “4축이 통계적으로 확인됨” | 요인구조 자료가 없음 | AERA 1.13; EFPA §10.2 |
| “성과·이직·직무 적합을 예측” | 준거·추적·교차검증이 없음 | AERA 1.5, 1.17–1.20 |
| “기업 도입에 안전”, “편향 없음” | 집단별 공정성·DIF·운영 위험 자료가 없음 | AERA Ch.3; ITC 2.3; EFPA §11 |
| “ISO 10667 준수/적합” | 정식 원문 대조·적합성 심사·적용범위 확인이 없음 | ISO 10667-1/-2:2020 |
| 클라우드 제공자 인증을 자사 인증처럼 표시 | 인증 범위·책임주체가 다름 | 인증서 scope 원칙; 표시광고법 제3조·제5조 |
| 실패한 게이트·낮은 평정·N/A를 삭제 | 선택적 공개로 합리적 구매 판단을 방해 | AERA 1.2–1.3; ITC 2.2·2.8·2.9 |
| 결과를 채용·승진·징계의 단독 근거로 사용 | 의도 용도 밖 고위험 해석이며 현 약관과도 충돌 | AERA 1.4; ITC 2.1–2.3; B2B 약관 제11조 |

법률 위험의 핵심은 이름보다 **소비자가 받아들이는 전체 인상**이다. 표시광고법 제3조는 거짓·과장·기만적 표시를 금지하고, 제5조는 사실 관련 주장에 실증 가능성을 요구한다. 한계 각주가 본문 헤드라인의 강한 오인을 자동으로 치유한다고 가정해서는 안 된다. 개인정보보호 관련 계약·국외이전·위탁 문구는 실제 계약 및 처리 흐름과 법률 검토를 거쳐야 한다.

## 6. 3차 재평가용 실행 순서와 수용 기준

### 1주차: 사실 정합성 봉합

- 공개 문항 수·메타 정의·내용 관련성 상태·연구 일정 모순 전수 정정
- 계산 재현성 문구를 release·입력·한계와 결합
- 산출물: `주장–증거–URL–확인일` 레지스터
- 수용: 금지 표현 0, 공개 페이지 간 핵심 수치 불일치 0

### 2주차: 공개 기술 매뉴얼·56행 매핑·근거 대시보드

- 정본 3종을 같은 release ID로 묶음
- 수용: 56/56 매핑, 모든 주장에 URL/digest, 미측정 항목 누락 0

### 3주차: 독립 재현·품질 로그

- 제작 미참여 2인이 blind 실행
- 음성 통제 결함을 모두 탐지하지 못하면 실패
- 수용: 원로그·환경·불일치·실패 공개, 결과 조정 전 일치도 보존

### 4주차: EFPA·ISO 공개 대조와 B2B 패킷

- EFPA는 원척도, ISO는 정식 원문 접근 범위에서만 대조
- 개인정보·DPA·리전·SLA의 미확인을 계약·설정 증거로 해소하거나 `미확인` 유지
- 수용: 기관 심사처럼 보이는 표현 0, 증빙 없는 ✅ 0

### 재평가 의뢰 조건

1. 2차와 동일한 ⑤축 정의와 동일 채점표 사용
2. 새로 만든 2점·4점 앵커를 **평가 전에** 공개하고 소급 적용 금지
3. 외부 평가자에게 항목별 원문 인용·점수·미충족·90점 추가조건을 요청
4. 67→90을 목표로 제시하되 자체 예상점수는 제공하지 않음
5. 90 미만 결과도 원문 그대로 보존

## 7. 점수 시나리오 — 보장값 아님

외부 원문의 평가 가능 8항목만 사용한 민감도다.

| 시나리오 | 항목 점수 가정 | 8항목 환산 | 판정 |
|---|---|---:|---|
| 2차 기준 | 4,3,3,4,3,3,4,4 | 71.1 | 외부 최종 67과 별도 종합 감점 존재 |
| 공개 정합성·전체 매핑만 개선 | 4,3,3,5,4,3,4,5 | 78.9 | 측정자료 공백 유지 |
| 독립 재현·문서·통제를 4점으로 외부 인정 | 5,4,3,5,4,4,5,5 | 88.9 | 항목 3과 9가 남아 90 미달 |
| 내용 항목도 4점으로 외부 인정 | 5,4,4,5,4,4,5,5 | 91.1 | 항목 9 N/A 감점이 다시 붙으면 90 미만 가능; 사람 SME 5점 요건도 미충족 |

이 표가 보여 주는 것은 **90이 수학적으로 가능한 경로**이지 3차 평가 결과가 아니다. 가장 취약한 가정은 원문에 없는 4점 앵커를 외부 평가자가 받아들이는지와 항목 9 N/A의 구조적 감점을 어떻게 처리하는지다.

## 8. 자기 반박

1. **문서가 좋아져도 측정근거는 생기지 않는다.** 공개·정합성·독립 재현은 항목 1·2·4·5·6·7·8을 개선할 수 있지만, 재검사·구조·준거·규준 공백을 해소하지 않는다.
2. **한계 공개가 곧 신뢰 상승이라는 인과는 확정되지 않았다.** 외부 루브릭은 정직성을 보상하지만 실제 구매자가 구매를 보류할 수도 있다. 그렇더라도 숨김은 더 큰 법적·장기 신뢰 위험이다.
3. **독립 재현은 외부 감사가 아니다.** 같은 조직의 에이전트나 계약자가 절차를 다시 실행해도 감사인의 책임·통제환경 검토·기관 감독은 생기지 않는다.
4. **90점은 외부 평가자의 판단이다.** 원문은 1·3·5점만 정의했고 4점 앵커와 N/A 감점 산식이 불완전하다. 평가 전에 이를 고정하지 않으면 점수 개선 주장은 사후 보간이 된다.
5. **B2B 준비도는 ⑤축 하나가 아니다.** 보안, 위탁, SLA, 접근성, 운영지원이 비어 있으면 전문성 문서가 좋아도 도입은 막힌다.
