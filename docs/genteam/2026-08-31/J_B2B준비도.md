- 외부 평가 기준선: ⑤ 전문성·신뢰감 67점, B2B 도입 실패 위험 “높음(80%+)”

## 0. 경영 판단

현재 상태는 **“거래 흐름은 있으나 기업 도입 증거 패키지는 미완성”**이다.

- 견적, 구간별 가격, 계약 조건, B2B 개인정보 처리방침, 조직 코드, 진행 현황, 환불 규칙은 존재한다.
- 반면 구매자가 핵심적으로 묻는 **측정 근거, 사용 한계, 실제 도입 사례, 효과 측정, 서비스 수준, 보안 증거, 구현·지원 책임**은 없거나 공개 문구와 계약 범위가 서로 어긋난다.
- 특히 랜딩은 `검증된 진단 구조`, `번아웃 신호`, `팀 종합 리포트`, `워크숍`, `연간 라이선스·분기별 리포트`, `다국어 운영`을 제시하지만, 계약서의 기본 서비스 구성은 `76문항 1회 + 개인별 리포트` 중심이다. 이 불일치는 준비 부족 신호를 강화한다.

따라서 **대기업·전사 도입 판매를 지금 확대하지 않는다.** 먼저 10~29명 규모의 유상 또는 제한적 PoC를 “자율 참여형 자기성찰·실행 프로그램”으로 운영하고, 구매 증거를 만든 뒤 확대한다.

## 1. 도입 결정자가 보는 구체적 준비도 신호와 현 상태

판정 기준의 외부 근거:

- NIST AI RMF는 목적·맥락·한계·책임·사람의 감독·측정과 문서화를 요구하는 위험관리 구조를 제시한다: https://www.nist.gov/itl/ai-risk-management-framework
- NIST AI RMF Playbook은 역할·책임과 사람의 감독을 정의·문서화하도록 권고한다: https://airc.nist.gov/airmf-resources/playbook/govern/
- 개인정보보호위원회는 근로자 개인정보 처리내용 공개와 안전성 확보조치를 안내한다: https://www.pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=8579
- ICO 근로자 모니터링 지침은 근로자에 대한 투명성, 필요성·비례성, 영향 검토를 강조한다: https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/employment/monitoring-workers/data-protection-and-monitoring-workers/
- EEOC는 소프트웨어·알고리즘을 채용·평가·승진 등에 사용할 때 차별 위험이 있음을 안내한다: https://www.eeoc.gov/eeoc-disability-related-resources/artificial-intelligence-and-ada

### 즉시 차단해야 할 신호

1. **증거보다 앞선 표현:** `검증된 진단 구조`, `번아웃 신호를 데이터로 확인`, `조직 시너지와 성과`.
2. **상품·계약 불일치:** 팀 종합 리포트·워크숍·연간/분기 리포트·다국어 지원이 실제 SOW와 일치하지 않음.
3. **규모 약속·운영 역량 불일치:** 200명+·전담 채널을 제안하면서 1인 운영·대규모 운영 미검증.
4. **사례 부재:** 실제 고객 로고·후기·PoC 결과가 없음.
5. **효과 증거 부재:** 참여·완료·행동 변화·관리자 만족·지원 부하 데이터가 없음.
6. **입력 수 표현 불명확:** B2B 표면은 `76문항`으로만 표기한다. 현행 내부 기준인 `56개 핵심 문항 + 최대 20개 조건부 추가 입력`과 정의를 맞추지 않으면 구매자는 설문 범위와 데이터 최소수집 여부를 오해할 수 있다.

| 조달 | 회사·세금·계약 서류 체크리스트 | 최신본·소유자·유효기간·제공 조건 기록 |
| 주장 정리 | B2B 랜딩 증거 레지스트리 | 문장마다 근거/상태/사용기한. 근거 없는 표현 제거 또는 조건부화 |

### B. 시간이 필요한 것 — 파일럿과 운영 이력

| 항목 | 최소 경로 | 완료 전 표기 |
|---|---|---|
| 재검사 신뢰도 | N≥30, 2~4주 간격, 동일 release, 사전 분석계획 | `미증명` |
| 내용타당도 | 독립 SME 평정 절차 완료 및 일치도 공개 | `진행 중` |
| 구성·예측타당도 | 가설·표본·비교척도·추적기간을 정한 연구 | `미증명` |
| 조직 효과 | 10~29명 PoC 여러 회차에서 참여·완료·첫 행동·지원부하·철회·부작용 측정 | `효과 미확인` |
| 사례 | 고객 동의 후 목적·대상·기간·방법·결과·한계를 포함한 사례 | `공개 사례 없음` |
| 서비스 수준 이력 | 최소 90일 가용성·장애·지원 응답 로그 | `목표값, 실적 없음` |
| 보안 외부 검토 | 범위가 명시된 독립 검토와 시정 완료 | `외부 검토 이력 확인 불가/없음` |
| 운영 용량 | 동시 사용자·코드 발급·지원 티켓 부하 테스트와 실제 PoC | `대규모 운영 미검증` |

### C. 현재 만들 수 없는 것 — 정직한 우회

| 만들 수 없는 것 | 정직한 우회 |
|---|---|
| 규준 기반 인사평가 도구라는 지위 | “자율 참여형 자기성찰·실행 지원 자료”로 한정하고 채용·평가·승진·보상에 사용 금지 |
| 구성원 개인 리포트를 HR에 자동 제공 | 제공하지 않는 것을 개인정보 보호 설계로 명시. HR에는 동의 기반 집계 또는 진행 현황만, 최소 인원·재식별 방지 규칙이 생기기 전에는 결과 집계도 제공하지 않음 |
| 조직 성과·번아웃 감소 보장 | 효과를 약속하지 않고 PoC에서 사전 등록된 행동·운영 지표만 측정 |
| 외부 검토 이력이 있는 것처럼 표시 | 기관명·연도·URL이 실제로 있을 때만 표시. 그 전에는 “현재 없음/확인 불가” |
| 24/7·대기업급 SLA | 영업시간·지원 채널·최초응답 목표를 보수적으로 계약하고, 초과 규모는 받지 않음 |
| 200명+ 즉시 전사 롤아웃 | 10~29명 PoC → 종료 검토 → 제한 확대의 단계 계약. 운영 용량 실증 전 Enterprise SKU 판매 중단 |
| 90점 또는 도입 성공 보장 | 3차 외부 재평가와 실제 PoC 결과를 기다리고 현재 상태·한계를 공개 |

## 3. B2B 도입 검토 최소 문서 세트

| 문서 | 목적 | 보유 여부 |
|---|---|---|
| 1. 제품·사용범위 1페이지 | 무엇을 제공하고 어디에 쓰지 않는지 결정자가 즉시 판단 | **부분:** `b2b.html`, `promise-and-limits.md`; 상호 문구 정렬 필요 |
| 2. SKU별 SOW/제안서 | 포함·제외·납기·인수기준·가격을 계약과 일치 | **미충족:** 랜딩·계약 범위 불일치 |
| 3. 샘플 리포트·프로그램 | 실제 산출물의 내용·톤·개인정보 노출 검토 | **부분/확인 불가:** 저장소 샘플은 있으나 B2B 구매 패키지 제공 여부 미확인 |
| 4. 방법론·한계 설명서 | 문항·산출 구조, 해석 범위, 미증명 항목 설명 | **미충족(공개 구매용)** |
| 5. B2B 표준 계약·환불·NDA | 상업 조건과 책임 배분 | **보유:** `b2b-terms.html` |
| 6. 개인정보 처리방침 | 처리 항목·목적·보유·위탁·권리 | **보유:** `b2b-privacy.html` |
| 7. 데이터 흐름도·DPA | 고객사/당사/수탁자 역할과 삭제 증빙 | **미충족/확인 불가** |
| 8. 보안·접근통제 개요 | IT·보안팀 질문에 통제와 예외를 증거로 답변 | **미충족(고객용 문서)** |
| 9. 접근성 현황서 | 직원 사용성·합리적 편의 검토 | **부분:** Lab 실측은 있으나 문서 패키지 없음 |
| 10. 구현계획·RACI | HR·IT·관리자·참여자·당사 책임 및 일정 | **미충족** |
| 11. 관리자·참여자 커뮤니케이션 키트 | 자율성, 개인정보, 시작·지원·철회 안내 | **미충족/확인 불가** |
| 12. 지원정책·서비스 수준 부속서 | 지원시간·심각도·응답·장애·복구·공지 기준 | **미충족** |
| 13. PoC 평가계획 | 성공·중단·확대 기준과 지표 정의 | **미충족** |
| 14. 사례·레퍼런스 시트 | 실제 도입 가능성과 결과의 범위를 증명 | **미충족:** placeholder 제거 기록 존재 |
| 15. 회사·조달 서류 묶음 | 사업자·세금·계좌·견적·법률 검토 확인 | **부분/확인 불가:** 발행 문구는 있으나 파일 묶음 미확인 |

**최소 게이트:** 1~12가 없으면 유상 PoC 제안 전 단계, 13까지 있어야 PoC 착수, 14와 90일 운영 이력이 있어야 전사 확대 검토로 본다.

## 4. “준비 안 됨”을 신뢰로 바꾸는 커뮤니케이션

### 판정: 브랜딩 원칙과 양립한다. 단, 결함 공개만으로는 부족하다.

양립 조건은 `발견 → 영향 → 임시 통제 → 수정 → 재검증 → 남은 한계`가 한 묶음일 때다. 결함 목록만 공개하면 구매자는 통제 부재로 읽는다. 수정 기록이 있어도 현재 계약·운영에 반영되지 않았다면 신뢰 증거가 아니다.

### 권장 메시지 구조

1. **현재 가능한 범위:** “현재 기업 도입은 10~29명 제한 PoC로 운영합니다.”
2. **하지 않는 사용:** “개인 결과는 HR에 제공하지 않으며 채용·평가·승진·보상의 근거로 쓰지 않습니다.”
3. **증명된 것:** “동일 release·엔진·입력의 계산 결과 일치를 확인했습니다.”
4. **아직 없는 것:** “재검사 신뢰도는 미증명, 내용타당도는 진행 중, 구성·예측타당도는 미증명입니다.”
5. **PoC에서 확인할 것:** 참여율·완료율·첫 행동 기록·지원 요청·철회·부작용.
6. **확대 조건:** 사전 기준 통과와 고객사 공동 종료 검토 후에만 확대.

### 구매자용 상태표

| 영역 | 상태 | 증거 | 다음 조건 |
|---|---|---|---|
| 개인결과 비공개 | 구현·문서 확인 | 계약/FAQ/진행현황 화면 | 교차계정 E2E 결과 추가 |
| 계산 재현성 | 증명됨 | 게이트 버전·fixture·로그 | 릴리스마다 회귀 |
| 재검사 신뢰도 | 미증명 | 없음 | N≥30·2~4주 |
| 내용타당도 | 진행 중 | 평정 계획·중간 산출물 | 독립 평정 완료 |
| 구성·예측타당도 | 미증명 | 없음 | 연구 설계·표본·기간 확보 |
| 조직 효과 | 미확인 | 공개 사례 없음 | PoC 사전등록 지표 측정 |
| 대규모 운영 | 미검증 | 용량·SLA 이력 없음 | 제한 PoC와 부하·지원 이력 |

### 금지되는 “정직성 마케팅”

- 결함 발견 건수 자체를 품질 우수성으로 포장
- 수정 전후 내부 점수를 외부 효과처럼 제시
- “우리는 투명하므로 안전하다”는 인과 주장
- 고객을 미완성 제품의 무상 시험대로 취급
- 핵심 위험을 각주에 숨기고 메인 문구에서 과장

## 5. B2B를 지금 추격하는 우선순위에 대한 반대 의견

### 결론: 전사·Enterprise 추격은 지금 틀린 우선순위일 가능성이 높다. 제한 PoC만 유지한다.

1. **자체 전략 문서가 이미 보류 조건을 두었다.** `docs/marketing/40_S2_S3_DEFER.md`는 S1 월 결제 800건+, 21일 CVR 8%+, LTV/CAC≥3, 인력·예산 확보 후 B2B를 활성화하도록 한다. 현재 이 조건의 달성 근거는 이번 조사에서 확인되지 않았다.
2. **가장 큰 외부 격차가 신뢰 영역이다.** 전문성·신뢰감 67점 상태에서 전사 도입을 팔면 영업이 제품 증거보다 앞선다.
3. **영업 문구와 계약 범위가 불일치한다.** 지금 리드 유입을 늘리면 세일즈·법무·운영 단계에서 신뢰 손실이 커진다.
4. **운영 용량이 모순된다.** 내부 약속 문서는 1인 운영·24/7·대규모 그룹 운영을 약속하지 않는데 랜딩은 200명+·전담 운영자 채널을 판매한다.
5. **B2B는 지원·보안·개인정보·법무·조달 부하를 동시에 만든다.** 현재는 문서와 증거를 만드는 고정비가 계약 규모보다 앞설 수 있다. ACV·세일즈 사이클·승률·지원 원가의 실제 데이터는 미확인이다.
6. **효과 사례가 없어 구매자 리스크를 낮출 수 없다.** 대기업보다 10~29명 제한 PoC가 학습 속도와 피해 한계를 관리하기 쉽다.

### 권고 우선순위

**향후 30일:** 신규 Enterprise 영업·대량 아웃바운드 중단 → 문구/계약 정합성 → 최소 문서 1~13 완성 → 10~29명 PoC 1~3건 모집.

**확대 게이트:**

- 랜딩·SOW·계약 일치
- PoC 2회 이상 종료 및 사전 성공/중단 기준 공개
- 개인결과 비공개·자율참여 E2E 확인
- 지원·장애·삭제 절차 실제 실행
- 운영 용량과 원가 측정
- 재사용 가능한 사례 1건 이상(고객 동의·한계 포함)

게이트 전에는 B2B를 매출 채널이 아니라 **증거 생성 채널**로 취급한다.

## 6. 30일 실행안

| 주차 | 산출 | 의사결정 |
|---|---|---|
| 1주 | B2B 주장 전수표, SKU/SOW 정합화, 위험 문구 조건부화 | 판매 가능한 범위 확정 |
| 2주 | 방법론·한계, 데이터 흐름/DPA, 보안·접근성 현황, 지원정책 | 구매 실사 패키지 v0.1 |
| 3주 | PoC 실행서·RACI·참여자 안내·성공/중단 기준 | PoC 승인/보류 |
| 4주 | 10~29명 후보 1~3곳에 동일 패키지 제시, 질문·거절 이유 기록 | 문서 결함 수정 후 첫 PoC 계약 |

### CRM/파이프라인 최소 단계

`관심 → 적합성 확인 → 위험·개인정보 검토 → PoC 설계 → PoC 계약 → 실행 → 종료 검토 → 확대/중단`

각 단계에는 필수 증거와 종료 사유를 둔다. PoC 종료 검토 없이 Enterprise 제안으로 건너뛰지 않는다.

## 7. 자기 반박

1. 저장소 문서가 실제 운영을 완전히 반영하지 않을 수 있다. 미확인 서류가 별도 드라이브에 존재하면 일부 미충족 판정은 바뀐다.
2. 해외 NIST·ICO·EEOC 자료는 한국 기업 구매의 법적 의무를 직접 정하지 않는다. 위험 질문의 참고 구조이며 한국 법률 검토를 대체하지 않는다.
3. 제한 PoC는 대기업 레퍼런스 확보를 늦출 수 있다. 다만 현재 증거 공백에서 큰 계약을 먼저 따는 위험이 더 크다고 판단했다.
4. 문서 세트가 완성돼도 실제 운영 역량이 생기는 것은 아니다. 모든 문서는 PoC 로그와 장애·지원·삭제 실행 증거로 검증해야 한다.
5. 외부 평가의 “80%+” 산정식·표본은 이번 발주에 제시되지 않았다. 따라서 위험의 방향은 채택하지만 80%를 확률 예측치로 재사용하지 않는다.
