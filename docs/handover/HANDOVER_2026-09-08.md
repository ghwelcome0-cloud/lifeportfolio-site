### 교훈 3 의 근본 해결법 (이번에 발견 — 반드시 쓰라)
**한글 요약을 손으로 쓰지 말고, 원문에서 grep 해 그대로 인용하라.**
```python
def q(path, needle):
    for l in io.open(path, encoding="utf-8").read().split("\n"):
        if needle in l: return l.strip()
    return "(not found)"
# 그 다음 f"> {q(...)}" 로 인용만 한다
```
- heredoc(`cat > f << 'EOF'`)은 **안전**하다. 위험한 것은 python escape 로 한글을 조립할 때다.
- 어쩔 수 없이 escape 가 필요하면 **파일에서 바이트를 읽어 escape 를 추출**하라:
  `s.encode("unicode_escape").decode("ascii")`
- 파일명에 `①`(U+2460) `§` 를 쓰지 마라. ASCII 로 바꿔 저장하라.
- MultiEdit 은 한글 문자열에서 **반복 실패**했다. python + `assert src.count(old)==1` 을 쓰라.

## 15. 마지막 조언

1. **실측하라. 추측을 사실로 쓰지 마라.** 이 프로젝트에서 가장 큰 사고는 전부
   "확인했다고 생각한 것"에서 나왔다.
2. **자기 검사기를 의심하라.** 초록불이 켜졌다고 통과한 것이 아니다. 불이 켜졌는지부터 보라.
3. **에이전트 회신을 그대로 믿지 마라. 재현하라.** N 의 지적 3건을 격리 재현했고 3/3 사실이었지만,
   재현 과정에서 아무도 지적하지 않은 4번째 결함을 스스로 찾았다.
4. **에이전트가 대표 지시를 반박할 수 있다.** V·T·P 가 그랬고 셋 다 근거가 있었다.
   반박을 봉쇄하지 말되, **승인 방향을 바꾸는 사안은 재단하지 말고 대표께 올려라.**
5. **불편한 사실을 먼저 보고하라.** 대표님은 그것을 브랜딩 자산으로 본다.
   내 거짓 커밋 메시지를 자진 보고했을 때 대표님은 승인으로 답했다.
6. **회신 22건 중 "90점을 보장한다"고 말한 것은 0건이다.** 발주 B 는 최선 시나리오에서도
   **88.9점**을 제시하며 "90 달성은 보장할 수 없습니다"라고 명시했다.
   **보장하지 마라.** 어디까지 실증했고 어디부터 추정인지를 구분해 보고하라.
7. 작업을 끝낼 때 **`git status --untracked-files=no` 가 blank** 인지 확인하라 (제4조).
   /tmp 산출물은 저장소 밖이므로 문제없지만, 진단 스크립트는 저장소 안에 두어라 (교훈 4).
