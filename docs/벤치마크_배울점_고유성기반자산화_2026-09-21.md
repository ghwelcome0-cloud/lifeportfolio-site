## 1. 사용자 피드백과 변경된 작업 순서

사용자는 네 벤치마크의 추천 조합에 동의했다. 핵심 요구는 다음과 같다.

1. 우리 비즈니스 철학과 차별성인 **고유성 기반 자산화**에 맞게 직관성을 개선한다.
2. '우리가 배울 점'을 제작규칙서나 헌법에 보관해 현재 에이전트·GenTeam·앞으로의 동료들이 같은 기준과 수준으로 일하게 한다.
3. 전체 리포트 페이지별 검토 중 **VII 네 영역 심층 진단을 가장 먼저** 다룬다. 자기이해부터 자기실행까지 기존 페이지 구조는 좋으며, 현재 품질 위에 축적한다.
4. Gallup의 배울 점과 그대로 가져오지 않을 점을 네 영역에 적용한다.
5. Birkman의 관점은 특히 자기이해에 적용한다.
6. InBody의 '숫자보다 비교 관계'는 네 영역 점수에 적용한다.
7. Hogan의 '척도의 뜻 → 점수 해석 → 대화·성찰 질문'으로 고객에게 열린 결말을 제공한다.

따라서 기존 표지부터 순차 검토하던 제안보다 VII 공동 검토가 우선한다. 이전 표지 유지 제안은 사용자 합의로 간주하지 않는다. VII 이후 나머지 리포트와 실행프로그램을 검토하고, 합의 목록을 모아 일괄 개선한다.

근거: 제작규칙서 v2.0 §0.3, §1.1~1.5, 대원칙 A/B/C/D.

벤치마크는 목적을 바꾸는 모델이 아니라 전달 품질을 높이는 참고다. 성향을 분류하거나 점수를 설명하는 데서 멈추지 않고, 발견한 고유성을 선택·행동에 사용하고 경험과 결과를 남겨 다시 활용하고 나눌 수 있도록 연결한다.

## 3. 네 벤치마크: 배울 것 / 가져오지 않을 것 / 우리 식 적용

### 3.1 Gallup CliftonStrengths 34 — 개인화 해석을 활용과 주의점까지 잇기

- 관찰: 핵심 설명, 개인화된 해석, 활용 행동, 맹점을 연결한다. 반복되는 제목과 영역 색상이 읽는 순서를 알려 준다.
- 배울 것: '어떤 사람인가' 다음에 **어디에서 힘이 되는가 → 어떻게 활용하는가 → 어떤 상황을 조심할 것인가**를 연결한다.
- 가져오지 않을 것: 많은 테마와 장문의 반복, 고정된 강점 분류, 근거 없는 칭찬과 맹점 추정을 이식하지 않는다. 견본 문장·그래픽·검사 모델을 복제하지 않는다.
- 우리 식 적용: 압축된 고유성 한 문장 아래에서 이유·활용 조건·선택 기준을 풀고, 경험을 남겨 재사용할 방향까지 잇는다. 기존 카드 구조와 응답 정보는 보존한다.
- 주의점은 검사에서 확인된 사실과 성찰을 위한 가능성을 구분한다. 확인되지 않은 위험은 '당신의 맹점'으로 선언하지 않는다.

### 3.2 Birkman Signature — 평소 모습과 잘 작동하는 조건 구분

- 관찰: 평소 행동, 필요, 스트레스 상황의 행동을 구분하고 같은 맵 체계로 설명한다.
- 배울 것: **나는 무엇을 중요하게 여기는가**와 **어떤 조건에서 그 특성을 잘 사용할 수 있는가**는 서로 다른 질문이다.
- 가져오지 않을 것: Birkman의 사분면·심리 척도·욕구·스트레스 분류를 우리 검사 결과로 가장하지 않는다. 측정하지 않은 숨은 욕구나 스트레스 반응을 새로 단정하지 않는다.
- 우리 식 적용: 자기이해에서 선택 기준·반복되는 경험과 환경·리듬을 구분해 읽는다. 환경/리듬 응답이 있으면 그 근거 범위에서 사용하고, 없으면 열린 질문으로 남긴다.
- 타인이 보는 모습, 본인이 느끼는 모습, 필요한 조건을 동일시하지 않는다. 필요한 데이터가 없으면 차이를 측정했다고 쓰지 않는다.

### 3.3 InBody 770 — 수치의 크기보다 읽을 수 있는 비교 관계

- 관찰: 관련 지표를 묶고 공통 기준 구간과 막대그래프로 비교한다. 전체 결과지는 밀도가 높아 별도 해설이 필요하다.
- 배울 것: **무엇을 수치화했는지 → 무엇과 비교하는지 → 그 차이를 어떻게 읽는지**를 가까이 배치한다.
- 가져오지 않을 것: 신체 검사 기준, 정상/비정상 구간, 타인 대비 백분위, 진단 정확성을 우리 지수에 가져오지 않는다.
- 우리 식 적용: 네 영역을 동일한 표시 범위·기준선·일관된 라벨로 나란히 보여 주고 각 척도의 뜻을 함께 설명한다. 색에만 의미를 맡기지 않는다. 축을 잘라 작은 차이를 과장하지 않는다.
- 수치상 차이는 관찰할 수 있지만, 그것만으로 능력 차이·성장 잠재력·원인·실행 우선순위를 확정하지 않는다. 공통 0~100 표시가 네 구성개념의 심리측정적 동등성을 증명하지 않는다.
- 목표는 네 점수를 같게 만드는 균형이 아니다. 각 기능이 어떤 선택과 결과로 이어지는지 성찰하도록 돕는다. 근거 없는 평균·목표선·종합점수·우열 색상은 추가하지 않는다.
- 재검 비교는 같은 문항·채점 버전·조건 및 실제 이전 자료가 확인될 때 별도로 검토한다. 현재 한 번의 검사에서 성장 추세를 만들지 않는다.

### 3.4 Hogan HPI Insight — 척도의 뜻 → 점수 해석 → 대화·성찰 질문

- 관찰: 척도 정의, 백분위 해석, 대화 질문을 연결한다.
- 배울 것: 결과를 믿으라고 요구하지 않고 자기 경험과 대조하게 한다. **설명은 명료하게, 개인의 결론은 열어 둔다.**
- 가져오지 않을 것: 백분위·규준·척도 해석을 그대로 차용하지 않는다. 우리에게 없는 통계적 검증이나 전문 임상 자격을 암시하지 않는다.
- 우리 식 적용: 척도가 무엇을 나타내고 무엇은 말하지 않는지 밝힌 뒤, 해당 응답에서 읽은 내용을 제안하고, 맞는 경험과 맞지 않는 경험을 모두 확인하게 한다.
- 열린 결말은 '무엇이든 당신 생각대로'라는 모호함이 아니다. **확인할 경험 → 직접 선택할 다음 행동 → 남길 기록/결과**를 열어 두는 것이다.
- 질문은 검사에 동의하도록 유도하지 않는다. 예: '이 설명과 맞았던 때와 달랐던 때는 언제였나요? 조건이 무엇이 달랐나요?' 구체 질문은 페이지별 합의 후 확정한다.

## 4. VII 공통 읽기 흐름 — 조판·문구는 합의 전 후보

기존 요약 지면과 상세 카드의 구조를 우선 보존한다. 아래 여섯 기능을 여섯 새 박스로 추가하라는 지시가 아니다. 현재 위치별 역할을 명료하게 하고 정보 중복을 줄여 수용하는 설계 후보다.

| 기능 | 독자의 질문 | 자산화 연결 |
|---|---|---|
| 척도 설명 | 이 영역은 무엇을 나타내는가? | 무엇을 관찰할지 알기 |
| 나의 특징 | 내 응답에서 어떤 기준·패턴이 보이는가? | 고유한 선택 기준 발견 |
| 의미·조건 | 언제 도움이 되고 무엇이 달라지면 다르게 작동하는가? | 다시 활용할 조건 알기 |
| 활용 제안 | 지금 어떤 선택이나 시도를 할 수 있는가? | 살아낼 행동 선택 |
| 열린 확인 | 내 경험과 맞는가, 다른 사례는 무엇인가? | 본인의 판단으로 보완 |
| 남길 것 | 무엇을 남기고 다음에 어디에 쓸 것인가? | 경험·결과의 축적과 기여 |

### 영역별 편집 질문 (새 척도 정의가 아님)

- 자기이해: 반복되는 선택에서 어떤 기준을 발견했고, 그 기준은 어떤 조건에서 유효했는가?
- 자기표현: 발견한 의미를 누구에게 어떤 형태로 전달하며, 실제로 전달되었는지 어떻게 확인할 것인가?
- 자기설계: 무엇을 우선하고 무엇은 보류하며, 언제 마쳤다고 볼 것인가?
- 자기실행: 무엇이 행동을 시작·지속하게 하며, 실행 후 어떤 결과와 배움을 남길 것인가?

이 질문들은 편집 관점이다. 기존 문항이 각 내용을 모두 측정한다고 주장하거나 채점 정의를 몰래 변경하지 않는다.

## 5. 점수·개인화·전략의 세 층을 섞지 않는다

### 5.1 지수와 해석의 근거 확인

기준 소스: PR329의 main `f846be1b0d59ad0ba0805eba4a1482b9899224bb`.

- `assets/js/report-engine.js`의 `computeScores`: 리커트는 역채점 반영 후 `(값-1)/4`, 선택형은 선택이 있으면 `1.0`, 결측은 분모에서도 제외한다. 다축 문항의 가중치는 해당 축에 균등 분배하며 축별 가중평균을 0~100으로 표시한다.
- 이는 확인한 현재 코드의 계산 방식이다. 선택형 선택 유무가 지수에 반영되므로 이를 순수한 능력 점수·정답률·백분위로 설명하지 않는다.
- 이 코드 읽기는 고객 응답 재계산, 타당도·신뢰도 검증, 전체 데이터 파이프라인 실행 검증을 대신하지 않는다.
- 지수 시각화 전에 문항·가중치·분모·결측·역채점·선택형 기여·반올림·렌더 변환을 확인한다. 산식 변경은 이번 표현 개선과 분리해 별도 승인한다.

### 5.2 세 층

1. **관찰:** 본인 응답, 지수, 선택된 가치·조건 등 확인 가능한 내용.
2. **해석:** 응답 조합에서 도출한 특징과 가능한 의미. 규칙·출처와 연결한다.
3. **제안:** 어떤 역할로 활용할지, 무엇을 해 볼지. 현재 능력이나 성격의 확정 판정이 아니다.

`decideAxisRoles`는 lead/support/friction 등 전략 신호와 기본 배정으로 역할을 정한다. 따라서 '보완 설계' 역할만으로 낮은 능력·약한 고리를 입증할 수 없다. 높은 지수와 보완 역할이 공존하면 무엇을 보완한다는 뜻인지 설명 근거부터 검토한다. 역할 다양성을 위해 개인의 결함을 만들어 내지 않는다.

키워드·문장 변주가 다르다는 사실과 응답 의미에 근거한 개인화는 다르다. 해시로 문구가 달라지는 것만으로 숨은 심리나 실제 경험을 안다고 주장하지 않는다.

## 6. 축적·안전·정직의 경계

- 기존 좋은 구조·응답 정보·선택 민감도·프로그램 연결을 보존한다. 고유성 문장을 범용 격언으로 덮지 않는다.
- 문장 압축 시 대상·조건·근거가 사라지지 않았는지 확인한다. 민감도 검증과 독자 이해도 검증을 분리한다.
- 기존 정보의 **근거 없는 주장**이 발견되면 그대로 영구 보존해야 한다고 해석하지 않는다. 원문·이유를 기록하고 정정안을 사용자와 합의한다. 조용히 삭제하거나 새 사실을 만들지 않는다.
- 문서 기준 저장은 코드 변경·개인 리포트 재생성·구매권 변경·배포 승인이 아니다. Firebase 유지, 고객 DB 임의 조회/변경/삭제 금지.
- 기존 승인 V8·영상·음악·포스터·Shorts 자산을 변경하지 않는다. '해설서', '할 일과 완료 기준'을 유지한다.
- 자산화 로드맵을 현재 판매 범위로 오인시키지 않는다. 신규 다이어리 판매 보류·과거 계약 보존. 단체 기본은 개인 진단 1회·리포트 1부·본인 열람이며, 팀 결과·코칭·워크숍·연간 운영·미출시 AI를 끼워 넣지 않는다.
