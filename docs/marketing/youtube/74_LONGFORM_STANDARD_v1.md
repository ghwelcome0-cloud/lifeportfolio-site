# 롱폼 제작 기준 v1 (EP.05~10 「자산화 유형」 편에서 확정)

> 오너 판정 2026-10-14: 「이 수준이 앞으로의 기준」. 다음 롱폼은 이 문서와 `ep05_10_prep/pipe/` 도구로 같은 품질을 만든다.
> 앞 문서(71 제작 규칙, 72 크레딧 원칙, 80·73 회차 기록)를 대체하지 않고, 그 위에 올라간 최신 기준이다. 충돌하면 이 문서가 우선한다.

## 1. 무엇이 「기준 수준」인가
- 6~7분 다큐 롱폼, 1920×1080 30fps. 한 편 = 13문단 대본 · 18장면 · 실제 서비스 화면 4장.
- **모든 배경이 움직인다**: 미니어처 인형 장면 18장 → Seedance 2.0 fast 6초 영상. 앞으로만 재생(되감기 금지), 필요하면 천천히 다가가기.
- **실제 화면을 공간 안에 붙인다**: 빈 흰 태블릿 장면(A06)에 리포트 XI장을 추적해 붙이고(매치무브), 그대로 화면 안으로 들어간다.
- **실제 화면 클로즈업**: 리포트 XI장 · 12주 퀘스트 · 다이어리 4주/12주를 확대·이동·금색 테두리로 짚는다. 화면 표기 「실제 서비스 화면 · 예시 계정」, 장면 표기 「가상의 인물 · 설명용 시각화」.
- **다큐 표지**: 시간·장소 태그(「9주 차 · 써 보게 하기 · 오전 7:00 · 종자 저장고」), 이름 카드, 장 제목 11개(「EP.0N · k / 11」), 끝 카드.
- **자막**: 의미 단위 줄바꿈(subwrap v3.1) 검사 0, 화면 숫자는 아라비아, 「N주 차」 띄어 씀, 음성보다 1.0초 늦게 시작하는 SRT 별도 제공.
- **소리**: 내레이션 + 세계별 배경음악(92 BPM 계열, 편마다 악기) + 현장음 3종. 내레이션이 나오면 음악이 내려간다.

## 3. 순서 (병렬 / 순차)
**병렬(편 수만큼 동시에)**: 대본 → `split.py`(발음 점검 포함) → 녹음 → 받아쓰기 → `vo_prep.py`(동시 2편까지, 메모리) → 장면 영상 → A06 모서리 찾기 + `track.py` → 배경음악·현장음 → 화면(`screens/` + `cfg/0N_screens.json`) → `cfg/0N_render.json` → `dry.py` → 썸네일(`thumb.py`) → 업로드 정보(`meta.py`).
**순차(한 번에 한 편)**: `run_ep.sh 0N`(믹스 → 60초 조각 렌더 → 합치기 → 조각 즉시 삭제 → QA) → `finish_ep.sh 0N`(QA 표 · 저장소 커밋 · 업로드 링크 · 로컬 영상 삭제). 여러 편은 `chain3.sh` 방식으로 이어 붙인다.
- 렌더 속도: 60초 조각 약 8~9분, 한 편 약 65분 (4GB RAM / 2 CPU).

## 4. 편마다 바꾸는 것 (코드 수정 없이 설정 파일만)
- `cfg/0N_render.json`: 유형 이름·설명, 주인공 이름 카드, 장 제목 11개, 태그 7개, 「같은 변화」 2명 이름 카드, 카드 문구(three, assets).
- `cfg/0N_screens.json`: 다이어리 12주 기록 한 줄씩, 자산 카드 세 칸(무엇이 남았나 / 누가 다시 썼나 / 다음에 넓힐 곳).
- `cfg/thumbs.json`: 썸네일 3안 문구.
- `quads.json`: A06 태블릿 화면 네 모서리(1280×720 기준). 첫 프레임에서 흰 사각형 자동 찾기 후 눈으로 확인.
- 샷 타이밍은 대본 문장 순서로 자동 계산(`sn(문단, 문장)`)되므로 대본 구조(13문단)를 지키면 그대로 맞는다.

## 5. 크레딧 · 디스크 원칙
- 크레딧 드는 단계는 녹음·장면 영상·음악·현장음 생성뿐. 렌더·QA·썸네일·업로드 정보는 크레딧 0.
- Seedance가 SUCCESS인데 영상 주소가 비면 같은 요청을 한 번 더.
- 디스크 여유 2.5GB 이상에서 렌더 시작. 렌더와 다른 무거운 작업을 동시에 돌리지 않는다(2026-10-14 디스크 가득 참으로 EP.08 한 번 날림).
- 완성 영상은 업로드 링크를 받은 뒤에만 지운다.

## 6. 글·인물 원칙
- 「—」 금지, 사실만, 대비 구도 금지, 가격·「무료」 금지, 성경 인물 금지.
- 기업인은 남긴 것과 다시 쓴 사람만(매출·규모 금지). 돈 예시는 살림·관리만.
- 모든 인물은 가상 미니어처 인형.
- **인물 구성 (오너 2026-10-14)**: 성별·육아·인종·종교 같은 배경 다양성을 일부러 넣지 않는다. 고유성은 그런 것에 치우치지 않는다.
  - 주인공 = 그 유형을 온전히 대표하는 사람.
  - 「같은 변화」 2명 = 같은 유형의 **다른 직업·다른 방향**.
  - 장면 프롬프트에 군중의 국적·인종·복장 구성을 따로 지정하지 않는다.

## 7. 발음 원칙 (오너 2026-10-14, 다음 녹음부터 필수)

## 9. 이미지 속 글자 원칙 (오너 2026-10-14, 다음 제작부터 필수)
- 장면 그림·영상 안에 보이는 글자(간판, 칠판, 종이, 화면, 포스터 등)는 **정확한 한글 또는 정확한 영어**만 쓴다.
- 그 밖의 언어나 뜻 없는 가짜 글자(깨진 한글, 외계 문자 같은 낙서)는 쓰지 않는다. 특별한 이유가 있을 때만 예외로 하고, 대본에 그 이유를 적는다.
- 만드는 방법:
  - 글자가 꼭 필요한 곳은 프롬프트에 정확한 문구를 따옴표로 적는다(예: sign reads "골목 배경 묶음"). 한글 표기에 강한 모델을 쓴다.
  - 글자가 필요 없는 곳은 「no text, no letters, blank paper」로 비워 둔다. 뜻 있는 글자는 렌더 단계에서 화면 위에 덧씌운다(지금의 태그·카드 방식).
- 확인: 장면 18장 모아 보기에서 글자가 보이는 곳을 모두 짚어, 틀리거나 다른 언어면 그 장면만 다시 만든다. 영상으로 만든 뒤에도 첫·끝 프레임을 한 번 더 본다.
- 통과 기준 표에 추가: **이미지 속 글자 | 정확한 한글·영어만, 오류 0 | 모아 보기 눈 확인**.
