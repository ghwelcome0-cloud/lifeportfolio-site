## 1. 하이브리드 3D 모션이란 무엇인가 — 한 문장 정의

> **하이브리드 3D 모션 = 실제 촬영 영상(현실)과 3D CG(가상)를 "하나의 공간, 하나의 카메라, 하나의 빛" 아래 두어, 관객이 경계를 인식하지 못하게 만든 영상.**

핵심은 예쁨이 아니라 **공간(space)** 입니다.

### 1.1 슬라이드쇼와 하이브리드 3D를 가르는 단 하나의 기준 — 시차(Parallax)

카메라가 움직일 때,
- **슬라이드쇼**: 그림 전체가 통째로 확대/이동합니다. 앞의 것과 뒤의 것이 **같은 속도**로 움직입니다.
- **하이브리드 3D**: 가까운 것은 많이, 먼 것은 적게 움직입니다. 이것이 **시차**입니다.

사람의 뇌는 시차로 "깊이"를 판단합니다. 그래서 시차가 없으면 아무리 4K로 선명해도 **"평면 그림"** 으로 읽히고, 시차가 있으면 저해상도라도 **"공간"** 으로 읽힙니다.

**대표님이 기억하실 한 줄 판별법:**
> 카메라가 움직일 때 앞뒤가 **다른 속도**로 움직이는가? → 아니면 하이브리드 3D가 아니다.

두 번째 참고 영상 분석에서도 같은 결론이 나왔습니다.
> "A simple slideshow or 'quality improvement' cannot account for … This requires a **spatial understanding of the scene (3D geometry)** that goes beyond 2D image manipulation."

**① `-OHeRVGeiPQ` (대표님이 "최소 이 수준" 이라 지정)**

사진은 원래 평면인데, 3D 지형에 투사되면 시차가 생겨 공간이 됩니다. 즉 **가진 이미지 자산으로 하이브리드를 만들 수 있다**는 뜻입니다. 새 이미지를 더 예쁘게 뽑을 필요가 없습니다.

## 2. 왜 "AI 외 다른 도구"가 필요한가 — 두 영상의 비-AI 흔적

대표님 질문("AI 뿐만 아니라 다른 도구도 사용한다고 했잔아요?")에 대한 실측 답입니다.
분석 결과 두 영상 모두 **생성형 AI 로는 만들 수 없는 흔적**이 명확했습니다.

| 화면에서 보이는 것 | 필요한 도구 범주 | AI 로 안 되는 이유 |
|---|---|---|
| 흔들리는 옛 필름에 붙어 움직이는 3D 화살표 | **카메라 트래킹** (SynthEyes / Mocha / OpenCV) | AI 는 카메라의 실제 6자유도 운동을 수치로 못 준다 |
| 물살 흐름선, 파티클 | **시뮬레이션** (X-Particles / Houdini) | AI 는 물리 해를 계산하지 않는다 |
| 자갈·석재 층이 반복 배치된 단면 | **프로시저럴 지오메트리** (C4D Cloner / Blender Geometry Nodes) | AI 는 같은 요소를 규칙대로 N개 복제 못 한다 |
| 빨간 선이 스스로 그려지는 애니메이션 | **Trim Paths** (After Effects 벡터) | AI 는 프레임 간 선 길이를 정확히 제어 못 한다 |
| 3D 공간에 앵커된 텍스트 라벨 | **3D 트래킹 타이포** | AI 는 텍스트를 씬 좌표에 고정 못 한다 |
| 매 동작에 딱 맞는 목재/금속 타격음 | **폴리(Foley) 사운드 디자인** | 별개의 오디오 작업 |

**요약: AI 는 "재료(텍스처·배경·B-roll)"를 만들고, 비-AI 도구가 "공간과 운동"을 만듭니다.**
그동안 우리는 재료만 계속 좋게 만들었습니다. 그래서 지지부진했습니다.

## 3. 하이브리드 3D 만드는 5단계 — 대표님 학습용 파이프라인

두 영상 분석에서 공통으로 도출된 5단계입니다. 각 단계마다 **"제대로 됐다"의 판정 기준**을 붙였습니다.

### 1단계 — 카메라 트래킹 / 매치무브 (Match-Move)
**무엇**: 실사 푸티지에서 카메라가 어떻게 움직였는지 숫자로 뽑아낸다.
**왜**: 이 숫자를 3D 카메라에 그대로 먹여야 CG가 실사에 "붙어" 있는다. 이게 없으면 CG가 화면 위에서 미끄러진다(slipping).
**도구**: SynthEyes, Mocha Pro, Blender 트래커, **OpenCV**(우리 환경에 있음)
**합격 기준**: 트래킹 포인트를 실사에 올려놓고 재생했을 때, 포인트가 지면의 같은 자리에 **1픽셀도 안 미끄러진다**.

### 2단계 — 3D 구조 애니메이션 / Projection Mapping
**무엇**: (a) 반복 요소를 프로시저럴로 생성해 조립·해체시키거나, (b) 평면 이미지를 3D 지오메트리에 투사한다.
**왜**: 시차(§1.1)를 만드는 유일한 방법. 여기서 "슬라이드쇼 vs 하이브리드"가 갈린다.
**도구**: Blender Geometry Nodes, C4D Cloner/Mograph
**합격 기준**: 카메라가 좌우로 움직일 때 **앞의 요소와 뒤의 요소 이동량이 다르다**. 같으면 실패.

### 3단계 — 빛 일치 (Light Matching)
**무엇**: 실사 장면의 빛(방향·색온도·강도)을 3D 씬의 조명에 똑같이 세팅한다. 실사에서 뽑은 HDRI 를 쓰면 가장 정확하다.
**왜**: 인간의 눈은 "빛이 안 맞는 것"을 가장 먼저 알아챈다. 형태보다 빛이 먼저다.
**합격 기준**: 3D 오브젝트의 **그림자 방향이 실사의 그림자 방향과 같다**. 그리고 3D가 지면에 **접지 그림자(contact shadow)** 를 만든다. 접지 그림자가 없으면 오브젝트가 공중에 떠 보인다.

### 4단계 — 경계 은폐 (Seam Hiding) ← **가장 많이 빠뜨리는 단계**
**무엇**: CG 를 실사 쪽으로 "더럽힌다".
- **그레인 매칭**: 실사의 필름 그레인/노이즈를 CG에도 입힌다
- **대기 감쇠(Depth Grading)**: 먼 CG는 배경 색으로 살짝 흐려지게
- **라이트 랩(Light Wrap)**: 배경 빛이 CG 외곽을 살짝 감싸게
- **모션 블러**: 실사 셔터와 같은 정도로
**왜**: CG 는 기본적으로 **너무 깨끗하다**. 깨끗한 게 오히려 가짜로 보인다.
**합격 기준**: 프레임을 정지시켰을 때 **어디가 CG인지 즉시 지목할 수 없다**.
> 참고 영상 실측: "3D red lines are treated with Film Grain and Fast Box Blur to match the low resolution of the 1960s footage" — 일부러 화질을 **떨어뜨렸습니다.**

### 5단계 — 폴리 사운드 (Foley per Motion)
**무엇**: 화면의 **모든 움직임**에 실제 재질의 소리를 붙인다.
**왜**: 소리가 재질과 무게를 만든다. 소리 없는 CG 움직임은 "디지털 그래픽"으로, 소리 있는 CG 움직임은 "물체"로 인식된다.
**합격 기준**: 눈을 감고 들었을 때 **무엇이 움직였는지 알 수 있다**.

## 4. 우리 상황에 맞춘 실전 판단 — 무엇이 가능하고 무엇이 안 되는가

대표님께 정직하게 보고드립니다. 이상적인 파이프라인과 우리 실제 도구는 다릅니다.

| 5단계 | 이상적 도구 | 우리가 실제로 쓸 것 | 가능 여부 |
|---|---|---|---|
| 1. 매치무브 | SynthEyes / Mocha | **OpenCV 4.11** (설치 확인됨) — 광학 흐름/특징점 추적으로 카메라 운동 추정 | ✅ 가능 |
| 2. 3D 구조·투사 | Blender / C4D | Blender 미설치 → **NumPy + OpenCV 로 직접 원근 투사(homography) 계산** | ✅ 가능 (범위 제한) |
| 3. 빛 일치 | HDRI 렌더 | ffmpeg `colorbalance`/`eq` + 그림자 레이어 수동 배치 | 🟡 근사 가능 |
| 4. 경계 은폐 | Nuke / AE | **ffmpeg `noise`,`gblur`,`blend`,`displace`,`lenscorrection`** (전부 확인됨) | ✅ 가능 |
| 5. 폴리 | 사운드 라이브러리 | `elevenlabs/sound-effects` (모션별 개별 생성) | ✅ 가능 |

**결론: Blender 없이도 하이브리드 3D의 본질(시차 + 매치무브 + 경계 은폐)은 구현 가능합니다.**
핵심은 도구의 화려함이 아니라 **§1.1 의 시차를 실제로 만드는 것**입니다.

**우리가 쓸 대표 기법 — 2.5D Projection Parallax**
참고영상 ② `0:02–0:07` 과 동일한 원리입니다.
1. 이미지를 깊이 레이어로 분리 (전경/중경/배경)
2. 각 레이어를 3D 공간의 다른 Z 거리에 배치
3. 가상 카메라를 이동 → 레이어별로 **다른 이동량** 발생 = 시차
4. 레이어 경계를 그레인/블러로 은폐

이것은 순수 3D 렌더보다 가볍고, **우리가 이미 가진 125개 이미지 자산을 그대로 쓸 수 있습니다.**

## 6. 검수 체크리스트 — 하이브리드 전용 (기존 §10 에 추가)

기존 `PRODUCTION_STANDARD.md §10` 검수에 **아래 6항을 추가**합니다.

```
[ ] H-1 시차 검증    카메라 이동 구간에서 전경/배경 이동량이 다른가
                     (판정: 첫 프레임과 끝 프레임 겹쳐 놓고 전경·배경 변위 측정, 비율 ≥ 1.3:1)
[ ] H-2 슬립 검증    CG 요소가 실사 지면 위에서 미끄러지지 않는가 (1px 이내)
[ ] H-3 접지 검증    CG 오브젝트에 접지 그림자가 있는가 (없으면 공중부양으로 보임)
[ ] H-4 그레인 정합  CG 영역과 실사 영역의 노이즈 수준이 같은가 (정지 프레임에서 CG 지목 불가)
[ ] H-5 프레임 홀드  동일 프레임 연속 = 0 (P0-A 재발 방지)
[ ] H-6 폴리 동기    모든 CG 움직임에 소리가 있는가 · 오디오 트랙 중복 0 (P0-B 재발 방지)
[ ] H-7 깊이 가독성  ★ 소재에 윤곽 랜드마크가 있는가 (근경 에지밀도 ≥ 0.010)
                     — 시차가 수치상 존재해도 랜드마크가 없으면 관객은 평면으로 본다
```

**H-1 은 자동 판정 가능합니다.** frame N 과 frame N+k 사이 변위를 계산해, 원경과 근경의 평균 변위 비율을 재면 됩니다. 비율이 1.0 에 가까우면 = 통째로 움직인 슬라이드쇼 = 실패.

**⚠ 단 측정 방법에 함정이 있습니다 (실패에서 배움 · §9 참조).**

| 측정 방법 | 신뢰도 | 용도 |
|---|---|---|
| **구조 판정** `verify_layer_parallax` — 렌더러와 동일 변환식으로 레이어 화면변위 계산 | ★ 정본 | 텍스처 무의존. 항상 옳다 |
| **위상 상관** `measure_parallax_phase` — `cv2.phaseCorrelate` 로 영역별 변위 직접 측정 | ★ 정본 | 실제 픽셀 증거 |
| Farneback 광학흐름 `measure_parallax` | ✗ 판정 제외 | 평탄 영역에서 **거짓 0** 을 낸다 |

동일 렌더를 3가지로 측정한 실측값: 위상 **2.01x** / 구조 **2.29x** / Farneback **0.004x**. 앞의 둘은 일치하고 Farneback 만 틀렸습니다. 그래서 **Farneback 은 판정에서 빼고 보조 참고로만** 씁니다. 표본이 부족할 때는 '실패'가 아니라 **'판정 불가(indeterminate)'** 로 보고해야 정상 렌더를 잘못 반려하지 않습니다.

**★★★ H-7 이 왜 새로 필요했는가 — 이번 작업의 가장 중요한 발견**

성운 이미지로 렌더한 결과가 이랬습니다.

```
수치 판정 : 근경 110px / 원경 55px = 2.01x   →  시차 명백히 존재  ✅
사람 눈   : "reads as flat" · "완전히 정지된 것처럼 보인다"
            · "정지 이미지와 구별할 수 없다"                        ❌
```

둘 다 옳습니다. **시차는 실재하지만 보이지 않았습니다.** 원인은 시차 부족이 아니라 **기준 랜드마크의 부재**입니다. 사람은 "A 가 B 를 지나간다"로 깊이를 인식합니다. 지나갈 A, B 가 없으면 정확한 시차도 지각되지 않습니다.

⇒ **하이브리드 3D 소재는 반드시 윤곽이 뚜렷한 형태(건물·구조물·도형·인물 실루엣·격자)를 가져야 합니다. 안개·성운·그라디언트·추상 텍스처는 시차를 넣어도 헛수고입니다.**

실측 에지밀도(Canny 60/160, 근경 영역):

```
bg09_auto.png      near 0.0273  overall 0.0525   PASS  ← 데모에 채택
bg18_cta.png       near 0.0340  overall 0.0139   PASS
shorts_v2 base.png near 0.0186  overall 0.0151   PASS
bg16_diagnosis.png near 0.0009                   FAIL
bg13_galaxy.png    near 0.0000  (원경만 0.0420)   FAIL  ← "평면으로 보였던" 그 소재
기준 MIN_EDGE = 0.010
```

**★★ 그런데 H-7(에지밀도)만으로도 부족했습니다 — 한 단계 더 배웠습니다.**

에지밀도 PASS 소재(`bg09_auto.png`, 회로기판+금색 광선 그래픽)로 렌더해 구조 2.29x · 위상 2.18x · H-5 0 · H-7 PASS 로 **게이트를 전부 통과**시켰습니다. 그런데 사람 눈 판정은 다시 **"1/10 · flat image · 2D 슬라이드"** 였습니다. 실제 출력 프레임을 격자 블록매칭으로 직접 재보니 이렇게 나왔습니다.

```
y=   0- 256  median dx = 149.0 px   (상단 = 원경)
y= 256- 512  median dx = 187.5 px
y= 768-1024  median dx = 207.0 px   (하단 = 근경)
⇒ 실제 차등 이동은 존재했다 (1.39x). 그런데도 깊이로 읽히지 않았다.
```

**원인은 소재가 추상 그래픽이라는 것입니다.** 회로 패턴과 금색 광선은 에지는 많지만 **원근(perspective)이 없습니다.** 앞뒤 관계가 그림 자체에 없으므로, 차등 이동을 넣어도 관객의 뇌가 "앞의 것이 뒤의 것을 지나간다"로 해석할 근거가 없습니다. 즉,

> **에지가 많은 것 ≠ 원근이 있는 것.**
> 하이브리드 3D 소재의 진짜 조건은 **소재 자체에 원근이 있는가** 입니다.
> (수렴하는 직선, 크기가 줄어드는 반복 요소, 겹침(occlusion), 지면-수평선)

**소재 판정 3단 기준 (이 순서로 거르십시오)**

| 순서 | 기준 | 방법 | 실측 |
|---|---|---|---|
| 1 | 원근이 실재하는가 | 사람/모델 판정. 수렴선·겹침·지면이 있는가 | 건축 사진 통과 / 추상 그래픽 탈락 |
| 2 | H-7 에지밀도 ≥ 0.010 | `measure_depth_legibility` (초 단위) | 건축 사진 근경 **0.185** vs 회로 그래픽 0.017 |
| 3 | H-1 시차 ≥ 1.3x | 구조 + 위상(**신뢰도 ≥ 0.15**) | 아래 참조 |

**위상 신뢰도 하한 0.15 를 게이트에 추가했습니다.** 회로 그래픽 렌더의 위상 신뢰도는 `near 0.067 / far 0.026` — 거의 노이즈였는데도 비율만 보고 통과했습니다. 신뢰도가 낮으면 `status: low_confidence` 로 떨어뜨려 통과시키지 않습니다.

**★★★★★ 그리고 여기서 진짜 원인을 찾았습니다 — 엔진 자체의 버그였습니다.**

원근이 확실한 건축 사진(근경 에지밀도 **0.185**, 기존 소재의 10배)으로 다시 렌더했습니다. 이번에는 광학흐름이 처음으로 **신뢰 가능한 표본**(근경 30.7만 px / 원경 21.0만 px)에서 측정됐고, 그 값이 이렇게 나왔습니다.

```
구조식 계산값 (의도) : 2.29x
화면 실측 (결과)     : 1.017x   ← 시차가 사실상 0
```

**의도와 결과가 달랐습니다.** 원인은 `split_layers()` 였습니다.

> 레이어 분리 함수가 **모든 레이어에 원본 전체 이미지를 담고 알파만 달리 씌우는** 구조였습니다.
> 렌더 시 최원거리 레이어가 화면 대부분을 채우므로, 결국 **화면 전체가 '배경 속도'로 통째로 움직였습니다.**
> 구조식은 레이어의 z 값으로 계산했으니 2.29 를 냈지만, 그것은 **'의도'였을 뿐 '결과'가 아니었습니다.**

**⇒ 이것이 그동안 "품질만 좋아진 슬라이드쇼"가 반복된 기술적 뿌리입니다.** 소재 문제이기도 했지만, 엔진이 애초에 시차를 화면에 내지 못하고 있었습니다.

**해결 — 레이어 방식을 버리고 픽셀 단위 깊이 워프로 교체했습니다.**

```python
# render_parallax_depth()  ← 정본 렌더러
strength(d) = (1 - d) * PARALLAX_GAIN(1.45) + PARALLAX_BASE(0.30)
map_x = (x - cx) / z_eff + cx - dx * w * strength     # 픽셀마다 다른 변위
→ cv2.remap (backward warp)
```

픽셀마다 깊이에 비례한 변위를 주는 backward warp 입니다. 레이어 경계선도, 구멍(occlusion hole)도 생기지 않습니다.

**교체 후 실제 화면 블록매칭 실측 (같은 소재·같은 카메라):**

```
y=   0-256   상단(원경)  median dx = 155.0 px
y= 512-768   중간        median dx = 199.5 px
y= 768-1024  하단(근경)  median dx = 237.0 px
⇒ 깊이에 따라 단조 증가. 실측 비율 1.53x · 구조식 3.04x
   (이전 레이어 방식은 1.017x = 평면이었다)
```

**★ 대표님이 기억하실 원칙 하나 — "구조식이 아니라 화면을 믿는다."**
계산이 2.29 를 냈어도 화면에서 1.017 이면 그것은 실패입니다. 그래서 검수는 반드시 **렌더된 출력 프레임을 직접 재는 방식**(블록매칭·위상상관)이어야 하고, 공식 계산은 보조입니다. 이 원칙을 지키지 않았기 때문에 "수치는 통과인데 눈에는 평면"이 두 번 반복됐습니다.

**★★★★★ 두 번째 실패 — 깊이 워프는 건물을 녹였습니다.**

픽셀 깊이 워프로 교체해 화면 실측 155→237px(단조 증가)을 확인하고 렌더했습니다. 그런데 눈 판정은 또 **1/10** 이었습니다. 이번 사유는 완전히 달랐습니다.

> "석조 기둥과 창틀이 **S 자로 휘어진다**. 석재는 절대 휘지 않는다."
> "건물이 **녹는 것처럼** 보인다 — 카메라 무브가 아니라 고무판 왜곡(rubber-sheet warping)이다."
> "깊이 엔진이 기둥과 뒤쪽 벽의 간격을 인식하지 못하고 **하나의 탄성 천처럼** 취급한다."

**원인: 깊이맵이 추정값(가짜)이기 때문입니다.** 우리 `estimate_depth()` 는 수직 그라디언트·선명도·채도를 가중결합한 **휴리스틱**입니다. 진짜 깊이 모델(MiDaS 등)은 `torch` 가 필요한데 샌드박스에 없습니다. 부정확한 깊이맵으로 픽셀을 각각 다르게 밀면 **직선이 곡선으로 망가집니다.**

**★★★★★ 최종 해법 — 평면 투사(Projection Mapping / 호모그래피)**

참고영상 ② `0:02–0:07` 이 바로 이 기법이었습니다. **"사진을 3D 공간의 기울어진 평면에 붙이고, 그 평면 앞에서 카메라를 움직인다."**

```python
# render_projection_frame()  ← 최종 정본 렌더러
평면 코너 4점을 3D 로 놓는다 (화면 아래 = 카메라에 가까움, 위 = 멀음)
카메라를 dx, dy 만큼 움직여 4점을 원근 투영 → 새 4점
cv2.getPerspectiveTransform(원본4점, 새4점) → cv2.warpPerspective

# ★★★ 최종 확정값 (hybrid_core.py 라인 40~44 = 이 문서와 코드가 일치)
PLANE_TILT_DEG  = 60.0    # 42 → 54 → 60  (소재를 교체한 뒤 재스캔해서 확정)
PLANE_CAM_DIST  = 2.15
PLANE_FOCAL     = 2.05
PLANE_MOVE_GAIN = 2.4     # 4.2 는 텍스처 밖을 봐서 좌측 20% 가 늘어졌다
PLANE_SAFE_ZOOM = 1.60    # 1.10(하드코딩) → 1.42 → 1.60
```

> **★ 42 → 54 → 60 의 이력을 남기는 이유:** 54 는 **잘못된 소재**(정면 파사드)로 스캔해서 나온 값이고, 60 은 **올바른 소재**(후퇴 평면)로 재스캔해서 나온 값입니다. 즉 **파라미터는 소재에 종속됩니다.** 소재를 바꾸면 파라미터도 다시 스캔해야 합니다(`/tmp/scan_plane.py` 로 22초).

**왜 이것이 정답인가 — 세 가지 결정적 이유**

1. **호모그래피는 직선을 직선으로 보존합니다** (수학적 성질). 따라서 **기둥이 휘는 일이 원천적으로 불가능**합니다. 깊이 워프의 실패 모드가 구조적으로 제거됩니다.
2. **깊이 추정에 의존하지 않습니다.** 가짜 깊이맵이 원인이었으므로, 깊이맵을 아예 쓰지 않는 방식이 옳습니다.
3. **기울어진 평면이므로 아래쪽(가까움)이 위쪽(멀음)보다 실제로 더 많이 움직입니다** = 진짜 원근 시차.

```
                         (cv2.matchTemplate TM_CCOEFF_NORMED, 응답 0.55 이상만 채택)
```

**대표님이 기억하실 문장:** **"공식이 아니라 화면을 믿는다."** 이 원칙을 세우기까지 실패가 세 번(레이어·깊이워프·부호) 필요했고, 그 세 번 모두 **수치는 통과했는데 눈은 평면이라고 답한** 경우였습니다.

**소재 선정은 렌더 전에 초 단위로 끝냅니다.** 3초 클립 렌더가 약 60초이므로, 소재 후보 33개의 에지밀도를 먼저 일괄 측정(약 10초)해 통과 소재만 렌더하는 것이 정답입니다. 이 순서를 지키지 않으면 렌더를 돌린 뒤 반려되는 낭비가 반복됩니다.

## 7. 대표님이 기억하실 7줄 요약

1. **하이브리드 3D 는 "예쁨"이 아니라 "공간"이다.** 이미지 품질을 올려도 하이브리드가 되지 않는다.
2. **판별법은 시차 하나.** 카메라가 움직일 때 앞뒤가 다른 속도로 움직이면 하이브리드, 통째로 움직이면 슬라이드쇼.
3. **AI 는 재료를, 비-AI 도구는 공간과 운동을 만든다.** 매치무브·시뮬레이션·프로시저럴은 AI 로 대체 불가.
4. **가장 많이 빠뜨리는 단계는 4단계(경계 은폐)** 다. CG 를 일부러 더럽혀야 진짜가 된다.
5. **하이브리드는 전 구간이 아니라 결정적 3초에 쓴다.** 참고영상도 3초였다.
6. **★ 공식이 아니라 화면을 믿는다.** 구조 계산이 2.29 를 내도 화면 실측이 1.017 이면 실패다. 우리는 이걸 세 번 겪고 나서야 화면 실측(H-8)을 최종 판정으로 세웠다.
7. **★ 렌더러를 고치기 전에 소재의 기하를 보라.** 세 세대에 걸쳐 코드를 고쳤지만 마지막 벽은 코드가 아니었다. **후퇴하는 평면(길·바닥·회랑)이 있는 사진** 한 장이 코드 수정 열 번보다 결정적이었다. 정면 파사드 사진으로는 이 기법이 원리적으로 안 된다.
