## 2. 롱폼 제작 원리 (EP.02에서 확인됨)
1. **대본 → 단일 테이크 음성 → 단어 단위 타임스탬프(scribe_v2)** 순서로 진행한다.
   - 모든 화면 전환과 강조를 단어 시각에 묶는다. 함수 `at(구간, '구절')`이 그 시각을 찾는다.
   - 숫자는 TTS 원고에 한글로 적는다(백삼십팔). 화면에는 아라비아 숫자로 합성한다.
2. **화면 종류 2가지**
   - plate(AI 배경): 카메라가 멈추지 않게 계속 확대·이동하고, 먼지 입자를 넣는다. → 다음 회차부터는 Seedance 영상으로 교체.
   - screen(실제 서비스 화면): 키프레임 확대·이동, 해당 칸 주변을 어둡게 하고 금색 테두리를 두르며, 책장 넘김 전환을 쓴다.
3. **연구 카드**: 숫자·출처를 결정론 합성 카드로 띄운다. AI 이미지 안에 글자를 넣지 않는다.
4. **장 제목**: 반투명 판에 「EP.02 · nn / 17」과 제목. 상단 좌측 브랜드, 우측 표시는 장면 종류에 따라 자동으로 바뀐다(설명용 시각화 / 실제 서비스 화면).
5. **자막**: 어절 단위로 균형 있게 2줄을 넘지 않게 나눈다. SRT 시각은 영상 시작 오프셋(+1.0초)과 맞춘다. EP.02에서 이 오프셋이 한 번 누락된 실수가 있었다.
6. **끝화면** 10초: 다음 행동 하나(홈페이지 맨 위 › 내 다이어리)만 보여 준다.
7. **QA 게이트**(전부 자동으로 측정):
   - 멈춤(freezedetect 1.5초) 0회
   - 2초 창 광류 p95 합계 ≥ 1.5px (EP.02 최소 7.1)
   - 전체 디코드 오류 0
   - 음량 측정
   - 최종 음성을 다시 받아쓰기해 원고와 비교
   - 22컷 장면 모음

## 3. 숏츠 제작 원리
- **첫 1~2초가 승부**(대표 동의).
  - 0초 화면에 질문 문구만 큰 글씨로 보여 준다. 로고·고지문·인트로는 첫 화면에 두지 않는다.
  - 첫 음절이 잘리지 않도록 음성은 0.25초 뒤에 시작한다. EP.02 v1에서 '적'이 거의 안 들린 결함의 원인이었다.
  - 첫 문장은 필요하면 따로 재녹음해 붙인다.
- **진행 칩(1/2/3)과 숫자 카운트업**으로 "몇 개 중 몇 번째"를 계속 보여 줘 끝까지 볼 이유를 만든다.
- **자막 위치**는 화면 높이 68% 부근에 둔다. 하단 약 20%는 숏츠 버튼·설명 영역이라 비운다.
- **길이**: 업계 자료상 25초 이하가 유리하다. 다만 근거 3개를 다 담으려면 37초가 필요해 이 길이로 정했다. 다음 회차에서 25초판과 비교한다.
- **AI 배경 영상 만드는 법**:
  - GPT Image 2로 9:16 정지 이미지를 만든다. 롱폼 정지 이미지를 참고 이미지로 넣어 같은 세계관을 유지한다.
  - Seedance 2.0 fast(720p, 6초, 오디오 끔) i2v로 영상화한다.
  - 프롬프트에는 "물체가 실제로 움직임(책자가 빠져나옴, 책장이 넘어감) + 느린 카메라, 사람·손·글자 없음"을 넣는다.
  - 6초보다 길게 써야 하면 핑퐁 반복 + 감속(0.5~0.75배)으로 늘린다.
- **판정 기준**(게시 후 24~48시간):
  - 시청 vs 스와이프 70% 이상, 평균 시청 비율 70% 이상
  - 스와이프 비율이 50%를 넘으면 훅을 교체한다.
  - ※ 업계 경험칙이고 YouTube 공식 기준은 아니다.
- **연결**: 관련 동영상 = 롱폼. 링크에 숏츠 전용 UTM(`utm_medium=shorts`)을 붙인다.

## 4. 썸네일 원리
- YouTube 공식(answer/16391400):
  - 최대 3안까지 동시에 시험할 수 있고, 승자는 **시청 시간 점유율**로 정한다.
  - 비슷한 안끼리는 결론이 늦게 나니 확실히 다른 안을 시험한다.
  - 1280×720 미만 안이 하나라도 있으면 전체가 480p로 낮아진다.
- 이번 3안은 서로 다른 약속을 건다.
  - V1 「NEW 출시 / 내 다이어리」: 이름
  - V2 「리포트가 다이어리로」: 변화
  - V3 「1년을 담는 나만의 한 권」: 결과물
- V1을 기본안으로 올리고 시험 순서 맨 앞에 둔다(무승부일 때 첫 안이 적용됨).
- 휴대폰 목록 크기(246×138)로 줄였을 때 글자가 읽히고, 글자와 카드가 겹치지 않는지 확인한다.

## 5. 기술 함정 (재발 방지)
| 증상 | 원인 | 대책 |
|---|---|---|
| 렌더 중 샌드박스가 멈추거나 OOM | ① float32 풀HD 프레임 290장을 메모리에 미리 올림 ② 예전 일괄 작업 스크립트(`run.sh`)가 리셋 뒤에도 살아남아 다시 실행됨 | 프레임은 uint8로 보관하고 `cv2.addWeighted`로 섞는다. 렌더는 18초 단위로 나눠 **하나씩 차례로** 실행한다. 리셋 뒤에는 `pgrep -fa "python3\|ffmpeg"`부터 확인하고, 안 쓰는 스크립트는 이름을 바꿔 막아 둔다 |
| `pkill -f "패턴"`이 내 셸까지 종료 | 셸 명령줄에도 같은 패턴이 들어 있음 | PID를 직접 확인한 뒤 `kill PID` |
| AI Drive 파일을 curl로 받으면 59바이트 JSON | 인증 래퍼 URL | `DownloadFileWrapper`를 쓴다 |
| loudnorm JSON 파싱 실패 | stderr에 진행 로그가 섞임 | `-nostats` + `"input_i"`를 포함하는 `{…}`만 정규식으로 뽑는다 |
| 받아쓰기에서 '인생 코트폴리오' | 발음이 흐리거나 인식 오류일 가능성 | **다음 회차에서 개선 예정(대표 결정)**. 브랜드명은 따로 녹음하거나 발음 사전 사용을 검토 |
| params에 기본 화자 이름 표기(Samara/Hope) | 도구 표시일 뿐 실제 목소리는 custom_voice_id | 대표 청취로 확인했다. 표시는 무시한다 |
