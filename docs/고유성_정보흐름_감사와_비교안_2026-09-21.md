# 고유성 정보흐름 감사와 관계 기반 비교안

- ID: LP-UNIQUENESS-AUDIT-01 / v1.1 / 2026-09-21
- 기준: PR330의 생성 엔진(이후 PR331에서도 불변) / LP-UNIQUENESS-01 v1.1
- 상태: §1~5는 기존 276회 탐색 이력이다. 조건부 20개 동적·생성·표시 후속 감사는 별도 [56+20 감사와 수정 계약](조건부입력_56plus20_감사와_수정계약_2026-09-21.md)을 따른다. 새 개인화 모델의 구현·심리측정 검증·운영 배포는 아님.
- 재현: `node scripts/audit-four-axis-information.cjs <출력.json>`
- 고객 계정·원응답은 조회하지 않았다. 이하 사례는 실제 문항 선택지를 이용한 가상 비교다.

## 1. 관측 범위

본문항 56개, 조건부 기타 입력 20개의 명세를 목록화했다. 세 합성 입력에서 값 교체·두 번째 선택 교체·선택 순서만 교체를 합쳐 276회 실행했다. 조건부 기타 20개는 구조 목록만 확인했으며 부모/기타 활성화 계약의 동적 검증은 별도다.

같은 입력으로 두 번 실행한 감사 JSON은 바이트 동일했다. 입력/리포트 불변과 키워드 보존을 확인한다. 질문마다 응답 하나를 바꿔 보는 탐색이므로 사람 전체의 의미·타당도나 모든 조합을 검증한 것으로 확대하지 않는다.

| 층 | 이번에 관측한 것 | 관측으로 말할 수 없는 것 |
|---|---|---|
| 문항·명세 | 56개 본문항과 20개 기타 매핑 목록 | 구성개념을 충분히 측정한다는 증명 |
| 응답→점수 | 같은 입력에서 특정 값 변경이 축 지수에 미친 차이 | 객관적 능력이나 백분위 |
| 응답→전략 source | 복수 값이 source의 어느 필드에 남는지 | source 저장만으로 고객이 그 차이를 이해한다는 증명 |
| source→koCoords | 대표값·두 번째 값의 보존 여부 | 추출 값의 우선순위가 사용자 의도라는 증명 |
| 엔진→VII 표시 | 엔진 문장과 강조 문장/설명/키워드의 민감도 | 모든 지면의 실제 렌더나 실행 적합성 |

## 2. 재현 결과

- 강조 문장의 변화가 관측된 본문항: **Q6·Q39·Q63·Q73**.
- 설명 문장의 변화가 관측된 본문항: **Q39·Q47·Q49**.
- 같은 선택 집합의 **순서만 바꿔도** 강조 문장이 달라진 문항: **Q6·Q39·Q63**.
- 두 번째 선택을 바꾼 54회에서는 VII 강조 문장·설명 변화가 관측되지 않았다. 다른 키워드·엔진 결과·섹션 payload가 달라진 경우는 존재한다.
- 이 결과는 나머지 문항이 서비스 전체에서 사용되지 않는다는 뜻이 아니다. VII의 특정 표현층에서 변화가 보이지 않았다는 뜻이다.

### 보존되는 곳

- Q63의 복수 기준은 전략 `source.compass`에 남고 `koCoords.compass1`도 존재한다.
- Q6/Q39의 복수 값은 source에 남는다. 다만 Q6 계열 `strengthTraits`에는 합성 추론 성향도 합쳐질 수 있어, 이를 모두 직접 응답으로 표시하면 안 된다.
- 지수·고유코드·엔진 결과는 이번 감사로 변경되지 않는다.

### 일부 압축되거나 표현에 드러나지 않는 곳

- 표시 헬퍼 `axisReaderView`의 자기이해 핵심은 `compass0`, 자기표현은 `actShort`, 자기설계는 `doneWord`, 자기실행은 `trait0` 중심이다.
- `compass1`이 달라져도 자기이해 강조 문장·설명에는 나타나지 않는 사례가 있다.
- Q6/Q39의 두 번째 값을 바꾸면 엔진 핵심 문장은 달라지는데, 표시 헬퍼가 이를 같은 대표 문구로 덮어 차이를 지우는 사례가 있다.
- Q6/Q39/Q63은 명시적인 순위 입력 문항이 아니다. 실제 저장 순서·표시 순서를 추가 감사하고, 순위 질문 없이 `[0]`을 최우선이라고 해석하지 않는다. 기존 고유코드를 바꾸지 않고도 신규 표시 표현의 의미 순서 독립성을 설계할 수 있으나, 별도 버전/검증이 필요하다.

### 애초에 충분히 묻지 못하는 후보 영역

56개 질문의 문면 검토 기준이다. 경험 관련 문항이 전혀 없다는 뜻은 아니다. Q7/Q14/Q19/Q21 등은 상황·전환·회복의 단서를 묻지만 아래 구체적인 관계를 모두 직접 묻지는 않는다.

1. **누구의 어떤 문제를 돕고 싶은가:** 관심 분야(Q75/Q77)와 구체적 수혜자·과제는 다르다.
2. **가치가 충돌할 때 실제로 어떤 선택을 했는가:** 기준 선택(Q63)과 우선순위/상충 사례는 다르다.
3. **같은 강점이 잘 작동한 때와 막힌 때의 조건은 무엇인가:** 선호 환경(Q47/Q49)과 실제 성공·실패 조건의 비교는 다르다.
4. **남긴 결과를 타인이 실제로 사용했는가:** 성취감(Q73)과 도움·재사용이 확인된 사실은 다르다.

이 빈칸을 생성 문장으로 채우지 않는다. 후속 확인 질문이나 실행 후 회고에서 수집하는 것이 적절한지 먼저 검토한다. 56문항을 무조건 늘리는 안이 아니다.

## 3. 승인된 지면 위에서 비교할 후보

개념 한 줄 → 강조 문장 → 짧은 설명 → 기존 키워드 → 활용 제안 → 열린 질문의 현재 구조를 유지한다. 아래는 문구 풀이 아니라 근거 관계를 검토하기 위한 후보이며, 자동 생성기의 완성본이나 사용자 본인에 대한 해석이 아니다.

### 자기이해: 첫 기준이 같아도 함께 고른 기준은 다르다

가상 A의 Q63: 의미/보람/가치 + 안정성/안전/예측 가능성.
가상 B의 Q63: 의미/보람/가치 + 성장 가능성/배움의 기회.

- 현재 두 경우에 가능한 동일 핵심: ‘선택의 순간, 뜻이 남는 쪽에 마음이 향합니다.’
- A 비교 후보: **선택의 의미와 이어 갈 기반을 함께 살핍니다.**
- B 비교 후보: **선택의 의미와 배움의 여지를 함께 살핍니다.**
- 설명: ‘함께 선택한 기준을 연결한 해석입니다. 두 기준이 실제 선택에서 어떻게 작용했는지 경험과 대조해 보세요.’
- 열린 질문: ‘두 기준이 서로 다른 선택을 가리켰던 때, 나는 어떻게 결정했나요?’

둘 사이의 우선순위·갈등·심리 상태를 단정하지 않는다. ‘A를 위해 B를 포기한다’ 같은 주장은 실제 근거가 있어야 한다.

### 자기표현: 관심 활동만이 아니라 실제 표현 단서를 함께 본다

가상 A의 Q28: 감정을 솔직하게 말하는 편 / Q33: 정직·신뢰.
가상 B의 Q28: 감정을 행동으로 전달하는 편 / Q33: 배려·경청.

- A 비교 후보: **솔직한 말로 뜻을 전하고, 신뢰로 이어지는지 돌아봅니다.**
- B 비교 후보: **듣고 살피는 태도에, 행동으로 마음을 보태 봅니다.**
- 이때 Q28은 ‘다른 사람이 이렇게 말한다’는 본인의 응답이지 타인 평가를 직접 수집한 자료가 아니다. 설명에서 이 한계를 유지한다.
- 전달 능력이 검증됐다고 쓰지 않는다. 상대가 어떻게 이해했는지 경험 확인을 제안한다.

### 자기실행: 성향 한 단어보다 시작·지속·완료 조건

Q55의 시작 동기, Q57의 지속 이유, Q71의 실행 방식, Q73의 성취 기준과 Q47/Q49의 환경·리듬을 근거층에서 구분한다. 하나의 성향을 문장 머리에 붙이는 것만으로 실행 개인화를 완료하지 않는다.

미측정 대상·경력·실제 성과는 채우지 않는다. ‘나를 움직이게 하는 조건’과 ‘끝까지 이어 가게 하는 조건’이 같거나 다른지를 근거 범위에서 설명하고, 적절한 한 가지 실천을 제안하는 안을 비교한다.

## 4. 다음 구현의 순서

1. **근거 계약:** 직접 응답/추론/제안, 무순위 복수 선택, 결측, 기타 입력, 출처·버전을 분리한 중간 표현 설계.
2. **기존 데이터 감사:** 저장 report의 source만으로 충분한 근거와 원응답이 필요한 근거를 구분. 추론 성향을 직접 응답처럼 쓰지 않기.
3. **대조 가능한 후보:** 우선 Q63 복수 기준과 자기표현의 직접 단서부터 기존 지면에서 비교. 새 질문 없이 보존 가능한 정보 먼저 활용.
4. **반례 검증:** 두 번째 선택 변경·순서만 변경·정보 누락·같은 직업/다른 근거·같은 응답/다른 이름. 임의 동의어 변주는 성과로 세지 않기.
5. **독자/내용 검토:** 문장이 과잉 해석인지, 고객이 뜻과 근거를 설명하고 다음 행동을 고를 수 있는지 확인.
6. **별도 승인·버전:** 채점·문항 수정이 필요한 경우 이유와 영향 범위를 제시. 기존 고객 저장본에 일괄 소급 적용하지 않기.

## 5. 이번에 함께 발견·수정할 주변 정합성

- 해설서에 남은 점수 카드·%·단계 라벨 안내를 현재 VII 구조로 맞추고, 실행 역할을 공통 교육용 뜻과 한계로 설명한다.
- 같은 직업을 같은 자산화 경로로 취급하지 않도록 해설서의 역할을 명료하게 한다. 자동 모델이 이미 충분히 구현됐다는 뜻으로 쓰지 않는다.
- 최초 방문의 통계 동의 버튼을 공통 도움 위젯이 가리는 현상은 레이어 순서 문제다. 동의 정책 자체를 바꾸지 않고 버튼 접근성을 복원한다.
- 개별 수정의 검증/PR/배포 상태는 작업 기록을 따른다. 문서 등재만으로 운영 반영을 주장하지 않는다.
