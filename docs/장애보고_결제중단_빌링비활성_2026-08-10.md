### 왜 하필 결제가 죽는가
Cloud Functions 는 유료(Blaze) 플랜 전용이다. 빌링이 꺼지면 **함수 전체가 기동 불능**이 된다.
그리고 우리 결제는 `getPaypleClientConfig` 로 결제 키(clientKey)를 받아야 버튼이 켜지는 구조이므로,
함수가 죽으면 **버튼이 영구 회색**이 된다.

또한 코드에는 예산 초과 시 빌링을 스스로 끄는 장치가 **없다**(`disableBilling`·`cloudbilling` 참조 0건).
즉 자동 차단이 아니라 **청구 계정 쪽 사유**(카드 만료 · 결제 실패 · 청구 계정 해지/이탈)로 봐야 한다.

## 3. 대표님 복구 절차 (약 3~5분 · 복구 후 함수는 자동 재기동)

1. https://console.cloud.google.com/billing/linkedaccount?project=lifeporfolio 접속
2. 「결제 계정 연결(Link a billing account)」 확인
   - 연결이 끊겨 있으면 → 기존 계정을 다시 연결
   - 연결은 있는데 정지 상태면 → 결제 수단(카드) 갱신
3. 흔한 사유: **카드 만료 · 해외결제 차단 · 한도 초과 · 미납**
4. 복구 후 **2~5분 대기**(전파 시간). 함수 재배포는 필요 없다.
5. 확인은 아래 게이트로 한다(제가 만든 검사).

```bash
cd /home/user/webapp && LP_LIVE=1 node /home/user/baseline/g29_payment_live_gate.js
```
- `live_reachable: ok` → **결제 복구 완료**
- `live_reachable: FAIL · HTTP 503` → 아직 미복구

간단 확인만 원하시면:
```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST \
  https://asia-northeast3-lifeporfolio.cloudfunctions.net/getPaypleClientConfig \
  -H 'Content-Type: application/json' -d '{"data":{}}'
```
- **401** = 정상(함수 살아 있음 · 인증만 없음) → 결제 가능
- **500/503** = 아직 장애

## 4. 제가 배포한 처방 (커밋 `bbf2f51`)

프런트에서 결제를 되살릴 방법은 없다. 그래서 **할 수 있는 두 가지만** 했다(성공 경로 무변경 · 추가이지 교체가 아님).

1. **자력 회복** — 설정 로드를 3회 재시도(1.2초·2.4초 간격). 일시적 지연이면 고객이 아무 것도 안 해도 버튼이 켜진다.
2. **정직한 안내** — 회복 불가 시 아래 문장으로 바꿨다.

> 지금은 결제 서버에 연결되지 않아 결제를 진행할 수 없습니다.
> **고객님 기기나 결제수단 문제가 아니며**, 저희 쪽에서 확인하고 있습니다.
> 잠시 후 **새로고침** 해주시거나, 급하시면 faise@lifeportfolio.co.kr 로 알려주세요. 불편을 드려 죄송합니다.

- 내부 오류코드(`functions/internal`)는 **더 이상 고객 화면에 노출하지 않는다**. 고객에게 "internal" 은 아무 정보가 아니다.
- 빌링이 복구되면 이 안내는 사라지고 **버튼이 즉시 켜진다**(G29 성공 경로 검사로 실측 확인).

## 5. 재발 방지 — G29 게이트 신설

이번 장애는 **어떤 게이트에도 걸리지 않았다**. D-4 86항목부터 G28 까지 전부 '지면(리포트·프로그램)'만 본다.
고객이 돈을 내는 경로는 **측정 대상 자체가 아니었다**.

`/home/user/baseline/g29_payment_live_gate.js` — 13검사 0실패

| 축 | 검사 |
|---|---|
| 코드(항상) | 성공 시 버튼 켜짐 · 성공 시 재시도 안 함 · clientKey 누락 시 잠금 · 2회 실패 후 회복 · 영구 장애 시 잠금 · 3회 재시도 · 안내 노출 · **내부코드 미노출** · 문의 경로 · 고객 탓 문장 아님 · 재시도 버튼 배선 |
| 라이브(`LP_LIVE=1`) | `getPaypleClientConfig` 도달 가능(401=정상 / 5xx=장애) |

게이트는 `product-v2.html` 의 실제 블록을 절취해 구동한다. 추측하지 않으며, 소비처가 바뀌면 게이트도 따라간다.

### 결함 대장 등재 — (BS)
> **어떤 게이트도 '고객이 돈을 내는 경로'를 재지 않았다.**
> 리포트 지면 품질은 86+항목으로 재면서, 매출이 발생하는 결제 경로는 측정 대상 밖이었다.
> 라이브 결제가 멈춘 동안 모든 게이트는 초록불이었다. (결함 BL 계열 — 측정 대상 자체를 빼면 영원히 초록불이다)
