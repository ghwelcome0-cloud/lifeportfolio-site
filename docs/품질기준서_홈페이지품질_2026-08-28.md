## §0 한 문장 요약

지금까지 ⑥축은 **우리가 만든 잣대**로만 재고 있었다. 이 문서는 그 잣대를 **밖에서 이미 인정받은 기준**(구글·W3C·한국 법정)으로 바꿔 끼우고, 그 기준들이 다루지 못하는 **"아름다움"** 층을 새로 세운다.

**v1.1 에서 달라진 것 한 줄:** ㉮ 기능층이 **"전량 미측정" → "Lab 실측 24/24 통과"** 로, ㉯ 터치 타깃이 **"미측정" → "3점(실측)"** 으로 바뀌었다. 그리고 손님이 사람만이 아니게 되었으므로 **㉱ 에이전트 상호운용층**을 4번째 층으로 신설했다(§5-5, 전 항목 미측정 상태로 정직 등재).

⚠️ 다만 ㉮ 는 **Lab 측정**이며 Google 정본이 요구하는 **p75 필드 측정이 아니다**. "CWV 통과"로 줄여 인용하면 안 된다(§10 자기 반박 1번).

## §1 왜 4층인가 — 중학생 눈높이 설명

건물 검사를 생각해 보자.

| 층 | 비유 | 무엇을 보장하나 | 무엇을 보장 **못** 하나 |
|---|---|---|---|
| ㉮ 기능층 | 엘리베이터가 안 멈추고 잘 도는가 | **빠르고 안 튄다** | 예쁜지는 모른다 |
| ㉯ 접근층 | 휠체어 경사로·점자 블록이 있는가 | **아무도 못 들어오지 않는다** | 예쁜지는 모른다 |
| ㉰ 미학층 | 들어선 순간 "좋은 곳이네" 하는가 | **신뢰와 호감** | 규격은 안 본다 |
| **㉱ 에이전트층** | **건물 앞에 기계가 읽을 수 있는 안내판이 있는가** | **사람이 아닌 손님(AI)도 우리를 찾을 수 있다** | 사람 눈에 좋은지는 모른다 |

㉮㉯ 만 채우면 "감점이 없는 건물"이 된다. **감점이 없다는 것과 훌륭하다는 것은 다른 말이다.**
대표님 지시가 정확히 이 지점을 찔렀다. 그래서 ㉰ 미학층을 새로 만들었다.

그리고 v1.1 에서 층이 하나 더 늘었다. 예전에는 홈페이지를 보는 손님이 **사람**뿐이었지만, 이제는 **AI 에이전트**도 손님이다. 사람이 직접 찾는 대신 AI가 대신 웹을 읽고 판단하는 일이 늘고 있다. **기계가 우리를 읽을 수 없으면 그 손님에게는 우리가 없는 것과 같다.** 그래서 ㉱ 에이전트 상호운용층을 신설했다(§5-5).

## §2 ㉮ 기능층 — Core Web Vitals (구글 공인)

### 2-1. 정본 출처

| 항목 | 내용 |
|---|---|
| 정본 URL | **https://web.dev/articles/vitals** |
| 발행 주체 | Google (web.dev 공식) |
| 최종 갱신 | 2024-10-31 |
| 확인 방법 | 원문 크롤링 후 임계값 직접 확인 (2026-08-28) |

### 2-2. 임계값 (원문 그대로)

| 지표 | 뜻 (중학생 눈높이) | Good | Needs improvement | Poor |
|---|---|---|---|---|
| **LCP** (Largest Contentful Paint) | 화면에서 가장 큰 덩어리가 다 뜨는 시각 = "언제 페이지가 보였나" | **≤ 2.5초** | 2.5~4.0초 | > 4.0초 |
| **INP** (Interaction to Next Paint) | 눌렀을 때 반응이 화면에 나타나기까지 = "언제 반응했나" | **≤ 200ms** | 200~500ms | > 500ms |
| **CLS** (Cumulative Layout Shift) | 읽는 중에 글이 밀려나는 정도 = "안 튀나" | **≤ 0.1** | 0.1~0.25 | > 0.25 |

### 2-3. 측정 규약 (여기가 핵심 — 안 지키면 거짓 초록불이 된다)

원문이 못 박은 3가지:

1. **75th percentile (p75)** — 평균이 아니다. 방문자를 느린 순서로 줄 세워 **아래 75%가 통과**해야 한다. 평균으로 재면 빠른 기기 몇 대가 느린 기기를 가려 버린다.
2. **mobile / desktop 분리** — 합치지 않는다. 우리 ⑥축의 "PC·모바일 각각 채점하고 낮은 쪽을 점수로 쓴다" 원칙과 방향이 같다.
3. **세 지표 전부 통과해야 pass** — 두 개 좋고 하나 나쁘면 실패다.

### 2-4. Lab 측정 시 주의

| 사실 | 내용 |
|---|---|
| LCP/INP/CLS 상태 | 원문 기준 **전부 Stable** (실험 지표 아님) |
| Lighthouse 에서는 | **INP 를 못 잰다** → 대신 **TBT (Total Blocking Time)** 를 본다 |
| 이유 | INP 는 실제 사람의 클릭이 있어야 재는 값(field metric) |

### 2-5. 우리 현재 상태

| 지표 | 목표 | 현재 |
|---|---|---|
| LCP p75 (mobile) | ≤ 2.5s | **p75 미측정** · Lab 최악 **976ms ✓** |
| LCP p75 (desktop) | ≤ 2.5s | **p75 미측정** · Lab 최악 **1,112ms ✓** |
| INP p75 | ≤ 200ms | **미측정** (사용자 입력 필수 — Lab 자동 측정 불가) |

> 1. **`file://` 측정은 무효다.** i18n 이 `fetch` 로 번역을 불러오는데 `file://` 에서는 그 fetch 가 조용히 실패해 번역 키가 그대로 렌더된다. 글자 폭이 달라지므로 CLS 값이 오염된다. ⇒ 게이트가 **스스로 HTTP 서버를 띄운다**(노드 내장 모듈, 외부 의존성 0 — 네트워킹 실패·버전 드리프트로 재현성을 잃지 않기 위해).

> **⚠️ 전량 미측정이다.** 추측값을 적지 않는다(측정 원칙). GenTeam 첨부 `lighthouse-3x-summary.json`(21,224 B) 회수가 이 칸을 채우는 다음 작업이다.

- ✅ 사용 가능: "터치 타깃은 WCAG 2.2 AA 최소 요건(24×24)을 넘어 **AAA 권고치(44×44)** 를 목표로 설계했습니다"

## §5 ㉰ 미학층 — 신규 (대표님 지시로 추가)

### 5-1. 이 층이 왜 필요한가

㉮ CWV 와 ㉯ WCAG/KWCAG 는 **"감점이 없다"만 증명한다.** "훌륭하다"는 증명하지 않는다.
LCP 2.4초에 WCAG AA 전부 통과하면서도 촌스러운 페이지는 만들 수 있다.

대표님 지시:
> "고객들 입장에서 기능적, 시각적으로 편리하고, **미학적으로도 훌륭해야 해요(2D, 3D, 영상 등 사용하더라도)**"

⇒ 2D/3D/영상 자산 사용을 **사전 승인**받았다. 이 층의 기준을 세운다.

### 5-2. 벤치마크 세트 — 왜 이 3개인가 (외부 원문이 지목한 우리보다 높은 점수)

우리가 임의로 고른 게 아니다. **외부 심층리서치가 ①축 첫인상 직관성에서 우리보다 높게 매긴 제품들**이다. 즉 이 벤치마크는 미학 기준이면서 동시에 ①축 개선 근거다.

| 제품 | URL | 외부 ①축 점수 | 우리(73) 대비 | 우리가 배울 시각 장치 |
|---|---|---:|---:|---|
| **16Personalities** | https://www.16personalities.com | **92** | **+19** | **캐릭터 일러스트** + 4글자 라벨. 결과를 "그림 한 장"으로 기억시킴 |
| **Everything DiSC** | https://www.discprofile.com | **90** | +17 | **4색상 원형 다이어그램**. 색이 곧 분류표 |
| **MBTI (공식)** | https://www.myersbriggs.org | **88** | +15 | 4글자 코드의 압축력. 입으로 말할 수 있는 결과 |

> **⚠️ v1.1 자기 반박 — 이 벤치마크는 불충분하다.** 위 3개는 **전부 진단형(diagnostic) 제품**이다. 우리의 핵심 차별점은 진단이 아니라 **자산화(accumulation)** 이므로, ④축(자산화·축적 연결성 · 현재 88)의 벤치마크는 진단형 제품에서 나오지 않는다. ⇒ 자산화 플랫폼 벤치마크 6~8종 조사를 GenTeam 발주 A(`agent_p1m04ehzgv43`)에 발주해 진행 중이며, 회신이 오면 이 절을 보완한다. **도착 전에는 벤치마크 부족을 명시한다** — 있는 것처럼 쓰지 않는다.

## §5-5 ㉱ 에이전트 상호운용층 — 신규 (v1.1 신설, 2026-08-31)

### 5-5-1. 이 층이 왜 필요한가 — 중학생 눈높이

지금까지 우리 홈페이지의 손님은 **사람**뿐이었다. 그래서 ㉮(빠른가) ㉯(누구나 쓸 수 있는가) ㉰(보기 좋은가) 세 층만 봤다.

그런데 손님이 하나 더 늘었다. **AI 에이전트**다. 사람이 직접 검색하는 대신, AI가 대신 웹을 돌아다니며 "이 서비스가 무엇을 할 수 있는지"를 읽고 판단하는 일이 늘고 있다. AI가 우리 서비스를 **읽을 수 없으면, 우리는 그 손님에게는 존재하지 않는 것과 같다.**

그래서 이 층은 이렇게 묻는다: **"기계가 우리를 읽고 이해할 수 있는가?"**

### 5-5-2. 정본 출처 (추측 아님 — 실제 규격 문서)

### 5-5-4. ★ A1 이 미배포인 실측 원인 (4중 차단)

우리 `agent-card.json` 은 저장소에 있고(5,051 자, 필수 8필드 충족, 커밋 `be91e4b`) **배포물에는 들어가지 않는다.** 이유를 추측하지 않고 코드에서 확인했다.

| # | 위치 | 코드 | 효과 |
|---|---|---|---|
| 1 | `scripts/hosting-allowlist.mjs` L3 | `PUBLIC_ROOT_FILES` 에 `agent-card.json` 없음 | 허용 목록 밖 |
| 2 | `scripts/build-hosting.mjs` **L27** | `if (normalized.split("/").some((part) => part.startsWith(".")))` | 점으로 시작하는 폴더 차단 |
| 3 | `scripts/build-hosting.mjs` **L62** | `const hasDotPart = relative.split("/").some((part) => part.startsWith("."))` | 동일 차단(2중) |
| 4 | `firebase.json` | `ignore: ["**/.*"]` · `rewrites` 섹션 없음(grep 0건) | 호스팅 단계에서 재차 차단 |

즉 `.well-known/` 이라는 **점으로 시작하는 경로** 자체가 4중으로 막혀 있다. 이 4개 파일은 **성역(보호 파일)** 이다.

### 5-5-5. 대표 판단 및 이 층의 우선순위 (2026-08-31)

> 대표 지시 원문: **"현재 바로 할 필요는 없어요… 다만 앞으로 전체 설계와 개선을 하는 방향에 있어서 이것이 가능하도록 구축하는 건 필요해요. 우선순위는 아직 낮습니다."**

⇒ 이 판단을 다음과 같이 이행한다.

1. **성역 파일 4건은 지금 수정하지 않는다.** (거부가 아니라 **연기**다 — 이 구분을 문서에 남긴다)
2. **다만 향후 모든 설계는 이 경로를 막지 않아야 한다.** 즉 새 빌드 규칙·새 호스팅 설정을 추가할 때, dot-path 를 추가로 봉쇄하는 방향으로 가서는 안 된다.
3. **A2 는 지금도 지킨다.** `capabilities` 를 전부 `false` 로, `skills[].implemented` 를 전부 `false` 로 둔 것은 "아직 안 되는 것을 된다고 적지 않는다"는 원칙의 적용이다. 배포 전이라도 이 정직성은 유지한다.
4. 아키텍처 설계는 GenTeam 발주 E(`agent_f6d6hkjm9p5k`, 테크 리드)로 진행 중이다.

### 5-5-6. 자기 반박

- **이 층에는 외부 정박점이 있다** (A2A 1.0.0 규격). ㉰ 미학층과 달리 우리가 만든 기준이 아니다. 그것이 이 층의 강점이다.
- **그러나 "에이전트가 우리를 읽으면 매출이 오른다"는 인과는 우리가 측정한 바 없다.** 이 층의 사업적 가치는 **미검증**이다. 표준을 따르는 것이 손해는 아니라는 판단으로 준비하는 것이며, 효과를 주장하지 않는다.
- **A1 이 0점인 상태로 이 층을 신설한 것은 점수를 얻기 위한 것이 아니다.** 오히려 우리 약점을 하나 더 문서에 등재한 것이다.

## §8-1 ★ 신설 검증 규약 — "게이트 초록불"과 "배포물 반영"은 별건이다

2026-08-28 실제로 발생한 거짓 초록불에서 도출한 규약이다.

**사건:** 12페이지 개선 후 게이트가 12/12 를 냈고 `npm run build:hosting` 도 EXIT 0 이었다. 그런데 `dist/hosting/assets/css/a11y-core.css` 가 **존재하지 않았다.**
**원인:** 빌드는 **git 추적 파일만** 복사한다("265 tracked files"). 새 CSS 가 untracked 여서 빠졌다.
**결과 예상:** 라이브 배포 시 CSS 404 → 게이트는 통과인데 고객 화면은 개선 전 그대로.
**해소:** `git add` 후 재빌드 → **265 → 266 files**, 실제 포함 확인.

### 앞으로 의무 절차 (새 정적 자산을 추가할 때마다)

| # | 절차 | 명령 |
|---|---|---|
| 1 | 게이트 통과 확인 | `npm run test:ux` |
| 2 | git 추적 등록 | `git add <신규파일>` |
| 3 | 재빌드 | `npm run build:hosting` |
| 4 | **배포물에 실물 존재 확인** | `ls dist/hosting/<경로>` |
| 5 | **배포물 내 참조 확인** | `grep -c '<파일명>' dist/hosting/*.html` |

⇒ 4·5 를 빼면 결함 **BT**(거짓 초록불)가 재발한다.

## §9 자기 반박 (이 문서의 약점)

1. **미학층 6항목은 공인 기준이 아니다.** 우리가 방금 만들었다. 벤치마크 3종만 외부 근거이고 채점 눈금은 자체다. 대외에 "미학 50점"을 인용하면 안 된다.
2. **비전 이미지는 구현물이 아니다.** AI 생성 목업이며 확정 시안도 아니다.
3. **CWV 전량 미측정 상태로 목표표를 썼다.** 현재값 칸이 비어 있어 이 층은 아직 "설계"일 뿐 "측정"이 아니다.
4. **⑥축 점수 58.82 는 자체 채점이다.** §8.3 에 따라 제3자 채점이 아니며, 개선 후에도 자체 상향을 주장하지 않는다.
5. **KWCAG 인증을 받은 것이 아니다.** 기준을 참조했을 뿐이다. "웹 접근성 품질인증" 문구를 대외에 쓰면 허위다.
