# 인생포트폴리오 리포트 개선 방안 · 우선순위 실행계획

> **근거 문서**: `docs/벤치마킹_리포트_5축_점검_2026-07-25.md`
> **작성일**: 2026-07-25
> **원칙**: 정직(honesty) — 할 수 있는 것과 없는 것을 분명히 구분. 헌법 §7(원분야 라벨 고객노출 금지),
> 기능/엔진 무손상, 32bit fingerprint 불변을 모든 개선의 전제로 둔다.

## 0. 개선의 큰 방향 (대표 결정 반영)

우리 점수의 두 약점 **⑤ 신뢰감(58)** 과 **① 직관성(62)** 을 먼저 끌어올린다.
단, ⑤의 정공법인 **임상 타당도 연구는 지금 당장 어렵다**(표본·비용·기간).
그래서 대표 지시대로 **"인터넷 속도 측정·SSL 보안 측정처럼, 신뢰 있는 글로벌 도구로 우리 상품을
측정"** 하는 우회로를 검토했다. 아래는 그 검토 결과의 **정직한 판정**이다.

---

## 1. "글로벌 신뢰 도구 활용" 아이디어 — 정직한 판정

대표님 비유의 핵심 = **① 자동으로 측정 + ② 제3자 권위로 배지/등급 부여**(SSL Labs, Ookla Speedtest).
이를 우리 서비스에 적용하려면 "무엇을 측정하느냐"를 나눠서 봐야 한다.

### ❌ 안 되는 길 — "심리검사 타당도의 자동 측정 도구"
- **EFPA Test Review Model / ITC Guidelines**(유럽심리학회·국제검사위원회)가 사실상의 글로벌 표준이다.
- 그러나 이건 속도측정 같은 자동 도구가 **아니라**, 전문가가 **임상 데이터**(신뢰도 계수 Cronbach's α ≥ 0.70,
  타당도 근거, 규준 표본)를 심사하는 모델이다.
- 즉 **대표님이 피하고 싶어 하신 임상실험을 오히려 전제**로 한다. → **지금은 채택 불가.**
- (참고: DISC·MBTI조차 EFPA 심사에서 방법론 비판을 받는다. 이 인증은 문턱이 매우 높다.)

### ✅ 되는 길 A — "리포트 텍스트 품질"의 글로벌 표준 자동 측정
- 속도측정에 가장 근접한, **우리가 지금 붙일 수 있는** 객관 지표.
- 영어권 표준인 **Flesch-Kincaid 가독성**은 음절 기반이라 한국어에 그대로 안 맞는다(정직).
- 대신 **한국어 형태소 분석(KoNLPy/Okt) 기반**으로 다음을 자동 점수화할 수 있다:
  - 평균 문장 길이 · 어휘 다양성(TTR) · 반복 표현률 · 어려운 한자어 비율
- 이 지표는 **① 직관성**과 **⑤ 신뢰감(표현 일관성)** 개선의 **객관적 before/after 근거**가 된다.
- ⚠️ 단, 이건 사내 품질관리(QA) 도구이지 고객에게 보여줄 "제3자 배지"는 아니다. 혼동 금지.

### ✅ 되는 길 B — "방법론 투명성"으로 신뢰를 사는 정공법(비임상)
- 신뢰감의 본질은 "임상 논문"이 아니라 **"이 결과가 어떻게 나왔는지 보이는 것"**이다.
- 우리는 이미 규칙 기반 엔진 + 32bit fingerprint(재현성)를 갖고 있다 — 이걸 **강점으로 노출**하면 된다.
  - 어떤 응답이 어떤 결과로 이어졌는지(측정 근거 요약)
  - 동일 응답 → 동일 결과(결정론적 재현성)라는 사실
  - 표본·산출 로직의 투명한 설명
- Hogan(82점)이 신뢰를 얻는 방식의 **비임상 버전**이며, 헌법의 §정직 원칙과도 일치한다.

### 🔭 되는 길 C — 미래 옵션(지금 아님)
- 사용자 데이터가 축적되면(N↑), **내부 재검사 신뢰도(test-retest)** 를 우리 데이터로 자체 산출 가능.
- 그때 EFPA 스타일의 "우리만의 신뢰도 리포트"를 근거로 제시 → C길이 A/B의 상위 호환이 된다.

**결론**: 대표님 아이디어는 **길 A(품질 자동측정, 사내 QA) + 길 B(방법론 투명성, 고객 노출)** 로
구현하는 것이 정직하고 실현 가능하다. "제3자 타당도 배지"는 데이터가 쌓인 뒤 길 C로 간다.

## 2. 우선순위 실행계획 (P1 → P5)

각 항목은 **겨냥 축 · 기대효과 · 작업범위 · 무손상 체크 · 예상 난이도**로 정리한다.

### 🥇 P1 — 방법론 투명성 패널 (⑤ 신뢰감 58 → 목표 70+)
- **무엇**: 리포트 하단(또는 접이식 섹션)에 "이 결과는 이렇게 도출됐습니다" 패널 추가.
  - ① 측정 방식: N문항 응답 → 규칙 기반 엔진이 4축 지수로 환산
  - ② 재현성: 동일 응답은 항상 동일 결과(결정론적) — "당신의 고유 지문 KYS-xxxx"
  - ③ 한계 고지: 지수는 상대적 농도이며 사람의 가치를 서열화하지 않음(이미 있는 문구 강화)
- **왜 1순위**: 최대 약점(58)이며, **엔진 무손상 · 순수 표시(read-only) 추가**라 리스크가 가장 낮다.
- **작업범위**: `report.html` 표시 레이어 + `report-engine` 메타 노출(재계산 없음). 소장판/화면판 양쪽.
- **무손상**: fingerprint·엔진 로직 불변, §7 라벨 없음. CSS/DOM 추가만.
- **난이도**: ★★☆☆☆

### 🥈 P2 — 첫인상 1문장 단순화 (① 직관성 62 → 목표 72+)
- **무엇**: 리포트 최상단 요약을 **"1문장 = 1메시지"** 로 압축. 긴 복문 → 단문 분리.
- **왜 2순위**: 첫 화면 이탈을 막는 직접 효과. 텍스트 템플릿 표현 조정이라 fingerprint 무영향
  (고정 템플릿 문자열은 fingerprint 입력이 아님 — 헌법 확인됨).
- **작업범위**: 요약 섹션 카피 리라이팅 + 문장 길이 가이드.
- **무손상**: 지수·매핑 로직 불변.
- **난이도**: ★★☆☆☆

### 🥉 P3 — 진단 유형 네이밍 (①② 직관성·공감)
- **무엇**: 4축 조합에 **기억되는 유형명** 부여(예: "설계하는 실행가"류 — §7 중립·비종교 라벨).
  16Personalities가 유형명 하나로 각인시키는 효과를 벤치마킹.
- **왜 3순위**: 공유·재인지·공감을 동시에 올리지만, 네이밍 체계 설계가 필요해 P1/P2보다 무겁다.
- **작업범위**: 4축 tier 조합 → 유형명 매핑 테이블(신규). 엔진 출력에 라벨 1개 추가.
- **무손상 주의**: ⚠️ 유형명이 fingerprint 산출에 **들어가지 않도록** 순수 표시 라벨로만 추가.
  §7 원분야(종교/교육 등) 라벨 절대 금지.
- **난이도**: ★★★☆☆

### P4 — 표현 다양화(반복 제거) (①⑤)
- **무엇**: 모듈·문장의 반복 어휘를 동의어/변형으로 다양화. **길 A(KoNLPy 반복률 측정)** 로 before/after 검증.
- **작업범위**: program-engine / report-engine 템플릿 표현 다변화 + 사내 QA 스크립트.
- **무손상**: 표현 변형만, 로직·fingerprint 불변.
- **난이도**: ★★★☆☆

### P5 — 디지털 자산 대시보드 (④ 자산화 85 → 더 강화)
- **무엇**: 이미 최강점인 자산화를 **시각적으로** 축적(반복 진단 히스토리·성장 그래프).
- **왜 마지막**: 강점 강화라 급하지 않고, 데이터 축적·마이페이지 연동이 필요해 범위가 가장 크다.
- **난이도**: ★★★★☆

---

## 3. 사내 QA 도구 (길 A) — 착수 전 준비물

- 목적: P2/P4의 **객관 before/after 근거** 확보(고객 비노출, 사내용).
- 지표: 평균 문장 길이 / 어휘 다양성(TTR) / 반복표현률 / 한자어 난이도.
- 구현: KoNLPy(Okt) 기반 파이썬 스크립트(사내 실행). 리포트/프로그램 출력 텍스트를 입력.
- ⚠️ **주의**: 이 도구는 Cloudflare/Firebase 배포물이 아니라 **로컬 QA 유틸**이다(런타임 의존성 없음).

## 4. 권고 실행 순서

```
P1(방법론 투명성) ─┐  ← 최대 약점·최저 리스크. 먼저.
P2(첫인상 단순화) ─┤  ← 병렬 가능(표시 레이어).
                   ├─→ 배포·검증 → 대표 확인
P3(유형 네이밍)    │  ← 설계 승인 후.
P4(표현 다양화)    │  ← 길 A QA 도구와 함께.
P5(자산 대시보드) ─┘  ← 데이터 축적 후.
```

**대표 결정 요청 사항**
1. P1 착수 승인 (방법론 투명성 패널) — 권장 1순위.
2. "제3자 타당도 배지"는 데이터 축적 후 길 C로 보류하는 것에 동의하시는지.
3. P3 유형 네이밍의 네이밍 톤(§7 중립 라벨) 방향 확인.
