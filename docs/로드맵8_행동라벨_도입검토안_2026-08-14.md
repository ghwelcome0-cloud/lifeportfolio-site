# 행동 라벨 도입 검토안 (로드맵 8 · 고유성 원칙 충돌 심사)

- 문서 지위: 검토안 (도입 여부는 대표님 판단)
- 작성일: 2026-08-14
- 목적 축: ① 첫인상 직관성 (바이럴) · **단 고유성 원칙과 정면 충돌 가능**
- 상태: **판단 대기** — 이 문서는 결정하지 않고, 결정에 필요한 것을 정리한다

---

## 1. 문제의 구조

벤치마크 중 ①축 최고인 16Personalities(92점)의 힘은 대부분 **이름**에서 온다.
"INFP · The Mediator" 는 외우기 쉽고, 남에게 말하기 쉽고, 검색하기 쉽다.
우리 ①축이 73점인 이유의 상당 부분이 **부를 이름이 없다**는 데 있다.

그런데 대표님 원칙은 명확하다.

> "80억 인구가 검사해도 DNA가 다 다른 것처럼 … 그 나머지의 고유성을 발견해줄 수 있어야 합니다."

16개 상자에 넣는 것은 이 원칙의 정반대다. 그래서 이 항목은
**"이름을 붙일 것인가"가 아니라 "고유성을 깨지 않고 부를 수 있는가"** 의 문제다.

---

## 2. 세 가지 선택지

### 선택지 1 — 아무 이름도 붙이지 않는다 (현행 유지)

- 고유성 원칙: 완전 준수
- ①축: 73점에서 더 오르기 어렵다
- 바이럴: 고객이 남에게 옮길 말이 없다
- 판정: 원칙은 지키지만 성장 경로가 막힌다

### 선택지 2 — 유형 이름을 붙인다 (16Personalities 방식)

- 고유성 원칙: **위반**
- ①축: 크게 오른다
- 판정: **채택 불가.** 대표님 원칙과 서비스 정체성을 뒤집는다. 검토에서 제외한다.

### 선택지 3 — 행동 라벨 (검토 대상)

유형 이름이 아니라, **그 사람이 지금 하고 있는 행동**에 붙이는 짧은 말.

```
유형 이름  : "당신은 조력자입니다"        → 사람을 상자에 넣는다 (금지)
행동 라벨  : "가치를 잘 돌게 하는 일"      → 행동을 가리킨다 (검토 가능)
```

차이가 핵심이다.
- 유형 이름은 **명사이고 사람에 붙는다** → "나는 ○○형이다"
- 행동 라벨은 **동작이고 일에 붙는다** → "나는 지금 ○○하는 일을 한다"

앞의 것은 바뀌지 않는 신분이 되고, 뒤의 것은 바뀔 수 있는 활동이 된다.

## 3. 선택지 3 이 고유성을 깨지 않는 조건

아래를 **전부** 지킬 때만 도입 가능하다. 하나라도 못 지키면 유형화로 굴러떨어진다.

| 조건 | 내용 | 이유 |
|---|---|---|
| C1 | 라벨은 **조합으로 생성**한다. 미리 만든 목록에서 고르지 않는다 | 목록이 있으면 그게 유형표다 |
| C2 | 조합 가짓수가 충분히 크다 (수천 이상) | 수십 개면 사실상 유형이다 |
| C3 | 라벨을 **사람 뒤에 붙이지 않는다** ("당신은 ○○입니다" 금지) | 명사화되면 신분이 된다 |
| C4 | 라벨 옆에 **항상 고유코드를 같이 둔다** | 같은 라벨이어도 다른 사람임을 보인다 |
| C5 | 라벨이 같은 사람끼리 **묶어 보여주지 않는다** (통계·랭킹 금지) | 묶는 순간 집단이 된다 |
| C6 | 결과 판정에 **관여하지 않는다** — 표시 전용 | 판정 불변 원칙 |

★ C4 가 결정적이다. 라벨은 "부르기 위한 말"이고 고유코드가 "그 사람"이다.
둘을 함께 두면 **"같은 이름의 다른 사람"** 이 자연스럽게 성립한다.
사람 이름도 김민수가 많지만 같은 사람은 아니다 — 그 구조를 그대로 쓴다.

## 4. 우리는 이미 재료를 갖고 있다

새로 만들 필요가 없다. 엔진에 이미 있다.

```
DOMAIN_ATTR_KO  =  core (가치·작품·아름다움 …) + act (잘 돌게 해·비춰 주 …) + fruit (살림으로 …)
융합 문장       =  core + act + fruit  로 조립되고 있다
```

여기서 **core + act 두 조각만** 뽑으면 그것이 곧 행동 라벨이다.

```
예시 (조립 결과 · 실제 문장에서 이미 쓰이는 말)
  "가치를 잘 돌게 하는 일"
  "숨은 빛을 비춰 주는 일"
  "잘한 일을 밝혀 주는 일"
```

- 이미 지면에 나가는 표현이므로 **새 문안 심사가 필요 없다**
- 우선순위 2 에서 추상 표현을 걷어냈으므로 **지금이 라벨을 뽑기 가장 좋은 시점**이다
- 조합 가짓수: core 22 × act 22 = **484** … C2 기준(수천)에 **미달** ⚠

### 4.1 C2 미달을 어떻게 메우는가

484 개는 "유형 484종" 으로 읽힐 수 있다. 두 가지 보완이 있다.

- 보완 a: `fruit` 를 포함해 3조각으로 만든다 → 22×22×22 = 10,648 (C2 충족)
  단 라벨이 길어져 ①축(부르기 쉬움)이 약해진다 — 상충
- 보완 b: 라벨을 **2개 함께 표시**한다 (1순위 분야 + 2순위 분야 각각) → 484² 수준
  부르는 말은 짧게 유지되면서 조합 수가 커진다

**권고: 보완 b.** 짧음과 다양성을 동시에 지킨다.
이미 리포트가 상위 2분야를 다루므로 자료 구조도 바꿀 필요가 없다.

## 5. 도입 시 위험

| 위험 | 정도 | 대응 |
|---|---|---|
| 고객이 라벨만 보고 리포트를 안 읽는다 | 중 | 라벨을 표지에 두지 않고 I장 안에 둔다 |
| 라벨이 유형처럼 유통된다 (우리 통제 밖) | 중 | 라벨 옆 고유코드 병기(C4)로 완화. 완전 차단은 불가 |
| "MBTI 아류" 로 보인다 | 중 | 명사형 금지(C3)가 방어선. 동작으로 말하면 다르게 읽힌다 |
| 판정에 영향 | 없음 | C6 표시 전용 · 게이트로 검사 가능 |

## 6. 검증 방법 (도입할 경우)

기존 방식대로 게이트로 잡는다.

```
G35 후보 — 행동 라벨 규칙 검사
  · 라벨 뒤에 "입니다/이다/형" 이 붙는 문장이 0건인가        (C3)
  · 라벨과 고유코드가 같은 지면에 함께 있는가                (C4)
  · 라벨이 판정 수치에 관여하지 않는가 (라벨 제거 후 결과 동일) (C6)
  · 12시드 이상에서 라벨 중복률이 임계 이하인가              (C2)
```

★ 특히 마지막 항목: 시드를 늘려 라벨이 몇 종류로 수렴하는지 실측해야 한다.
484 를 계산으로 말하는 것과, 실제 고객 분포에서 몇 종이 나오는지는 다르다.
분포가 소수에 몰리면 그건 사실상 유형이다.

## 7. 판단이 필요한 지점 (대표님)

정리하면 결정할 것은 하나다.

> **"부를 이름을 주되, 그 이름이 사람이 아니라 행동에 붙는 것을 허용하는가."**

- 허용하면 → 조건 C1~C6 + 보완 b 로 설계하고, G35 게이트를 먼저 만든 뒤 도입
- 허용하지 않으면 → 선택지 1(현행 유지). ①축은 다른 수단으로 올린다
  (우선순위 3 완료 기준 변주 등 문장 개선 계속)

**권고**: 조건부 허용. 근거는
1. 재료가 이미 지면에 있고 새 주장을 만들지 않는다
2. C3(명사화 금지)·C4(고유코드 병기)가 유형화를 구조적으로 막는다
3. ①축 73점의 가장 큰 결손이 "부를 말 없음" 이고, 이것 외에 대체 수단이 약하다

단, **로드맵 4·5 보다 뒤에 둔다.** 4·5 는 기업 판매의 전제조건이고,
8 은 없어도 판매가 막히지 않는다. 순서를 바꾸지 않는다.
